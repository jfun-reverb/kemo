# 개발자 두 명 공동 작업 (영구, 2026-10-20 사용자 결정)

> 대표·wooyoung 두 사람이 각자 Claude 로 이 저장소를 고친다. 🔴 **Claude 는 상대 사람에게 메시지를 못 보낸다** — 아래 「알린다」는 전부 **사용자에게 「상대에게 이렇게 알리세요」라고 한 줄로 말하는 것**이다.

1. **같은 함수·제약·트리거를 다시 정의하기 전에 알린다** — 번호가 달라 충돌이 안 나도 나중 적용이 앞 변경을 조용히 지운다(554·555 가 같은 검사 제약을 같은 날 따로 정의). 착수 전 `git pull origin dev` 뒤 `CLAUDE.md` 「현재 원본 번호」와 그 대상의 마지막 `CREATE` 정의를 본다.
2. **새 마이그레이션 번호는 만들기 직전에** `git pull origin dev` 후 정한다. 병합 전 다시 받아 겹치면 내 쪽 이름을 바꾼다.
3. **개발·운영 데이터베이스에 SQL 을 실행하면 바로 알린다** — 「어느 서버에 몇 번」. 적용 기록 표가 생기기 전까지 유일한 기록이다(요청서 `docs/specs/2026-10-20-migration-ledger-handoff.md`).
4. **상대가 작업 중인 영역의 파일을 고칠 일이 생기면 먼저 알린다.** 핫스팟(`admin.js`·`storage.js`·`shared.js`·`CLAUDE.md`)은 짧게 끊어 자주 병합한다.
5. **운영(`main`) 병합은 둘 다 할 수 있다 — 단 병합 직전 상대에게 확인받는다.** `dev` → `main` 병합에는 **상대 작업도 같이 실려 간다.** 병합 전 `git log origin/main..origin/dev` 로 실려 갈 상대 커밋을 사용자에게 보여 주고 「개발서버 검증 끝났나 · 필요한 운영 마이그레이션 넣었나」를 상대에게 묻게 한다. 둘 중 하나라도 아니면 골라 담기([`git.md`](git.md) 「Cherry-pick 배포」). [`git.md`](git.md) 「운영서버 배포 확인」의 「사용자」는 그때 병합하는 사람이다.

⚠️ 메모리는 사람마다 따로다. 상대 Claude 도 알아야 할 결정은 메모리가 아니라 `CLAUDE.md`·규칙 파일에 쓴다.
