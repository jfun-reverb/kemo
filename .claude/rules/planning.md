## 인플루언서 화면 설계 기준 — Apple 지침 (2026-09-02 추가)

인플루언서 모바일 앱 화면을 새로 만들거나 다시 그리는 사양서는 **Apple 디자인 지침(Human Interface Guidelines)을 기준**으로 쓴다 — iOS 타입 스케일·평평한 표면·최소 터치 44×44pt·iOS 관습. 2026-05-29 사용자 지시(영구)이고, **기존 화면도 순차적으로 다시 그리기로**(2026-09-02) 정해져 **그 재작업 사양서를 기획이 쓴다.** 적용 단위는 **화면 통째** — 한 화면에 옛 방식·새 방식이 섞이면 통일 전보다 나쁘다.

- 세부 기준·하드 제약(SF Symbols 는 웹/하이브리드에 라이선스상 사용 불가 등)은 [`ui.md`](ui.md) 「Apple 디자인 지침(HIG) 우선」 절. 모호하면 `Skill("apple-design")`
- ⚠️ **관리자(PC)는 대상이 아니다** — 현재 기준은 **흑백(monochrome) 재설계 + 보라 강조색**이다. 옛 `docs/specs/2026-05-29-design-system-md3.md`(구글 머티리얼 3)는 **한 번도 구현되지 않았고 전제도 뒤집혔다** — 관리자 기준으로 삼지 말 것
- 🔴 **이 절이 `ui.md` 가 아니라 여기 있는 이유** — `ui.md` 는 경로 조건부라 `dev/**` 파일을 **열어야만** 읽힌다. 기획은 설계 단계에서 그 파일을 안 열어 **규칙이 정작 필요한 자리에서 안 보인다.** 실제로 원래 Apple 규칙은 원격에 안 올라가 3개월간 묻혔는데, 되살려 놓고 같은 자리에만 두면 **또 안 읽힌다.** 경로 조건부 규칙 중 **기획 단계에 필요한 것은 이렇게 항상 읽히는 파일에 요지를 남긴다**([`docs-tracking.md`](docs-tracking.md) 가 그 함정을 적어 뒀으나 「그러면 어떻게 하나」가 없었다)

### UX 의심 체크리스트 (매 제안마다 훑기)

REVERB JP 사용자는 **비개발자**, 인플루언서는 **초등학생 눈높이**(일본어), 관리자는 실무자(한국어). 화면·플로우 설계 시 다음을 의심:

- **진입 경로**: 사용자가 어디서 이 화면에 들어오는가? 들어오는 길이 1개뿐인가? (유일 진입점이면 제거·이동 시 기능 단절 위험 — `.claude/rules/interaction.md` 「UI 버튼 제거 전 검증」)
- **이탈·되돌리기 경로**: 이 화면에서 나가려면 어떻게 하는가? 브라우저 뒤로가기·해시 popstate 가 의도대로 동작하나? 모바일은 백버튼 없는 경우 햄버거·GNB 로 충분한가?
- **인지 부하**: 한 화면에 두 가지 일을 시키지 않는가? 정보가 너무 많아 사용자가 어디를 봐야 할지 모르게 되지 않나? (예: 응모이력 + 메시지 + 알림이 같은 면에 섞이면)
- **빈 상태 / 로딩 / 에러**: 데이터 0건일 때 화면이 텅 비지 않는가(안내 문구 필요), 로딩 중 화면 깜빡임은 없는가(`visibility:hidden` cloak), DB 에러는 사용자가 이해할 만한 일본어/한국어 문구인가(`friendlyErrorJa`)
- **실수 방지**: 되돌릴 수 없는 동작(삭제·운영 배포·메일 발송·차단)에 확인 모달 있는가? 한 번 누르면 끝나는 버튼이 손가락 옆에 다른 버튼과 붙어있지 않은가?
- **모바일 키보드**: input/textarea 가 모바일 키보드에 가려지지 않는가? `font-size:16px` 이상인가? 키보드 열렸을 때 GNB/탭바가 따라 올라오지 않는가? (`.claude/rules/ui.md`)
- **번역 누락**: 새 화면·새 문구를 i18n 키로 등록했는가? 일본어 UI에 한국어 단어가, 한국어 UI에 일본어 단어가 노출되지 않는가? Material Icons 에 `translate="no"` 붙였는가?
- **권한별 시각 차이**: super_admin / campaign_admin / campaign_manager / 인플루언서가 같은 화면에 들어왔을 때 보이는 것이 의도대로 다른가? (campaign_manager 가 CUD 버튼을 보고 누르고 나서 권한 에러를 보는 패턴은 UX 사고)
- **인플루언서 친화도**: 인플 대상 안내 문구가 초등학생 눈높이인가? 1·2·3 단계로 끊었는가? 전문용어·약어 없는가? 누르는 버튼 이름이 「」로 정확히 명시됐는가? (`.claude/rules/ui.md` 「인플루언서 안내 문구」)
- **관리자 운영 편의**: 관리자 모달에서 저장 후 뒤의 목록·배지가 stale 하지 않는가? (`.claude/rules/quality.md` `refreshPane` 의무)
- **알림·메일 맥락**: 알림·메일을 받은 사용자가 클릭했을 때 어디로 이동하는가? 맥락(어떤 응모·어떤 캠페인) 잃지 않고 진입하는가? 같은 사건에 알림 N개·메일 N통이 중복 발송되지 않는가? (멱등성)
- **접근성 (WCAG AA)**: 키보드 Tab 으로 모든 인터랙티브 요소에 도달 가능한가? 색 대비 4.5:1? `role`·`aria-label`·`aria-live`? 이미지 `alt`? (`docs/PROJECT_CONTEXT.md` 2-3)

## 규칙 C — 사양서 자기 정합성 점검 (다른 눈, 의무)

> **원칙 정의처는 글로벌 `~/.claude/rules/common-planning.md` 「규칙 C」.** 여기는 REVERB 에서 실제로 터진 함정만 덧붙인다. 언제·누가·5축은 글로벌 참조.
>
> 한 줄 요약: 사양서를 **내놓기 직전**, **작성하지 않은 다른 눈**(서브에이전트)이 **문서만** 읽고 앞뒤가 맞는지 본다. **고친 뒤에도 설계 축 지적 0건까지 다시 돌린다.**
>
> 🔴 **점검 대상은 두 축이고 섞으면 끝나지 않는다** — 설계(결정·근거·서로 부정하는 문장)는 0건까지, **진행 기록**(무엇이 배포됐나·몇 개 남았나)은 **점검으로 잡지 않고 한 자리에만 적는다.** 멈춤 기준·늘어날 때의 처리는 글로벌 참조.

### 호출 방법
- 메인 기획 세션이 서브에이전트를 띄워 **사양서 파일 경로만 주고** 「코드는 보지 말고 문서 안에서 서로 부정하는 곳만 찾아라」로 지시한다.
- `reverb-planner` 를 쓰지 않는다 — 그 에이전트는 설계를 하는 쪽이라 자기 설계를 변호하게 된다. 정합성 점검은 **설계에 관여하지 않은** 검토자여야 한다.

### REVERB 특유 함정 (5축에 더해 반드시 확인)

1. **단계 간 시점 의존** — 「N단계의 기준 = 현행 X」인데 다른 단계에서 X 를 없애거나 바꾸는가. 단계를 3개로 쪼갠 사양서에서 가장 잘 생긴다.
2. **검증 절차가 이 프로젝트 빌드 구조에서 실행 가능한가** — 인플루언서 앱(`dev/js/*.js`)과 관리자 앱은 **빌드 파일 목록이 따로**다(`dev/build.sh` 의 `ADMIN_JS_FILES`). 「관리자 화면에서 인플루언서 앱 함수를 돌린다」류 절차는 성립하지 않는다. 화면 판정을 대조 기준으로 쓰려면 **어느 앱에 그 코드가 있는지** 확인하고 절차를 쓴다.
3. **행 단위 보안 정책과 대조 범위** — 인플루언서 화면은 본인 데이터만 보인다. 「화면에서 전건을 뽑아 대조」는 관리자 쪽에서만 가능하다.
4. **시간대 기준이 양쪽에 명시됐는가** — 화면은 기기 로컬 시간, 데이터베이스는 지정한 시간대다. 두 판정을 대조하는 절차라면 **실행 장비의 시간대 조건**까지 적어야 한다(한국·일본은 같은 시간대라 일치).
5. **표와 본문** — 「확정된 결정」 표·「단계 분할」 표는 본문 설계를 고칠 때 같이 안 고쳐지는 1순위 자리다.
6. **마이그레이션 번호를 미리 박지 않았는가** (규칙 A 의 하위 항목이지만 점검 시 함께 확인)

### 적용 대상 (REVERB 기준)
- 단계(PR)가 2개 이상 / 「확정된 결정」 표가 있음 / 배포 전 게이트·대조 절차가 있음 — 하나라도 해당되면 의무
- 문구 다듬기·단일 화면 수정 사양서는 생략 가능

### 이 저장소에서 실제로 어긋난 자리 (2026-08-27)

| 사양서가 본 것 | 실제 |
|---|---|
| LIPS·@cosme는 **팔로워 값이 0**이라 아무도 통과 못 한다 | **검사가 아예 안 돈다** — `recruit_type='monitor'` 면 팔로워 체크를 건너뛰고, 저장할 때 `min_followers`·`primary_channel` 이 강제로 비워진다. 대상 캠페인 5건이 전부 리뷰어형이라 **효과 0건** |
| 판정 함수를 고치면 「또는」이 넓어진다 | **홍보 메일에 채널 문지기가 따로** 있다 — 네 채널(인스타·틱톡·X·유튜브)만 알아서 Qoo10 만 있는 캠페인은 애초에 대상이 아니다. **효과가 절반만** 난다 |
| 기준 채널 칸을 숨긴다 | **숨길 자리가 네 곳**이고 그중 **변경 이력 이름표는 지우면 안 된다**(과거 기록을 그릴 때 쓴다) |

⚠️ **첫 줄의 사실은 `CLAUDE.md` 에 이미 적혀 있었다**(「최소 팔로워수 정책 … `recruit_type='monitor'` 는 팔로워 체크 건너뜀」). **정보가 없어서가 아니라 값과 경로를 연결하지 못한 것**이다.

### 🔴 실측이 보여준 순서 — **「쓰는 자리 세기」가 먼저다**

2026-08-27 에 어긋난 셋 중 **둘은 찾으려고 본 것이 아니라 세다가 걸렸다.** `primary_channel` 을 쓰는 자리를 전수로 세던 중에 **저장 시 강제 비움**(`admin.js` 2852·4421)이 곁다리로 나왔다.

그리고 **코드만으로는 「검사를 건너뛸 수 있다」까지**였고, **「그리고」 캠페인 5건이 전부 리뷰어형**이라는 것은 **운영 데이터를 세어 보고서야** 알았다. **결정을 바꾼 것이 그쪽이다.**

→ **① 그 값을 쓰는 자리를 전수로 센다 → ② 세는 도중에 걸리는 것을 적는다 → ③ 필요하면 운영 건수를 센다.**

### ⚠️ 대조하는 쪽도 틀린다 — 실측 (2026-08-27)

대조한 세션이 낸 다섯 중 **둘을 동료가 잡았다**:

| 틀린 것 | 실제 |
|---|---|
| 문지기 함수 원본을 **141** 이라 지목 | **360**(141 → 143 → 259 → 321 → **360**). 141 을 베이스로 재작성하면 **321·360 이 통째로 사라진다** |
| 기준 채널 자리를 **「네 곳」** | **9곳** — **자기 표는 일곱 줄인데 문장은 「네 곳」**이었다 |

⚠️ 첫째는 **번호만 세면 안 된다**는 사례다 — 그 이름이 나오는 파일이 여섯인데 **375 는 정의가 아니라 권한만** 손댄다. **파일 목록을 뽑은 뒤 정의(`CREATE …`)인지 가른다.**
⚠️ 둘째는 이 저장소의 반복 유형이다 — **옮기는 과정에서 수가 달라진다.** 표를 만들었으면 **표의 줄 수와 문장의 숫자를 맞춰 본다.**

**대조는 혼자 하면 절반만 맞는다.** 결과를 낸 뒤 다른 눈에 한 번 보인다.

### 이 저장소에서 특히 자주 어긋나는 축

- **모집 형식(`recruit_type`) 분기** — 리뷰어형/시딩/방문형이 갈리는 자리가 많고, 한쪽에서만 도는 검사가 흔하다
- **저장 시 강제 비움** — 화면에서 넣어도 저장 함수가 형식에 따라 비운다
- **앞선 관문** — 메일 파이프라인은 대상 추리기 → 자격 판정 → 발송이 단계로 나뉘어, 뒤쪽만 고치면 앞에서 이미 걸러진다
- **같은 값을 쓰는 자리 수** — 화면·엑셀·메일·변경 이력이 같은 칸을 본다([[request-validation]] 「이름 전파 점검」)
