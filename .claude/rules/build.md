# 빌드 규칙

## 빌드 필수 실행 (누락 금지)
- dev/ 파일 수정 후 반드시 `cd dev && bash build.sh` 실행
- 빌드 없이 커밋하면 루트 index.html과 dev/ 코드가 불일치
- 빌드는 2개 파일 생성: `../index.html` (인플루언서), `../admin/index.html` (관리자)

## 빌드 순서 (build.sh)
### 인플루언서 빌드 (→ ../index.html)
- CSS: base.css → components.css → campaign.css → auth.css → mypage.css
- JS: **`dev/build.sh` 의 `JS_FILES` 배열이 단일 소스다.** (관리자 쪽과 같은 이유로 여기에 나열하지 않는다. 이 문서는 실제 19개 중 **10개가 빠진** 옛 9개 목록으로 오래 남아 있었다.)
- 순서 규칙: `lib/*` 가 `js/*` 보다 앞, `js/app.js` 가 맨 마지막.

### 관리자 빌드 (→ ../admin/index.html)
- CSS: base.css → components.css → admin.css
- JS: **`dev/build.sh` 의 `ADMIN_JS_FILES` 배열이 단일 소스다.** 2026-08 기준 30개이고 계속 늘어나므로 여기에 베껴 적지 않는다 — 베껴 적으면 반드시 갈린다(실제로 2026-05-25 에 `admin.js` 가 여러 파일로 쪼개진 뒤 이 문서만 옛 3개 목록으로 남아 있었다).
- 순서 규칙만 기억하면 된다: `admin-core.js` 가 다른 `admin-*` 보다 **앞**, `admin.js` 가 페인 파일들보다 **뒤**, `admin/app.js` 가 **맨 마지막**.

## 새 파일 추가 시
- CSS/JS 파일 추가 시 반드시 build.sh에 파일 경로 등록
- dev/index.html에 `<link>` 또는 `<script>` 태그 추가
- 빌드 순서(의존성) 고려하여 적절한 위치에 삽입

### ⚠️ build.sh 는 **두 곳**을 함께 고쳐야 한다
`ADMIN_JS_FILES` 배열에 파일을 넣는 것만으로는 부족하다. 바로 아래에 **원본 `<script>` 태그를 지우는 정규식**이 따로 있는데, 거기에 파일 이름을 빠뜨리면 **죽은 태그가 산출물에 남아 없는 경로를 부른다.**

실제 사고 — `image-compress.js` 가 관리자 빌드 목록에 없어서, 관리자가 응모건 메시지에 이미지를 첨부하면 **반드시 실패**했다(그 함수 정의가 관리자 빌드에 아예 없었다). 2026-08-12 에야 발견됐다.

## 🔴 `dev` 의 빌드 도장은 자기 내용보다 늘 옛것이다 (2026-09-02 확인)

관리자 화면 하단의 「빌드 시각 · 커밋」 표시(`admin-build-text`)를 **두 서버에서 비교해 어느 쪽이 앞선지 판단하지 말 것.** 개발서버 표시가 운영보다 이르게 뜨는데 **내용은 개발이 앞선다.**

- **실측**(2026-09-02): `origin/main` = `11:23 · c38f178` / `origin/dev` = `10:55 · 483adbd`. 그런데 코드는 `dev` 가 3커밋 앞이다
- **기제** — `dev → release → main` 에서 산출물이 양쪽 다 바뀌어 **충돌**하고, 그것을 풀려고 **다시 빌드**한다. 그 재빌드 커밋은 병합 요청으로 **`main` 에만 가고 `dev` 로 안 돌아온다.** ⚠️ 자동 재빌드가 아니라 **충돌 대응**이다
- 🔴 **한 번 어긋나면 스스로 굴러간다** — `main` 쪽 산출물이 `dev` 에 없으니 다음 release 도 반드시 충돌하고, 또 재빌드해 또 `main` 에만 남는다. **저절로 해소되지 않는다**
- **비대칭 실측**: 산출물(`index.html`·`admin/index.html`)을 건드린 커밋이 **`main` 에만 95건 · `dev` 에만 0건**(2026-09-02). 한 방향이다. ⚠️ 언제부터인지는 세지 않았다 — 95건이면 오래됐다는 것까지만 확인했다
- ⚠️ **기능 영향은 0이다** — 산출물 내용 자체는 정상이다(2026-09-02 확인: 최신 관리자 기능인 취소 사유 표시가 `dev` 산출물에 실려 있었다). **표시만** 어긋난다
- **고치지 않기로 했다**(2026-09-02 사용자 결정) — 고치려면 release 결과를 `dev` 로 되돌려 합치는 절차가 필요하고 그건 배포 워크플로 변경이다. 성질을 여기 적어 두는 것으로 갈음한다

⚠️ **이 표시의 「용도」는 원래 적혀 있었다 — 없던 것은 「믿을 수 없다」는 쪽이다.** 용도는 화면 안에 있다(`dev/admin/index.html` 의 `admin-build-info` **툴팁** — 「배포된 빌드의 일시·커밋. 운영팀이 어느 시점 빌드인지 식별할 때 사용」. 마우스를 올리면 운영자에게 실제로 뜬다). 적혀 있지 않던 것은 **「`dev` 쪽 값은 자기 내용보다 옛것이라 앞뒤 판단에 쓸 수 없다」**는 단서뿐이다. 그래서 2026-09-02 에 **두 세션이 각자** 이 도장을 보고 「개발이 뒤처졌나?」부터 의심했다.

- **앞뒤를 알고 싶으면** 도장이 아니라 `git log origin/main..origin/dev` 를 본다
- 🔴 **이 구분이 처방을 가른다** — 「설명이 아예 없다」면 설명을 새로 쓰는 일이지만, 실제로는 **설명이 있고 그 설명이 반만 맞는** 상태다. 그래서 처방은 **툴팁에 단서 한 마디를 붙이는 것**이었고, **2026-09-02 붙였다**(사용자 결정) — 「개발서버 표시는 실제 내용보다 이전 시점일 수 있습니다. 운영 표시와 비교해 앞뒤를 판단하지 마세요.」
  - 🔴 **개발서버에서만 붙는다** — 운영에 그대로 나가면 **운영 표시에 틀린 안내**가 된다. 판정은 `STAGING` 배지가 쓰는 도메인 분기(`IS_STAGING`)를 그대로 쓴다(`dev/admin/app.js` 의 같은 블록 — 같은 판정을 두 벌 만들지 않는다)
  - ⚠️ **왜 옛것인지는 툴팁에 넣지 않았다** — 운영자에게 필요한 것은 「이 숫자로 앞뒤를 판단하지 말라」 하나다. 이유는 이 문서에 있다
- ⚠️ **이 항목 자체가 같은 함정에 걸렸다** — 처음 적을 때 `CLAUDE.md` 와 `.claude/rules/` 만 찾아 놓고 **「어디에도 없다」로 결론을 넓혔다.** 찾은 범위가 곧 세상의 범위가 아니다. **「없다」를 쓸 때는 어디까지 찾았는지를 함께 적는다**

## 주의사항
- 루트 index.html, admin/index.html 직접 수정 금지 (빌드 시 덮어씀)
- 항상 dev/ 폴더에서만 수정
- build.sh는 Python을 사용하므로 python3 필요
