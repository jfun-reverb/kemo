# 브랜드 셀프 오리엔시트 (마이그레이션 186~195·200)

- **카드 고유 번호 `data.cards[].uid`**(마이그레이션 293·294): 카드별 메모를 **순번이 아니라 고유 번호로** 붙이기 위한 값. 🔴 **번호를 만드는 곳은 저장 함수 한 곳뿐**이고 폼은 실어 나르기만 한다(만드는 곳이 둘이면 안전망 발동이 갈려 검증 불가). `_orient_apply_card_uids(들어온data, 저장된data)` 가 `save_orient_draft`·`submit_orient_sheet` 직전에 ⓪정리(문자열 아님·빈값·공백 → 없음, 중복은 처음 것만) ①있으면 유지 ②없고 **「들어온 카드 수 = 저장된 카드 수」일 때만** 같은 자리 번호 물려받기 ③그래도 비면 새 번호. 🔴 **②의 개수 조건을 빼면 안 된다** — 옛 폼이 카드를 지운 채 저장하면 번호가 밀려 **메모가 표시 없이 엉뚱한 모집 건 아래** 나타난다(가장 나쁜 실패). 조건이 있으면 메모가 눈에 보이게 고아가 돼 「삭제된 모집 건의 메모」에 모인다. ⚠️ `mark_orient_card_consumed`(196)·`link_orient_card_to_campaign`(237)·`unlink_orient_card`(238)는 `data` 전체를 덮지 않고 `jsonb_set` 으로 자기 키만 고쳐 uid 를 보존한다 — **새 함수도 같은 방식으로**. ⚠️ **발행 표시(`campaign_id`)는 여전히 순번 기반**(메모는 고유 번호와 공존). 사양서 `docs/specs/2026-08-05-orient-sheet-internal-memo.md`

- **단순화 재설계 1단계(마이그레이션 424·425 — ★운영 완료)**: 새 시트는 **링크 1개 = 형식 1개 + 제품 1개**. 발급 모달에서 형식·시딩 채널(`instagram_feed·instagram_reels·x·tiktok·youtube`, `OS_SEEDING_CHANNELS`)을 정하고 `create_orient_sheet`(현재 원본 **490** — 5인자. 447 이 424 의 4인자에 모집비 직접 지정을, 465 가 발급 때 `uid` 를, 490 이 「모집비 직접 지정은 캠페인 관리자 이상」을 더했다. 465·490 은 `CREATE OR REPLACE` 라 권한 `authenticated` 가 보존된다)가 `data.issued{form_type,channel,issued_at}` + 카드 1개를 만든다. 🔴 **`data.issued` 유무가 새/옛 구조 판별** — 옛 시트는 옛 경로. **서버 키(`issued`·`quote`·`quote_history`·`quote_error`·`notice_ack` — 다섯째는 445, 헬퍼 현재 원본 **445**)는 `save_orient_draft`·`submit_orient_sheet`(425, `_orient_apply_issued_rules`)가 저장된 값으로 되돌린다** — 옛 캐시 폼이 저장해도 안 둔갑한다. `issued` 시트는 `cards[0].form_type`·`seeding.channels` 를 발급값으로 덮고, **제출만** 카드 2개 이상 `cards_limit`·**긴 글 칸 여섯 전부 1,000자**(`guide_too_long`/`appeal_too_long`/`text_too_long`+`field`, 429 — 폼 `textContent` 와 같은 셈법. `LONG_TEXT_FIELDS` · `cardHtmlNew` 카운터 · 서버 검사 **세 곳이 한 세트**). 🔴 임시저장에는 거부를 걸지 않는다(자동저장 보호). 제출 함수 현재 원본 **461**(425 → 427 → 429 → 430 → 446 → 459 → 461 — 옛 번호를 베이스로 잡으면 견적·글자 수 검사·헬퍼·고정 안내 확인이 사라진다). 폼은 `isNewLayout()` 으로 `cardHtmlNew`·`collectCardNew` 로 가른다(옛 요소 `.old-only`). 사양서 `docs/specs/2026-09-08-orient-sheet-simplify-and-quote.md`
- **단순화 2단계 — 견적(마이그레이션 426·427, ★운영 완료)**: 새 구조는 **제출 때** `submit_orient_sheet`(현재 원본 **461**)가 `quote_settings`(426, 조회 `get_quote_settings()` / 수정 `update_quote_setting()` 캠페인 관리자 이상)를 읽어 `data.quote` 스냅샷을 만든다. 시딩은 판매가 미사용, 부가세 `floor`. 🔴 **세트 규칙** — 제출마다 `quote` 또는 `quote_error` 하나만, 이전 판은 `quote_history[]`(`quote_no`=`{orient_no}-Q`, `revision`). 실패 3종 `price_unreadable`·`slots_missing`·`calc_error`(**제출을 막지 않는다**). ⚠️ 425 의 서버 키 보존이 견적 계산보다 **먼저**(반대면 새 견적이 옛 값으로 되돌아간다). 기준 데이터 페인 여덟 번째 탭 「견적 기준값」(`renderQuoteSettingsTable`, 가짜 단가는 노란 「미입력」) — ⚠️ 환율 단위는 `krw`(1엔당 원). `rate` 면 「1000 %」에 1 초과 거부로 수정이 막힌다. 폼: 작성 확인 → **「견적 보기」**(익명 `preview_orient_quote`, **430** — 계산만) → `screenQuote` → 제출 → **완료 화면 `screenDone`**(`submitted` 재진입도)이 견적서를 펼친다. **배송비(선택, 431)** — `sale.shipping_fee`(비우면 키 없음 = 0). 페이백 = **(판매가 + 배송비) × 환율 × 인원**, `quote.shipping_fee_jpy`(시딩 NULL). 🔴 **계산식은 `_orient_compute_quote`(현재 원본 **463** — 443 베이스 — 구간 요금. 448 은 네 번째 구간 이름, **452 는 「판매가」 이름**만 바꿨다) 한 벌** — 제출과 미리보기가 같은 헬퍼(미리보기는 저장 판 + 1). 인쇄는 견적서 **우측 상단 「인쇄 · PDF」 단추**(`renderQuoteDoc`)만 — 🔴 **자동으로 인쇄 창을 열지 않는다**.
