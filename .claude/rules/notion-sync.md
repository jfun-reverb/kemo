# 실무자 운영 가이드 관리 규칙 (Notion 정본)

> 실무자용 운영 가이드의 **정본(source of truth)은 Notion** 이다.
> 👉 https://app.notion.com/p/343231424cdd808ba388d195df947534 — 「REVERB JP 실무자 운영 가이드」 허브 + **「관리자 가이드」 데이터베이스**(화면별 페이지)
>
> `docs/OPERATOR_GUIDE.md` 는 **2026-08-07 동결된 보관본**이다. 읽지도 고치지도 않는다.

## 원칙

1. **실무자 가이드를 고칠 일이 생기면 Notion 을 고친다.** 로컬 마크다운 파일을 만들거나 고치지 않는다.
2. **화면 하나 = 페이지 하나.** 「관리자 가이드」 데이터베이스 안에 사이드바 화면 단위로 페이지를 둔다. 새 화면이 생기면 페이지를 새로 만든다.
3. **쓰기 전에 실제 화면·코드를 확인한다.** 기억이나 다른 문서를 근거로 쓰지 않는다 (아래 「정확성 게이트」).

## 정확성 게이트 (의무)

실무자 가이드는 **비개발자가 그대로 믿고 운영에 반영**하는 문서라, 틀리면 바로 운영 사고가 된다. 페이지를 새로 쓰거나 고치기 전에:

- [ ] **「운영에 있는 기능인가」를 코드로 확인** — `git cat-file -e origin/main:<파일>` 로 운영 브랜치 존재 확인. 「개발서버 전용」·「운영 미배포」 같은 배포 상태 서술은 **반드시** 이 확인을 거친다.
- [ ] **화면 이름·메뉴 경로를 실제 HTML 에서 확인** — 사이드바 라벨은 `dev/admin/index.html` 의 `data-pane` + `si-label`.
- [ ] **상태·종류·개수는 코드 상수에서 확인** — 상태 탭 배열, 알림 `kind` 목록, `lookup_values` 종류 등. 「N가지」라고 쓸 때는 세어 본다.
- [ ] **잠금·보류 상태를 빠뜨리지 않는다** — 코드가 운영에 있어도 설정으로 잠겨 있거나(예: 정산 인플루언서 노출), 약관 때문에 쓰면 안 되는 기능(예: 메시지 일괄 발송)이 있다. **「있다」와 「써도 된다」는 다르다.**
- [ ] **한 페이지 안에서 앞뒤가 맞는지 본다** — 변경 이력에는 적혀 있는데 본문 표는 옛날 그대로인 경우가 반복해서 발견됐다.

## 문구 규칙

- 대상은 **비개발자 실무자**. 영어 약어 단독 사용 금지 (`.claude/rules/interaction.md` 「약어·전문용어 자제」).
- **되돌릴 수 없는 동작**(삭제·병합·취소·일괄 처리·송금 기록)은 경고 상자로 눈에 띄게.
- 화면에 실제로 보이는 **버튼·탭 이름을 「」로 정확히** 옮긴다. 없는 항목을 찾게 만들지 않는다.

## 적용 시점

- 신규 기능·동작 변경·화면 개편을 **운영 배포한 뒤**, 같은 작업의 마무리로 Notion 을 갱신한다.
- 개발 세션이 직접 갱신해도 되고(문서화는 개발 의무 — `.claude/rules/interaction.md` 「사양서 작성 권한」), Notion 접근이 안 되면 **무엇을 어떻게 고쳐야 하는지 사용자에게 넘긴다.**

## 예외

- 약관·개인정보처리방침은 이 규칙 대상이 아니다 (`docs/{TERMS,PRIVACY}_{kr,ja}.md` 가 정본, `.claude/rules/policy.md`).
- 개발자용 문서(`CLAUDE.md`·`FEATURE_SPEC.md`·`docs/specs/*`)도 대상이 아니다. 그쪽은 레포가 정본이다.

---

**Why:** 원래 규칙은 「`docs/OPERATOR_GUIDE.md` 가 원본, Notion 은 손으로 복사한 사본」이었다. 그런데 Notion 이 따로 갱신되면서 **구조까지 갈라졌고**(한 장짜리 목차형 → 24장 데이터베이스), 로컬 파일은 2026-05-18에 멈춘 채 실제 화면과 어긋난 서술이 쌓였다. 그 결과 파일 안의 `NOTION:PENDING` 표시가 **거짓 정보**가 되어, 2026-08-07 점검에서 「Notion 이 뒤처졌다」는 잘못된 판단을 실제로 유발했다. 실무자가 보는 곳이 Notion 하나뿐이므로 정본을 Notion 으로 옮기고 이중 관리를 없앤다 (2026-08-07 사용자 결정).

**정확성 게이트를 넣은 이유:** 같은 점검에서 Notion 12개 페이지에 **57곳의 사실 오류**가 있었다. 그중 운영 사고로 이어질 수 있던 것들 — 「결과물 승인 알림이 없으니 직접 안내하라」(실제로는 자동 발송돼 중복 안내 중이었음), 「영수증은 이미지만 낸다」(실제로는 금액이 곧 송금액), 「블랙리스트는 자동 차단된다」(차단 로직 없음), 「오리엔시트는 개발서버 전용」(운영 출시 완료) — 은 모두 **코드를 한 번만 확인했으면 걸렸을 것**이다.
