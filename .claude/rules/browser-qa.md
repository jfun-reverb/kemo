# 브라우저 화면 확인 규칙 — 사용자가 보면서 따라올 수 있게 (영구)

> 개발 세션이 크롬(Claude in Chrome)으로 화면을 확인할 때, **마우스를 실제로 움직이고 필요한 자리로 스크롤해서** 사용자가 옆에서 보며 따라올 수 있게 한다. 2026-08-21 사용자 지시.

---

## 왜 이 규칙이 있나

같은 「확인했습니다」라도 방법에 따라 사용자가 보는 것이 완전히 다르다.

| 방법 | 화면에서 보이는 것 |
|---|---|
| 좌표로 마우스를 옮겨 누르기 | **커서가 움직이고 눌린다** — 사람이 하는 것과 같다 |
| 요소 지목(`ref`)으로 누르기 | 결과만 바뀐다. **어디를 눌렀는지 안 보인다** |
| 자바스크립트로 값 넣기 | **아무 움직임도 없다.** 화면이 갑자기 바뀐다 |

2026-08-21 회원 탈퇴 검증에서 세 방법이 섞여 있었다. 사용자가 「내가 QA 하는 것을 보며 참고하고 싶다」고 요청했고, 그러려면 **화면에 흔적이 남는 방법**을 기본으로 삼아야 한다.

---

## 기본 방법 (이 순서로)

1. **볼 자리를 화면에 띄운다** — 확인할 것이 스크롤 아래에 있으면 먼저 올린다
   - `computer` `scroll_to` + 요소 지목(`ref`) — 가장 정확하다. `find` 로 지목을 먼저 얻는다
   - 또는 `computer` `scroll` (`scroll_direction`·`scroll_amount`)
   - ⚠️ **모달 안의 스크롤도 같은 방법으로 된다**(실측 확인)
2. **마우스를 그 자리로 옮긴다** — `computer` `hover` + 좌표. 커서가 실제로 이동한다
3. **누른다** — `computer` `left_click` + **좌표**
4. **스크린샷으로 결과를 남긴다** — 사용자가 나중에 되짚을 수 있게

글자 입력은 **칸을 눌러 초점을 준 뒤 `type`** 으로 실제 타이핑한다. 값을 자바스크립트로 밀어 넣지 않는다.

---

## 좌표는 「방금 찍은 화면」에서만 가져온다

이 저장소에서 **가장 자주 빗나가는 지점**이다. 2026-08-21 하루에만 세 번 빗나갔다 — 취소 화면에서 뒤로 가 버렸고, 알림 창이 열려 클릭을 가로챘고, 확인 창 버튼이 스크롤돼 아래를 눌렀다.

- 좌표를 **재고 나서 누르기 전에** 화면이 움직이면 그 좌표는 이미 틀렸다. 비동기 렌더·자동 스크롤·팝업이 흔한 원인이다
- **스크린샷 → 그 화면의 좌표로 클릭 → 다시 스크린샷**. 사이에 다른 동작을 끼우지 않는다
- 누른 뒤 **의도한 일이 일어났는지 확인**한다. 안 일어났으면 좌표를 다시 잰다 — 같은 좌표로 다시 누르지 않는다

---

## 자바스크립트를 써도 되는 곳 / 쓰면 안 되는 곳

| | 허용 |
|---|---|
| ✅ **읽기** | 데이터베이스 조회, 화면 상태 확인, 요소 위치 재기, 로그인 계정 확인 |
| ✅ **사람이 만들 수 없는 상황 꾸미기** | 시험용 데이터 심기 등 — 단 **무엇을 왜 꾸몄는지 말한다** |
| ❌ **화면 조작 대신** | 버튼 클릭·값 입력·체크박스 켜기 — 사용자가 아무것도 못 본다 |

---

## 하나 안 되는 것 — 운영체제 드롭다운(`<select>`)

2026-08-21 실측:
- 눌러도 **선택지 목록이 스크린샷에 안 찍힌다**(운영체제가 그리는 팝업이라 페이지 밖이다)
- 방향키·엔터를 보내도 **값이 안 바뀐다**(초점만 잡힌다)

→ 이때만 값을 코드로 지정하되 **반드시 셋을 지킨다**:
1. 사용자에게 **「드롭다운은 화면 조작이 안 돼서 값을 직접 지정합니다」라고 말한다**
2. 바꾼 **뒤 스크린샷**을 찍어 무엇이 선택됐는지 보이게 한다
3. 그 선택으로 **화면이 실제로 달라졌는지** 확인한다(목록 건수 등)

---

## 되돌릴 수 없는 것을 누르기 전에

- **개발서버에서 한다.** 운영에서 누를 일이면 먼저 확인받는다
- 삭제·취소·발송처럼 되돌릴 수 없는 동작은 **무엇이 사라지는지 먼저 조회해 보고** 사용자에게 알린 뒤 누른다
- 시험 데이터를 쓰면 **끝나고 되돌린다.** 되돌릴 수 없는 것(취소된 응모·지워진 파일)은 **미리 말한다**

---

## 하지 않는 것

- **비밀번호 입력 금지.** 다른 등급·다른 회원 계정으로 봐야 하면 **사용자에게 로그인을 부탁**한다
- **내가 만든 탭은 내가 닫는다**
- 확인이 끝나면 **화면에 심어 둔 것을 지운다**(미리보기 상자 등)

---

## 이 규칙을 안 써도 되는 때

- 배포된 산출물에 특정 코드가 실렸는지 확인(`curl` 로 충분)
- 데이터베이스 값만 확인 — 다만 **어느 서버인지 화면으로 확인**([[supabase]] 「검증 조회는 크롬으로 직접」)
- 파일·빌드 확인

---

**Why:** 개발 세션이 브라우저로 확인할 때 요소 지목 클릭과 자바스크립트 값 넣기를 섞어 쓰면, 결과는 맞아도 **사용자는 무슨 일이 일어났는지 볼 수 없다.** 사용자가 비개발자라 「됐습니다」라는 말과 화면에서 실제로 일어나는 일을 대조할 방법이 필요하고, 그게 있어야 잘못된 확인도 걸러낼 수 있다. 좌표 방식은 느리고 빗나가기도 하지만, **보이는 것이 곧 검증**이라는 게 이 규칙의 요점이다 (2026-08-21 사용자 지시).
