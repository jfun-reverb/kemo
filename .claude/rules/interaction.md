## 🚨 일본어 문구는 반드시 한국어 뜻 병기 (의무 — 사용자는 일본어를 모른다)

**원칙**: 사용자에게 보이는 **모든 일본어 문구**(인플루언서 화면 문안·메일 문구·자동응답·기존 화면 인용)에는 **한국어 뜻을 함께** 적는다. 일본어 원문만 보여주고 "고르세요"라고 하면 사용자는 판단할 수 없다.

### 형식
- `日本語の文` — "한국어 뜻"  (또는 「한국어 뜻 | 일본어」 두 칸 표)
- 후보 A·B·C를 비교할 때는 **후보마다** 한국어 뜻을 붙인다
- 담백/다정/재촉 같은 **뉘앙스 차이는 한국어로 설명**한다 — 사용자는 일본어 뉘앙스를 못 느낀다
- 추천은 **한국어 뜻 기준**으로 한다

### 적용 범위 (전부)
- 일반 대화·상태 보고·확인 질문
- `AskUserQuestion` 옵션 라벨·설명 (일본어 원문만 넣지 말 것)
- **사양서·요청서·인수인계 문서 본문** — 나중에 사용자가 혼자 읽는 문서라 더 중요
- 서브 에이전트(planner/reviewer 등)가 일본어만 반환하면 **메인 Claude가 전달 전 한국어 뜻을 붙여 재가공**

### 적용 제외
- 코드 안에 그대로 들어가는 문자열·번역 키 값을 **코드 블록으로** 보여줄 때(코드는 코드대로 보여주되, 그 코드가 화면에 뭐라고 뜨는지는 본문에 한국어로 설명)

### 상세 작성 지침
문구 후보를 새로 만들 때의 톤·눈높이·용어 사전은 스킬 `reverb-ui-copy`(`.claude/skills/reverb-ui-copy/SKILL.md`)에 있다. **화면 문구·라벨·메일 문구를 새로 쓰거나 다듬으면 그 스킬을 부른다.** 다만 병기 의무 자체는 스킬 호출 여부와 무관하게 이 규칙으로 항상 적용된다.

**Why:** 병기 의무는 원래 `reverb-ui-copy` 스킬 안에만 있었다. 스킬은 세션이 스스로 불러야 열리는데 **그 스킬을 부르라고 시키는 규칙·후크가 어디에도 없어서**, 스킬을 안 부른 세션은 규칙의 존재조차 모른 채 일본어 원문만 던지고 결정을 요구했다. 실제로 2026-08-11 사양서 2건(`2026-08-11-receipt-deadline-mail-fix.md`·`2026-08-11-period-wording-rollout-gaps.md`)이 「レシート・レビュー認証写真 … まで」 같은 문구를 뜻 없이 실었고, 반면 2026-08-06 사양서는 한국어·일본어 두 칸 표로 적어 세션마다 지켜지기도 안 지켜지기도 했다. 항상 읽히는 규칙 파일로 올려 스킬 호출 여부와 분리한다 (2026-08-11 사용자 지적: "나한테 일본어를 보여주며 결정하라고 계속 한다").

## 🚨 한국어 오탈자 자체 점검 (의무 — 반복 위반 금지)

**문서·노션·HTML 등 한국어 텍스트 대량 작업 완료 직전 반드시 아래 순서로 자체 점검:**

### 1단계: 로컬 파일 grep
```
Grep("(캐페인|캐웩인|캠패인|켐페인|행버거|재생각|부와다니|마카일 기록|돿습|됏|뗴다가|뮤티|팔로움|컴럼|바뀍니다|뜨:)", output_mode="content")
```

### 2단계: 노션 전수 점검
- 수정한 모든 노션 페이지를 `mcp__claude_ai_Notion__notion-fetch`로 다시 가져와 본문 육안 스캔
- 표(`<table>`) 내부, FAQ 자유 서술, 주의 박스(`> ⚠️`, `> 💡`)는 특히 꼼꼼히
- `mcp__claude_ai_Notion__notion-search`로 `캐페인`, `캐웩`, `현장 없음`, `뜨:` 등 의심 키워드 검색

### 확정 오탈자 리스트 (memory/feedback_korean_typos.md와 동기화)
- **캠페인** ↔ 캐페인/캐웩인 (2회 반복 지적, 노션 MCP 유니코드 혼동 주의: `\ucea0\ud398\uc778`)
- **햄버거** ↔ 행버거
- **현재** ↔ 현장 (문맥 혼동)
- **뜸** ↔ 뜨 (종결형 불완전)
- **바뀝니다** ↔ 바뀍니다
- **제거됐습니다** ↔ 제거돿습니다
- **콘텐츠** ↔ 컨텐츠
- **메시지** ↔ 메세지

### 사용자가 오탈자 지적 시
- 단순 하나만 고치지 말고 **해당 세션의 모든 작업물 전수 재점검**
- 발견된 오탈자는 `~/.claude/projects/-Users-younggeunkim-Documents-projects-reverb-jp/memory/feedback_korean_typos.md`에 누적 추가

**Why:** 사용자가 2회 이상 지적한 항목을 또 위반하면 신뢰 훼손. 노션은 MCP 유니코드 이스케이프 버그로 ghost 오탈자 위험 특히 높음. 작업 완료 시그널 내기 전 반드시 점검.

## 배포 전 필수 에이전트 호출 (스킵 금지)

**모든 `git commit` 직전에 반드시 수행 (단순 한 줄 오탈자 예외 외 스킵 금지):**

```
[필수 체크]
□ reverb-reviewer 호출 완료
□ Supabase/Auth/RLS/마이그레이션 변경 있으면 → reverb-supabase-expert 호출 완료
□ 인증/신청/관리자 플로우 변경 또는 운영 배포 직전 → reverb-qa-tester **권장**(자동 호출 아님 — 다른 세션이 Playwright 안 쓸 때 단일 세션에서 실행. 동시 실행 시 먼저 돌던 테스트가 멈춤)
□ 크롬으로 직접 화면을 확인할 때 → **마우스를 실제로 옮기고 볼 자리로 스크롤한다** (`.claude/rules/browser-qa.md`) — 사용자가 보며 따라올 수 있어야 한다
□ 기능 추가·개선·리팩토링 시작 전 (규모 무관) → reverb-planner 호출 완료
```

- "한 줄짜리 간단한 수정이니까" 핑계로 reviewer 스킵 금지
- **스스로 판단해서 스킵하면 반드시 재지적받는다** (이전 세션에서 반복 위반 사례 있음)
- 메인 Claude가 push/merge 누르기 전 위 체크리스트를 텍스트로 되뇌고 확인
- `.claude/rules/git.md`의 "에이전트 호출 의무" 섹션과 동일한 내용이지만, 반복 위반으로 인해 이 파일에도 중복 명시 (이중 안전망)

**Why:** 이전 세션·이번 세션에서 reviewer 호출 누락 사례 반복 발생. "작은 변경이니까"가 가장 흔한 스킵 핑계 — 그러나 작은 변경도 stale 참조/z-index 충돌/RLS 누락 등을 만들 수 있으므로 예외 없이 호출.
