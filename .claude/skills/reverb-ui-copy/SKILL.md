# REVERB UI 문구·용어 도우미

REVERB JP 화면에 들어갈 **문장·라벨·용어**를 정하거나 다듬을 때 쓰는 스킬.
범용 마케팅 카피가 아니라, 이 프로젝트의 언어·눈높이·용어·규제 규칙을 지키면서
"명확하고 자연스럽고 행동을 이끄는" 문구를 제안한다.

## 언제 이 스킬을 쓰나
- 버튼·라벨·메뉴 이름을 정할 때
- 안내문·빈 상태(데이터 0건) 문구·로딩·에러·토스트 문구를 쓸 때
- 인플루언서/관리자 메일 문구를 다듬을 때
- 같은 개념을 부르는 **새 용어**를 정할 때 (용어 사전과 충돌 점검)

단순 오탈자 수정·기존 문구 그대로 복사는 이 스킬 없이 진행해도 된다.

## 3초 판정 — 어느 화면인가 (가장 먼저)

| 화면 | 언어 | 눈높이 | 유지하는 용어 |
|---|---|---|---|
| **인플루언서 앱** (`dev/index.html`, 모바일) | **일본어** | 초등학생 눈높이 | 없음 — 전부 쉬운 말 |
| **관리자 앱** (`dev/admin/index.html`, PC) | **한국어** | 초등학생도 이해할 쉬운 문장 | **업무 도메인 용어는 유지** |
| **광고주 신청 폼** (`sales/*`) | **한국어** | 쉬운 문장 | 업무 용어 유지 |

⚠️ 언어를 절대 섞지 않는다. 일본어 화면에 한국어 단어, 한국어 화면에 일본어 단어가 새어 나가면 안 된다.

## 관리자 화면 눈높이 (중요 — 오해 방지)

"관리자도 초등학생 눈높이"의 뜻은 **개발·시스템 용어를 쉬운 말로 푸는 것**이지,
업무 자체를 못 알아듣는 사람 기준으로 낮추는 게 아니다.

- **풀어써야 할 것 (개발·시스템)**: 영어 약어(`i18n`·`RLS`·`RPC`·`FK`), 코드값(`draft`·`closed`·`active`), 컬럼명(`submission_end`), 함수명·해시·마이그레이션 번호, 오류코드 → 전부 쉬운 한국어
- **유지하는 것 (업무 도메인)**: 캠페인·검수·정산·응모·모집·리뷰어·시딩 — 관리자가 매일 쓰는 실무 용어는 그대로. 이걸 풀어쓰면 오히려 실무가 번거로워진다.
- 톤: 짧은 문장, 한 줄에 한 가지 사실, "어떻게 보이는지·어떻게 쓰는지" 위주

(근거: 메모리 `feedback_admin_notice_simple_language` — 관리자 공지도 이미 쉬운 한국어 규칙)

## 인플루언서 화면 눈높이

읽는 사람이 시스템·개발 이해도가 매우 낮다고 전제한다.
- 초등학생에게 설명하듯 — 전문용어·영어 약어 금지, 부득이하면 **동작으로 풀이**("인증" → 「メールのリンクを開く」)
- 처리 방향은 **번호 단계(1·2·3)**로 끊는다: 무엇을 → 어디서 → 어떻게
- **한 문장 = 한 동작**. 길게 잇지 않는다
- 누르는 버튼 이름은 「」로 정확히
- 마지막은 안전망(「直接お問い合わせ」)으로 닫는다 (handoff 항목 제외)
- 한국어·일본어 문안은 의미·단계 수가 같아야 한다

작성 템플릿: 도입 1문장 → 「つぎの順番で」 → 번호 단계 → 안전망
(근거: 메모리 `feedback_influencer_easy_step_guide`, 사양서 `docs/specs/2026-05-21-message-faq.md` §7)

## 문구 만드는 순서

1. **화면 판정** — 위 표로 언어·눈높이 확정
2. **후보 2~3안 제시** — 뉘앙스가 다르게 (예: 담백한 안 / 다정한 안 / 짧은 안)
3. **각 안 자가 점검** — 아래 체크리스트를 문구마다 훑는다
4. **용어 충돌 점검** — `references/glossary.md`와 대조. 같은 개념을 다른 단어로 쓰고 있으면 경고하고 표준 용어 제시
5. **규제 점검** — 인플루언서 대상 문구·홍보 문구면 `references/regulation-checklist.md` 적용
6. **추천 1안** — 위 점검을 통과한 것 중 하나를 권하되 이유 한 줄

## 문구 자가 점검 체크리스트 (매 후보마다)

- [ ] 언어가 화면과 맞나 (인플=일본어 / 관리자=한국어), 다른 언어 단어 섞이지 않았나
- [ ] 약어·전문용어를 풀어썼나 (인플=전부 / 관리자=개발·시스템 용어만)
- [ ] 한 문장이 한 가지만 말하나 (인플은 특히)
- [ ] 되돌릴 수 없는 동작(삭제·발송·차단·운영 배포)이면 확인을 유도하는 문구인가
- [ ] 빈 상태·에러 문구가 "무엇을 어떻게 하면 되는지"를 알려주나 (막다른 골목 금지)
- [ ] 참조 번호(§N·PR·#NNN)를 단독으로 쓰지 않고 한글/일본어 제목을 병기했나
- [ ] 과장·단정("반드시 당첨"·"확실히") 없이 정확한가

## 전환(행동 유도)은 규제 안에서만

빈 상태·CTA·에러 문구는 **다음 행동으로 이끄는 것**이 목적이다. 다만:
- 인플루언서 화면은 **과장·후킹을 억제**한다. 일본 뒷광고 규제 + 초등학생 눈높이가 세일즈 톤을 누른다.
- "지금 신청" 같은 담백한 유도는 OK. "놓치면 후회"·"단 하루" 같은 압박·희소성 조장은 지양.
- 행동 유도 ≠ 압박. 명확함이 최고의 전환이다.

## 출력 형식 (예)

```
[화면] 인플루언서 앱 · 일본어 · 빈 상태 문구
[후보]
A) 応募したキャンペーンがまだありません。
   気になるキャンペーンをさがしてみましょう。
   → 담백. 다음 행동(캠페인 찾기)으로 유도
B) ...
[용어 점검] 「キャンペーン」 표준 용어 일치 ✓
[규제 점검] 과장·희소성 없음 ✓
[추천] A — 한 문장 한 동작 + 다음 행동이 분명
```
