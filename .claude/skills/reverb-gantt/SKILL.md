# REVERB 간트차트 길잡이

원칙은 전역 `~/.claude/rules/common-planning.md` 규칙 E 「일정표」, 이 저장소 세부는 `.claude/rules/planning.md` 「간트차트」. 여기는 **어디를 보고 어떤 순서로** 하는지만 적는다.

- **쓰는 세션은 기획 세션 하나뿐**이다. 고문·개발 세션은 고치지 말고 기획 세션에 메시지로 넘긴다
- **진행의 정본은 저장소**(사양서 「구현 결과」 + `dev` 병합 이력). 시트는 보고용 화면이다. 둘이 다르면 저장소가 맞다

## 1. 시트

- 주소: https://docs.google.com/spreadsheets/d/192byJWLRfJm85M6usjVPL6OE6ewkb0ODWeBjO8w35RQ/edit?gid=1913074042 — 탭 「내부용」(「삭제 금지」 탭은 건드리지 않는다)
- 구글 드라이브 연결로는 안 열린다(「Requested entity was not found」) → **크롬으로 연다.** 크롬은 세션끼리 하나를 나눠 쓰니 쓰고 나면 탭을 닫는다(`.claude/rules/browser-qa.md`)
- 사용자도 같은 시트를 함께 고친다 — **고치기 직전에 다시 읽는다.** 열 순서·행 번호가 그사이 바뀐 적이 있다(2026-10-19 — 「종류」·「구분」 열이 자리를 바꿨고, 위쪽 행 하나가 지워져 머리 줄이 한 칸 올라갔다)

## 2. 구성 (2026-10-19 기준 — 위 이유로 매번 확인)

| 열 | 내용 |
|---|---|
| B · C · D | WBS 번호 — B = 묶음(2글자 이하, 진한 회색 행) 또는 화면(3글자 이상, 연한 파랑 — 조건부 서식 `LEN($B)>=3`) · C = 기능 · D = 부가작업 |
| E 종류 | 칩: 개발 · 기획 · 약관 · 출시 |
| F 구분 | 칩: 운영 완료 · 개발 완료 · 진행 · 예정 · 보류 (상태만) |
| G 작업 제목 · H 비고 | 비고에 「선행: 번호 화면 › 기능」, 짝 화면, 남은 확인 |
| I 담당자 | 역할 칩(여러 개): 개발 · 기획 · 관리자(= 프로젝트 관리자, 사용자) · 운영팀 · 변호사 |
| J 시작일 · K 마감일 · L 기간 | **수식** — 달력 칸에 숫자가 처음·마지막으로 있는 날 |
| M 완료율 · N 막대 | M 은 손으로 · N 은 `SPARKLINE` 수식 |
| O~EL 달력 | O = 2026-09-01. 머리 줄 = 날짜(숫자 표시)·요일. **평일 칸에만** 숫자를 넣는다. 숫자 = 막대 색(1 파랑 = 완료 · 2 청록 = 기획 · 3 초록 = 개발 예정 · 4 노랑 = 약관 · 0 진노랑 = 출시) |

**묶음**: `bw` 브랜드 페이지 · `a` 관리자 화면 · `m` 회원 앱 · `c` 공통 기반 · `L` 약관·출시 · `cs` CS 이력 관리

## 3. 번호 규칙

- 화면 = 피그마 페이지 번호(`bw05`, `a03`) · 기능 = 피그마 화면 번호(`bw05-02`) · 부가작업 = 기능 번호 + `①②`(데이터베이스·서버 함수·메일·작업표)
- 피그마 그림이 없는 기능 = `-n1`, `-n2` … · 화면이 없는 일 = `m`(회원 앱) · `c`(공통) · `L`(약관·출시) 기호 + 순번
- 서버·데이터베이스 작업은 **따로 묶음을 만들지 않고 그것을 쓰는 화면 기능의 부가작업**으로 붙인다
- 피그마 화면 이름·번호의 정본: `docs/specs/2026-07-15-brand-portal.md` §15(브랜드·관리자) · CS 는 `docs/specs/2026-10-16-cs-history-management.md`(a10)
- 메일은 행을 따로 만들지 않고 보내는 기능의 비고에 「메일 bw01-96」처럼

## 4. 「간트차트 업데이트」 절차

1. 시트 위쪽 「마지막 갱신」 표시를 읽는다(없으면 사용자에게 기준일을 묻는다)
2. 그 뒤로 병합된 것을 센다: `git log origin/dev --since=<기준일> --first-parent --format='%ad %s' --date=format:'%m-%d'` + 해당 작업표·사양서 「구현 결과」
3. 행마다 대조해 고친다 — 구분 칩(개발 완료 / 운영 완료는 **운영 브랜치·운영 데이터베이스로 확인한 것만**) · 완료율 · 날짜(달력 숫자) · 비고(남은 확인)
4. 화면 행의 구분·완료율은 아래 행에서 다시 센다(자동 계산 아님)
5. 「마지막 갱신: 날짜 · 본 범위(커밋·사양서)」를 남기고, 바꾼 행을 사용자에게 보고한다
6. 새 피그마 화면이 생겼거나 번호가 바뀌었으면 함께 맞춘다(`reverb-figma` 원칙 4)

## 5. 편집 함정 (2026-10-19 실측)

- **붙여넣기는 메뉴 「수정 → 붙여넣기」로.** 이름 상자로 범위를 고른 직후 단축키로 붙이면 셀 편집 상태로 들어가 **여러 줄이 한 칸에 몰린다**
- 클립보드는 `pbcopy` 로 채운다(탭으로 나눈 글). 페이지 안 자바스크립트로는 클립보드에 못 쓴다
- **한글을 타이핑하면 첫 글자가 빠진다**(입력기) — 한글은 붙여넣기로 넣는다. 영문·숫자는 수식 입력줄에 타이핑해도 된다
- 이름 상자는 `cmd+j`. **페이지를 연 직후 첫 번째는 자주 무시된다** — 고른 범위를 확인하고 다시
- 읽기는 페이지 안 `fetch('/spreadsheets/d/<ID>/gviz/tq?tqx=out:csv&gid=1913074042&headers=0&range=…')`. ⚠️ **완전히 빈 행은 결과에서 빠진다** — 행 번호를 셀 때는 늘 값이 있는 열(작업 제목 G)을 함께 읽어 맞춘다. `export?format=csv` 주소로 이동하면 **파일이 내려받아지니** 쓰지 않는다
- **새 행**: 행 삽입 → 틀 행(기능 행 하나, 예: 12행)을 `A:EM` 통째로 복사해 붙인다(시작일·마감일·기간 수식과 막대가 생긴다) → 내용(B~M)·달력(O~)을 붙인다. 묶음 제목 행이면 제목 행 서식만 붙이고 J~N 수식은 지운다(`#N/A`)
- 드롭다운 규칙 범위는 행 끝이 정해져 있다 — 맨 아래에 행을 덧붙이면 규칙 범위도 넓힌다. 열을 끼우면 이웃 열의 드롭다운 규칙이 **함께 묶여** 복사된다(규칙 범위를 열별로 다시 나눈다)
- 주말 색·막대 색은 조건부 서식이다. 칸에 고정 채우기를 하지 않는다
