## 5. 핵심 업무 흐름 4가지

### 5-1. 발굴 → 검증 → 마스터 등록 (Scout)
```
자동 발굴(Scout AI)  →  발굴 큐 검토  →  사람 승인  →  Master DB 등록
                     ↘ 관측용 등록 / 자동승인 후보(관측) / 제외
```
- **핵심 원칙 명시:** 「Master DB 는 사람의 승인에서만 생성됩니다」
- 발굴 큐 상태: 진행 중 45 · 검토 가능 45 · 승인 0 · 오늘 발견 17 · 이번주 162 · 총 212건
- 후보마다 **D 점수(발굴 점수)** 와 **QC 점수** 2축으로 표시되고, 다음 액션이 문장으로 제시됨 (「검토 후 승인/제외」, 「수집·검사 진행 중」)
- 수집 계획(Collection Plan) 상태 7단계: `PLANNED → APPROVED → EXECUTING → DONE` / `DEFERRED` / `REJECTED` / `EXPIRED`
- **현재 대부분의 실수집이 정책으로 막혀 있음** — 거부 266건의 사유가 거의 전부 `PLATFORM_LIVE_COLLECTION_NOT_ENABLED_THIS_PHASE`(이번 단계에서는 실시간 수집 미허용). 실제 데이터는 `cached_snapshot`(캐시 스냅샷)에서 가져오고 있음
- 소스 건강도: instagram/tiktok/x/youtube 의 `cached_snapshot` 은 정상, `youtube_api` 만 **DEGRADED**(연속 실패 4)

### 5-2. 상품 → 추천 → 예산 조합 → 브랜드 공유
5단계 마법사: **① 상품 확인 → ② 추천 조건 → ③ 후보 검토 → ④ 예산 구성 → ⑤ 브랜드 공유**
- 입력은 Amazon·Qoo10 **상품 URL 한 줄**. 상품 정보를 구조화한 뒤 적합 인플루언서 추천
- 예산·인원 구성기: 통화 / 모드(예산 기준·인원 기준) / 조합 전략(균형·예산 효율·영향력 중심) / 총예산 / 인원 하한·상한 / 인당 최대 단가 / 국가 / 플랫폼 / 복수 채널 허용 / 필수 포함·제외 인플루언서
- 별도 경로로 **캠페인 브리프 기반 추천**(`/influencers/recommend`)도 있음 — 브랜드·제품·목적·국가(KR/US/JP/TH/VN/ID/TW)·플랫폼·타깃·예산·목표 인원·팔로워 범위·LINE 필수·단가 확인 필수·경쟁 브랜드 제외
- 화면 상단에 **SUGGEST (자동 확정 없음)** 명시

### 5-3. 컨택 → 단가 → 협상 → 콘텐츠 (업무)
`/tasks` 는 6그룹 칸반: **검토함 · 컨택 필요 · 회신 대기 · 단가·협상 · 진행 중 · 완료**
- 각 그룹 설명이 실무 문장으로 붙어 있음 (「첫 컨택 · LINE ID 요청」, 「컨택 후 응답 · 단가 요청 대기」, 「단가 확보 후 협상」, 「확정 · 콘텐츠 · 게시」, 「완료 · 거절(종료)」)
- 현재 전 그룹 0건, 상단에 「HUMAN_REVIEW 266건 · 정책 승인 요청 3건 대기」만 표시

### 5-4. 데이터베이스 → 구글 시트 되쓰기 (Sheet Sync)
- 대원칙 배지: **「System DB = Source of Truth · Sheet = 보조/백업」**
- 현재 단계(3E-1)는 **읽기 전용 / 모의실행 전용** — 매핑 승인·충돌 해결·이력은 전부 "결정 기록"일 뿐 실제 시트 반영 아님
- 실제 쓰기는 별도 **Canary(소량 시범) 승인 단계**에서만 열림. 해당 버튼 2개는 자물쇠 아이콘으로 비활성
- 8단계 구성: 연결 확인 → 탭별 구조 분석 → 매핑 → 모의실행 → 작업 목록/미리보기 → 충돌 → 이력 → Canary 쓰기
- 이력은 append-only(덧붙이기 전용) 감사 타임라인 — `MAPPING_SUGGEST`, `ANALYZE tabs=19`, `INCREMENTAL_WRITE ... verified` 형태로 셀 단위 기록
- 대상 스프레드시트 ID `1V68tv…YrEk`, 서비스 계정 `unified-influencer-reader@uni-influencer-intelligence.iam.gserviceaccount.com`

## 6. 안전장치 설계 — 이 시스템의 가장 큰 특징

전 화면에 **"자동은 제안까지, 확정은 사람"** 이 일관되게 박혀 있다. 참고할 만한 패턴:

| 장치 | 내용 |
|---|---|
| 단계별 잠금 | `scout_enabled: ON` / `dry_run: OFF` / `shadow: OFF` / `live_collection: ON` / `master_apply: ON` / `policy_version: scout-rule-1.0.0` 를 화면 상단에 그대로 노출 |
| 위험도 차단 | `RISK_HIGH_BLOCKED` — 「risk_level=HIGH → 자동 실행 금지(§5)」 |
| 확신도 게이트 | `APPLY_GATE_LOW_CONFIDENCE` — 「confidence=0.795 < threshold=0.85」 이면 자동 적용 중단 |
| 승격 관문(Promotion Gate) | 정책 변경안이 6개 조건(최소 표본 수·유의미한 개선·안전 퇴행 없음·비용 한계 내·회귀 테스트 통과·되돌리기 가능)을 모두 통과해야 사람 승인 대기열에 오름 |
| 그림자 비교(Shadow) | 현재 정책 vs 제안 정책의 8개 지표(신원 해소 성공률·수집 성공률·유효 필드 커버리지·사람 검토 비율·잘못된 중복 제거 비율·잘못된 마스터 반영 비율·API 호출 효율·신선도 준수율)를 나란히 비교 |
| 되돌리기 정책 명문화 | 각 정책 후보마다 「적용 범위」와 「적용 취소 정책」을 사람이 읽는 문장으로 서술 |
| 대규모 언어 모델 역할 제한 | 「LLM 은 판단 보조·설명·인사이트만 담당하고, 점수·안전·최종 반영은 규칙 엔진(Rule Engine)이 통제」 · 현재 `OBSERVE_ONLY/SUGGEST` 단계 |
| 값 위조 금지 | 「수집되지 않은 지표는 "데이터 없음"으로 표시하며, 값을 임의로 생성하지 않습니다」 |
| 브랜드 공개 마스킹 | 브랜드 제안서에서 숨길 내부 필드 목록 관리: `line_id`, `email`, `internal_cost`, `negotiated_rate`, `final_cost`, `internal_note`, `other_brand_history` |
