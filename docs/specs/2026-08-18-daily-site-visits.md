## 현재 상태 (2026-08-18, 코드·문서 직접 확인)

### 방문 기록이 데이터베이스에 없었다

방문은 Vercel Web Analytics 로만 흘러갔다(`dev/js/app.js`·`dev/js/admin-core.js` 의 `va('event')`). 그건 Vercel 사이트에서만 보이고, **관리자 화면에서 방문자수를 볼 수 있는 경로는 0개**였다.

### 문서 오류 2건 — 이번에 함께 정정

| 문서가 적고 있던 것 | 실제 |
|---|---|
| 브랜드 현황 대시보드에 「Vercel Web Analytics 외부 링크」가 있다 (`CLAUDE.md`) | **없다.** 관리자 화면 코드에 `vercel.com` 문자열 0건(저장소 전체로는 배포 진단용 문서에 1건 있으나 화면과 무관). 화면에는 새로고침 버튼과 「설문 페이지」 링크뿐 |

## 설계

### 표 `site_daily_visits`

| 칸 | 뜻 |
|---|---|
| `visit_date` | 집계 날짜(일본 표준시). **서버가 만든다** |
| `app` | `influencer` / `admin` / `sales` — 지금은 `influencer` 만 기록 |
| `visitor_count` | 방문자수 (브라우저 단위 하루 1회) |
| `page_view_count` | 열람 횟수 (보조 — **저장만 하고 화면에는 안 쓴다**. 지나간 방문은 되살릴 수 없어 「나중에 볼걸」을 막으려고 함께 적립) |

`(visit_date, app)` 유일 제약 → 하루 1행. 조회는 관리자만, **쓰기 정책 없음**(함수만 씀).

**개인을 식별할 수 있는 값은 한 칸도 저장하지 않는다.** 「새 방문자인가」는 브라우저가 판정해 참·거짓 하나로만 넘기고, 무엇으로 식별했는지는 서버에 도달하지 않는다.

### 함수 `record_site_visit(p_app, p_is_new_visitor)`

263 과 같은 형태 — 관리자·감사용 계정 서버 제외, 앱 구분 화이트리스트 밖이면 **조용히 종료**(방문 집계가 화면을 막으면 안 된다), 유일 제약 기준 UPSERT 로 원자적 증가.

**하루 상한 없음 · 잠금 없음 · 보존기간 정리 없음** — 근거는 마이그레이션 파일 상단 주석. 특히 잠금은 **걸면 안 된다**(하루 한 행이라 경합이 잦아 방문 트래픽 전체가 직렬화된다).

### 브라우저 쪽 (`dev/lib/storage.js`)

- `_markSiteVisited(app)` → `'new'` / `'repeat'` / `null`(저장소를 못 씀)
- `_siteVisitLooksHuman()` → 자동화 브라우저 표시·미리 불러오기 제외. **가려진 탭은 제외하지 않는다**(뒤에 열어 두는 것도 사람이다)
- `recordSiteVisit(app)` → 위 둘을 거쳐 함수 호출. 실패는 삼킨다

### ⚠️ 조회수와 정반대인 지점 — 의도한 것

저장소를 못 쓰는 환경에서 **조회수는 그냥 통과시키고, 방문자수는 세지 않는다.**

조회수는 캠페인마다 행이 나뉘어 한 사람이 부풀려도 그 캠페인 하나로 끝난다. 방문자수는 **사이트 전체가 하루 한 행**이라, 그런 사용자 1명이 새로고침한 횟수가 그대로 그날 방문자수가 된다. **부풀리는 실패보다 누락하는 실패가 낫다** — 틀리게 늘어난 숫자가 광고주 자료로 나가면 되돌릴 수 없다.

두 정책이 같은 파일에 공존하므로 주석을 남겼다. 「일관성 없다」며 맞추지 말 것.

### ⚠️ 호출 위치 — 세션 복원 뒤

`init()` 의 `updateGnb()` 직후. 관리자·감사용 제외는 서버가 로그인 정보로 판정하므로, **복원 전에 부르면 운영자 접속이 방문자로 세어진다.** 화면 전환마다가 아니라 **부팅 1회**다.

### 화면 위치 — 관리자 대시보드 (2단계)

「운영 현황」 화면은 **브랜드를 고르고 들어가는 구조**라 브랜드와 무관한 전체 숫자를 놓으면 「이 브랜드 방문자인가?」로 오독된다. 관리자 대시보드는 축이 같고(사이트 전체·날짜별·사람 수) 회원가입 추이 차트의 기간 토글을 재사용할 수 있다.

## 알려진 한계 (화면에 반드시 밝힐 것)

1. **폰과 PC를 함께 쓰면 2명**으로 세고, 브라우저 저장소를 지우면 다시 1명이 된다
2. **로그아웃 상태의 관리자는 못 거른다** — 서버 제외는 로그인해야 판정된다
3. **헤드리스 봇은 못 거른다** — 검색엔진도 이제 자바스크립트를 실행한다
4. **개인 식별자를 저장하지 않는 이상 서버는 도배를 구분할 수 없다** — 「같은 사람이 1,000번」과 「1,000명이 한 번씩」이 서버에서 같아 보인다. 이건 개인정보 최소화의 대가다

→ 카드 제목 옆에 **「같은 브라우저는 하루 1회 · 관리자·감사용 계정 제외 · 참고 지표」** 한 줄이 필수. 없으면 Vercel 숫자와 비교했을 때 반드시 어긋나고, 그때 답할 말이 없으면 지표 자체가 불신된다.

### 데이터베이스 (SQL 편집기)

> ⚠️ **관리자·감사용 제외는 SQL 편집기로 검증할 수 없다.** 서비스 키라 로그인 사용자가 비어 있어 그 분기가 아예 안 돈다(마이그레이션 272 에서 이미 겪은 함정). **실제 로그인 브라우저로만** 확인 가능.

### 브라우저 (개발서버 먼저)
1. 로그아웃 상태로 접속 → 1 증가. 새로고침 5회 → **더 안 늘어남**(열람 횟수만 증가)
2. 브라우저 저장소 키(`reverb.siteVisit`) 삭제 후 새로고침 → 1 더 증가
3. 시크릿 창 → 1 더 증가
4. **관리자 계정 로그인 후** 인플루언서 사이트 접속 → **증가하지 않음**
5. 감사용 계정 접속 → **증가하지 않음**
6. 저장소를 막은 상태 → **증가하지 않음**(263 과 반대 동작 확인)

### 구현 중 발견해 고친 결함 1건
**기록 날짜가 브라우저 시계보다 앞서면 차트가 통째로 비었다.** 날짜는 서버(일본 표준시)가 찍는데 화면의 「오늘」 판정은 관리자 PC 시계라, **자정 직후 PC 시계가 몇 분만 느려도** 「첫 기록일 > 오늘」이 되어 그릴 칸이 0개가 됐다. 오른쪽 끝을 `max(오늘, 마지막 기록일)` 로 바꿔 해소. 노드로 날짜 계산 6가지를 돌리다 재현됐다(브라우저 없이 잡힌 케이스).

### 검증

- `reverb-reviewer` GO (날짜 기준·null 구분·차트 정리·빌드 순서·권한)
- ⚠️ **브라우저 눈 확인은 못 했다** — 이 세션에 브라우저 자동화 도구가 없었다. 좁은 화면에서 제목 옆 기준 문구가 접히는지, 기간 버튼 연타 시 차트가 겹치지 않는지는 사람이 볼 것
