## 2. 무슨 일이 있었나 (사실관계)

@cosme 채널을 시스템 안에서 가리키는 **내부 코드가 바뀌었다**(옛 코드 → 새 코드).
바꿀 때 세 곳 중 두 곳만 새 코드로 정리되고, **이미 제출된 인증샷의 채널 값은 옛 코드로 남았다.**

| 대상 | 코드 상태 |
|---|---|
| 기준 데이터(채널 목록) | 새 코드만 남고 옛 코드 행은 삭제됨 |
| 캠페인의 요구 채널 | 새 코드로 정리 완료 (2026-07-30 재확인 — 옛 코드 잔존 0건) |
| **이미 제출된 리뷰 인증샷** | **옛 코드로 방치** ← 이번 문제 |

시스템은 「캠페인이 요구한 채널」과 「제출된 인증샷의 채널」이 **같은 값인지 글자 그대로 비교**한다.
그 비교가 **세 곳에서 동시에 쓰이기 때문에**, 채널 값 하나가 어긋나자 세 곳이 함께 깨졌다.

1. 인플루언서 활동관리 화면 — 제출한 인증샷이 화면에 안 보인다
2. 관리자 인증 상태 — 「인증성공」으로 올라가지 못한다
3. 정산 후보 — 정산 대상에서 빠진다

**데이터는 사라지지 않았다.** 인증샷 파일과 승인 기록은 그대로 있고, 채널 값만 어긋나 있다.
그래서 **채널 값을 맞추면 위 세 곳이 함께 회복된다**(화면·판정 로직 수정 불필요).

### 왜 아무도 먼저 발견하지 못했나
관리자 검수 화면에는 「채널이 지정되지 않은 옛 인증샷」을 찾아 주는 구제 장치가 있는데,
그 장치는 **채널 값이 비어 있을 때만** 작동한다. 이번 건은 **값이 있고 그 값이 틀린** 경우라
구제 장치의 사각지대에 들어가, 정리 대상으로도 표시되지 않았다.

### 이번 대상이 아닌 것
- **같은 응모에 옛 코드와 새 코드가 둘 다 있는 26건** — 채널 값을 바꾸면 「한 응모에 같은 채널 인증샷이 두 개」가 되어 저장이 거부된다. 처리 방침이 미결이라 이번 교정에서 제외했다. → **2026-07-31 「그대로 유지」로 결정**(§4 「26건 유지 결정 근거」).
- **게시물(리뷰 인증샷이 아닌 SNS 게시물) 2건** — 채널이 「기타」로 저장돼 있으나 **둘 다 이미 반려 처리**돼 인증 성공률·정산에 영향이 없다. 다만 채널이 지정되지 않은 캠페인에서는 아직 「기타」를 고를 수 있는 구멍이 남아 있어, 재발 방지 항목으로 별도 관리한다.

### 26건 유지 결정 근거 (2026-07-31 운영 실측)

**결론: 이 26건은 아무 문제를 일으키지 않는다.** 실측으로 확인한 사실:

| 확인 항목 | 결과 |
|---|---|
| 새 코드(`cosme`) 행 승인 | **26건 전부 승인** |
| 새 코드 행 반려 | **0건** — 인증이 안 돼 손해 보는 인플루언서 없음 |
| 옛 코드 행이 더 나중 제출 | **0건** — 새 것이 항상 최신이라 판정 순서에도 영향 없음 |
| 캠페인 | 8개(@cosme 리뷰어) |

즉 **같은 응모에 같은 채널 인증샷이 두 장 승인**돼 있고, 시스템은 새 것만 보고 정상 작동한다.
화면 노출 경로도 없다 — 인플루언서 활동관리(`renderActivityReviewImageList`)와 관리자 검수 모달은
둘 다 **캠페인의 채널 목록을 기준으로** 카드를 만들기 때문에, 그 목록에 없는 옛 코드 행은 그려지지 않는다.

> ⚠️ **이전 기록 정정** — 이 문서와 CLAUDE.md·메모리에 「26건은 그 채널이 **「미제출」로 보이는 표시
> 불일치**가 남아 있다」고 적혀 있었으나 **사실이 아니다.** 그 서술은 **A그룹(옛 코드만 있던 55건)**
> 에 해당하는 것이고 그건 2026-07-30 교정으로 이미 해소됐다. B그룹 26건은 새 코드 행이 정상
> 승인돼 있어 처음부터 표시가 정상이었다. 실측 없이 A그룹 서술을 B그룹에 옮겨 적은 오류다.

**지우지 않기로 한 이유** — 지우면 `deliverable_events` 가 CASCADE 로 함께 삭제돼 **승인 이력 26건이
사라지고**(이 프로젝트는 금전·검수 이력을 중시해 정산 이력은 아예 삭제를 막아뒀다), **이미지 파일은
저장소에 고아로 남는다**(행만 지워도 파일은 안 지워진다). 얻는 것은 「나중에 만들 감지 장치의 노이즈
제거」뿐인데, 그건 위 10번처럼 **알려진 예외로 등록**하면 더 싸게 해결된다.

> 이 표가 **남은 작업의 단일 소스**다. 다른 문서(인수인계 배너·사양서 구현 결과)는 이 표를 가리키기만 하고
> 목록을 복사해 두지 않는다 — 복사본은 한쪽만 갱신되어 반드시 어긋난다.

### 교정 실행 기록 (2026-07-30, 운영)

| 검증 항목 | 결과 |
|---|---|
| 교정 대상 잔여 | **0건** |
| 대상 아닌 26건 | 26건 그대로 (손대지 않음) |
| 교정 이력 | **55건** 기록 |
| 교정한 55건의 상태 | **전부 승인** — 상태 변경 없음 |
| 인플루언서 알림 | **0건** (최근 15분 내 결과물 관련 알림 전체 기준) |
| 캠페인별 회복 건수 | §3 표와 완전 일치 |

실행 순서: 시험 1건 → 알림 0 확인 → 나머지 54건 → 검증 4종.
(같은 시험 1건을 앞서 한 번 교정했다가 명단 확보를 위해 되돌린 뒤, 다시 교정해 확정했다.)

### 교정 작업의 안전성 (확인된 사항)
- 결과물의 **상태 값은 건드리지 않는다.** 그래서 5~6월 건에 대해 인플루언서에게 **지금 알림이 나가지 않는다** — 개발·운영 양쪽에서 실측 확인 완료(알림 0건).
- 처리 대상을 조회 조건으로 미리 좁혀, 위 「대상이 아닌 26건」은 손대지 않는다.
- 시험 1건 → 확인 → 나머지 일괄 순서로 진행하고, 되돌리는 조회문도 함께 준비돼 있다.

## 5. 관리자 공지사항 초안

> 교정이 **2026-07-30 에 완료**됐으므로 아래 초안은 그대로 등록 가능하다(건수·날짜 확정됨).

### 등록 방법

**붙여넣을 본문은 별도 파일에 있다 — `docs/specs/2026-07-30-cosme-channel-notice.html`.**
그 파일에는 **본문만** 들어 있다(안내문·주석 없음). 파일 전체를 그대로 복사하면 된다.

1. 관리자 페이지 → **공지사항** → 신규 작성
2. **분류**: 「경고」 또는 「시스템 업데이트」 (분류 이름은 관리자 화면 드롭다운 표기와 같아야 한다)
3. **제목**: `@cosme 리뷰 인증샷 55건이 검수 화면에 안 보이던 문제를 고쳤습니다`
4. **본문**: 편집기의 **HTML 소스 보기 토글을 먼저 켜고** 붙여넣는다(토글을 안 켜면 태그가 글자 그대로 보인다)
5. **상단 고정** 켜기 권장 — 담당자가 놓치지 않게
6. **「게시하기」** 로 발행 — 초안 저장 상태로 두면 사이드바 배지·로그인 팝업에 노출되지 않는다

**본문 파일이 아래 초안과 다른 점 2가지** (초안 검수 이후에 보탠 것):
- 캠페인 번호 8개와 건수 목록 — 담당자가 결과물 화면에서 바로 찾을 수 있게 (수치는 §3 표와 동일)
- 정산 관련 한 문장 — 「정산은 아직 인플루언서에게 열려 있지 않아 금액이 자동으로 생기거나 알림이 가지 않는다」 (근거는 §4 조치 계획 4번)

표(table)는 쓰지 않고 목록으로 풀었다 — 공지 편집기가 표를 지원하지 않아 붙여넣으면 통째로 사라진다.

**제목:** @cosme 리뷰 인증샷 55건이 검수 화면에 안 보이던 문제를 고쳤습니다

**본문:**

@cosme 캠페인의 리뷰 인증샷 일부가 관리자 검수 화면과 인플루언서 화면에서 보이지 않던 문제가 있었습니다. 원인을 찾아 데이터를 바로잡았습니다.

**어떤 문제였나**

@cosme 채널을 시스템 안에서 가리키는 이름이 바뀌었는데, 그 전에 이미 제출된 인증샷은 옛 이름을 그대로 갖고 있었습니다. 시스템은 캠페인이 요구한 채널과 제출된 인증샷의 채널이 같은지 비교하기 때문에, 이름이 어긋난 인증샷은 「제출되지 않은 것」처럼 취급됐습니다.

그 결과 세 가지가 함께 어긋났습니다.

1. 인플루언서 활동관리 화면에 본인이 올린 인증샷이 보이지 않음
2. 관리자 결과물 화면에서 「인증성공」으로 올라가지 않음
3. 정산 대상 후보에 잡히지 않음

**영향 범위**

- 인증샷 55건 (모두 이미 승인 처리된 것)
- 캠페인 8개, 인플루언서 34명
- 제출 시기 2026년 5월 12일 ~ 6월 16일

인증샷 파일과 승인 기록은 지워진 적이 없습니다. 채널 이름만 어긋나 있었습니다.

**어떻게 고쳤나**

옛 이름으로 남아 있던 55건의 채널 이름을 현재 이름으로 맞췄습니다. 승인·반려 상태는 전혀 바꾸지 않았으므로, 이 작업 때문에 인플루언서에게 알림이 가지는 않습니다. 누가 언제 무엇을 바꿨는지는 각 결과물의 이력에 남겨 두었습니다.

**담당자가 확인해 주실 것**

1. 해당 캠페인 8개의 **인증 성공률이 올라갔는지** 결과물 화면에서 확인해 주세요.

3. 인플루언서가 「인증샷이 안 보인다」고 문의하면, **다시 올리지 않아도 된다**고 안내해 주세요. 이미 승인된 것이 화면에 다시 나타납니다. 같은 인증샷을 또 올리면 중복이라 오류 화면이 나옵니다.

**앞으로**

채널 이름을 지우거나 바꿀 때, 이미 제출된 결과물에 그 이름이 남아 있으면 변경을 막는 장치를 추가할 예정입니다.

## 6. 개별 명단 조회문 (담당자 전달용 — 표 파일로 저장해 사내 보관)

> **교정이 끝났으므로, 이 문서에 있던 A 그룹 조건(옛 코드 + 같은 응모에 새 코드 없음)으로 조회하면 이제 0행이다.**
> ⚠️ 단, 조건 없이 **옛 코드만으로** 조회하면 0행이 아니다 — 교정 대상이 아니었던 26건(§3 「이번 대상이 아닌 것」)이 옛 코드를 그대로 갖고 있다.
> 대신 **교정 이력이 붙은 행**으로 조회한다 — 이번에 고친 55건과 정확히 같은 집합이고,
> 교정 후에도 언제든 다시 뽑을 수 있다(패치 파일에 박아 둔 식별자 55개를 옮겨 적을 필요 없음).

```sql
SELECT c.campaign_no       AS 캠페인번호,
       c.title             AS 캠페인명,
       i.name              AS 인플루언서_한자,
       i.name_kana         AS 인플루언서_가나,
       i.email             AS 이메일,
       d.id                AS 결과물id,
       d.status            AS 결과물상태,
       d.created_at::date  AS 제출일,
       d.receipt_url       AS 인증샷주소,
       a.status            AS 신청상태
  FROM deliverables d
  JOIN campaigns c         ON c.id = d.campaign_id
  LEFT JOIN applications a ON a.id = d.application_id
  LEFT JOIN influencers i  ON i.id = d.user_id
 WHERE d.id IN (
   SELECT deliverable_id FROM deliverable_events
    WHERE action = 'channel_assign'
      AND reason LIKE '@cosme 채널 코드 교정%'
 )
 ORDER BY c.campaign_no, i.email;
-- 기대: 55행
```
