# 캠페인 목록 탭별 주소 분리

**작성일:** 2026-09-30 · **작성:** 기획 세션 · **받는 쪽:** 개발 세션 · 데이터베이스 변경 없음

## 목적 (사용자 결정 2026-09-30)

인플루언서 앱 캠페인 목록의 모집 형식 탭(전체·리뷰어·기프팅·방문형)마다 주소를 따로 둔다. 목적 셋:

1. **밖에 공유할 링크** — 인스타그램·LINE 등에 「리뷰어 캠페인만 보기」 같은 링크를 건다
2. **보던 탭 유지** — 새로고침하거나 캠페인 상세를 보고 뒤로 와도 탭이 「전체」로 돌아가지 않는다
3. **메타 픽셀 추적** — 탭별 방문이 메타에 따로 잡힌다

## 의심·경우의 수

1. **주소를 읽는 자리 ①~⑤ 중 하나를 빠뜨린다**(기술) — 가장 가능성 높다. 증상이 조용하다: 빈 화면 · 홈 강조 · 옛 언어 탭. → 판정을 **대응표 하나 + 함수 둘**(설계 ①)로 모은다. ①~④는 그 함수를 직접 부르고, ⑤는 ①이 넘겨 준 페이지 이름으로 따라온다(설계 ②).
2. **뒤로가기가 탭 사이를 오간다**(UX) — 결정 3의 대가. 들어온 뒤 탭을 세 번 바꾸면 뒤로가기 세 번으로는 처음 탭까지만 돌아오고 **네 번째에** 목록을 떠난다. ⚠️ 그 뒤로가기마다 **목록 전체를 초기화하면** 상태 칩·검색어가 매번 날아가 더 나빠진다 → 설계 ③(스크롤은 탭 클릭과 같게 맨 위로 간다).
3. **같은 탭을 또 누른다**(UX·메타) — 그때도 기록을 쌓으면 뒤로가기가 「아무 변화 없음」을 한 번 더 거치고, 메타에 가짜 페이지뷰가 1건 더 간다 → 이미 그 탭이면 **아무것도 안 한다.**
4. **틀린 주소**(`#campaigns-foo`, 옛 링크 오타)(기술) — 빈 화면이면 안 된다 → 「전체」로 보이고 주소를 `#campaigns` 로 **바꿔 적는다**(`replaceState` — 기록을 늘리지 않는다). ⚠️ 이 `replaceState` 가 메타에 세어지는지는 모른다(「현재 상태」 메타 픽셀 절). **세어지지 않아도 되는 자리**다 — 부팅 때 픽셀이 보내는 첫 페이지뷰 1건으로 방문은 이미 잡히고, 앱을 쓰던 중 주소창에서 해시만 고친 경우는 그 이동도 뒤로가기 처리(`popstate`)를 타므로 픽셀이 1건으로 셀 **것으로 보이나 실측은 없다**(실측은 뒤로가기 버튼뿐). 어느 쪽이든 그 뒤의 교체는 세어지지 않아도 되고, 세어진 주소가 고치기 전·후 어느 쪽이든 목적 3(탭별 구분)에는 영향이 없다(틀린 주소는 탭이 아니다).
5. **Vercel 페이지 집계가 쪼개진다**(운영) — `navigate()` 는 `pv_inf` 에 페이지 이름을 보낸다(`app.js:~130`). 이름을 떼지 않으면 `campaigns-visit` 가 따로 잡혀 목록 방문 총합이 흩어진다 → ①의 판정 함수가 떼어 낸 이름(`campaigns`)이 들어가게 한다. 탭 클릭은 `navigate()` 를 안 거치므로 원래 안 잡힌다(지금과 같음).
6. **메타에 해시가 안 보이거나 탭 전환 페이지뷰 건수가 어긋나면**(완료 기준 8의 넷) 목적 3이 안 선다 — 전제는 있으나(위) 이 주소 모양으로는 처음이다 → 완료 기준 8. **하나라도 해당하면 배포하지 말고 기획으로 되돌린다**(대안은 이벤트에 탭 값을 싣는 수동 호출인데, 결정 3과 이중 계산 문제를 다시 봐야 한다).

### 사용자 의도와 다르게 읽힐 수 있는 곳
- 「탭별 주소」에 **상태 칩은 없다**(결정 2). 「방문형 모집중」 링크는 못 만든다.
- 공유 링크로 들어온 사람도 **상태 칩은 「전체」**로 시작한다.

## 설계

### ① 판정 한 곳 — `campaign.js` 에 대응표와 함수 둘
```js
// 탭 ↔ 주소 대응 — 이 표가 유일한 정의처다
const CAMP_PAGE_TYPE_HASH = { all: 'campaigns', monitor: 'campaigns-reviewer', gifting: 'campaigns-gifting', visit: 'campaigns-visit' };
function campPageTypeFromHash(hash)  // 'campaigns-visit' → 'visit' / 그 밖의 'campaigns-…' → 'all' / campaigns 가 아니면 null
function isCampaignsHash(hash)       // 'campaigns' 또는 'campaigns-' 로 시작
```
- ⚠️ `campaign.js` 가 `app.js` 보다 **앞에** 이어붙여지므로(`dev/build.sh` `JS_FILES`) `app.js` 에서 그대로 부를 수 있다.

### ② 주소를 읽는 자리 ①~⑤가 그 함수를 쓴다
- ① `navigate()` — `isCampaignsHash(page)` 면 `pageName = 'campaigns'`. `pushState` 는 받은 주소 그대로
- ② 뒤로가기 — **①을 고쳐도 빈 화면은 풀리지만, 그대로 두면 탭 사이 뒤로가기가 매번 전체 초기화된다**(`navigate()` → `loadCampaignsPage()`). 그래서 ②에는 설계 ③의 갈림을 **따로 넣는다**
- ③ 새로고침 복원 · 첫 화면 선택(`initPage`) — 같은 판정으로 `page-campaigns` 를 고른다
- ④ 언어 전환 — `isCampaignsHash` 로 판정, **탭은 유지**하고 다시 그린다
- ⑤ 메뉴 강조 — `pageName`(이미 `campaigns`)을 쓰므로 ①만 고치면 따라온다. **확인만** 한다

### ③ 목록 진입과 탭 전환을 가른다 — **갈림은 뒤로가기 처리(②) 한 곳**
- **뒤로가기·앞으로가기(`popstate`)** 로 캠페인 주소에 왔고 **그 순간 떠 있는 화면이 `page-campaigns`** 이면 → `navigate()` 를 **부르지 않고** 탭만 바꿔 다시 그린다(상태 칩·검색어 유지). 탭 강조도 함께
- 탭만 바꿀 때 스크롤은 **맨 위로** 간다(탭 클릭인 설계 ④와 같게 — 다른 탭의 목록이라 이전 위치가 의미 없다).
- 그 밖의 모든 경우는 `navigate()` → `loadCampaignsPage()` = **전체 초기화**. 여기에 해당하는 것: 다른 화면에서 뒤로가기로 목록에 돌아옴(상세 → 목록) · 새로고침 복원 · **진입 경로 5곳**(목록을 보던 중에 거쳐도 — 이 경로들은 `popstate` 가 아니다)
- `loadCampaignsPage()` 는 **`navigate()` 가 받은 목표 주소**(`page` 인자)에서 탭을 읽어 초기값으로 쓴다(지금은 늘 `all`) — 인자로 넘긴다. ⚠️ 부르기 **전의** 브라우저 주소를 읽으면 안 된다: 방문형을 보다 햄버거 「캠페인」을 누르면 옛 주소 `#campaigns-visit` 가 읽혀 「전체」 약속이 깨진다. 상태 칩·검색어는 지금처럼 초기화
- 탭 강조 칠하기(169~175줄 · 192~196줄 두 벌)는 **한 함수로** 합친다 — 진입·클릭·뒤로가기 세 곳이 쓴다

### ④ 탭 클릭
- `setCampPageType(type)` — ①이미 그 탭이면 아무것도 안 함 ②`history.pushState({page: 해시}, '', '#' + 해시)` ③다시 그리기·맨 위로(지금과 같음)
- ⚠️ `navigate()` 를 **부르지 않는다** — 부르면 목록을 통째로 다시 받고 초기화한다

### ⑤ 틀린 주소
- `#campaigns-` 로 시작하는데 표에 없으면 「전체」로 그리고 `history.replaceState` 로 주소를 `#campaigns` 로 고친다
- 처리 자리는 **둘** — 전체 초기화 경로(`loadCampaignsPage()` — 새로고침·진입)와 탭만 바꾸는 뒤로가기 경로(설계 ③). 앱을 쓰던 중 주소창의 해시만 고쳐 들어오면 뒤로가기 처리(`popstate`)를 탄다 — 목록이 떠 있으면 탭만 바꾸는 경로, 아니면 `navigate()` 경로

## 완료 기준

1. 탭 넷을 누르면 주소가 결정 1대로 바뀐다. 같은 탭을 다시 누르면 주소·기록이 그대로다
2. 각 주소를 **새 탭에 붙여 넣어 열면** 그 탭이 선택된 채 열린다(로그인·비로그인 둘 다)
3. 방문형 탭 → 캠페인 상세 → 뒤로가기 = **방문형 탭**으로 돌아온다
4. 기프팅에서 「모집중」 칩을 켠 뒤 방문형 → 뒤로가기 = 기프팅 **+ 모집중 유지**
5. 목록에서 새로고침·끌어서 새로고침 = 탭 유지
6. 햄버거 메뉴에서 「캠페인」이 강조된다(「홈」 아님). 햄버거·홈 「모두 보기」로 들어가면 「전체」 — 🔴 **방문형 탭을 보던 중에** 햄버거 「캠페인」을 눌러도 「전체」 + 상태 칩·검색어 초기화(설계 ③ 경고)
7. 언어를 바꾸면 탭 이름이 바뀌고 **선택한 탭은 그대로**
8. 🔴 **메타 「테스트 이벤트」에서** **다른 탭으로** 바꿀 때마다 `PageView` 가 **1건씩**(0건도 2건도 아님) 오고(같은 탭 재클릭은 0건), 그 주소에 `#campaigns-visit` 등이 **보인다**. **넷 중 하나라도 어긋나면**(주소가 안 보임 / 다른 탭인데 0건 / 다른 탭인데 2건 이상 / 같은 탭 재클릭인데 1건 이상) 배포 중단 → 기획(경우의 수 6)
9. `#campaigns-foo` 로 열면 「전체」 + 주소가 `#campaigns` 로 바뀐다. 목록을 보던 중 주소창에서 해시만 `#campaigns-foo` 로 고쳐도 같다
10. Vercel 집계 이름(`pv_inf`)이 `campaigns` 하나로 나온다(개발자 도구로 `va` 호출 인자 확인)

⚠️ 8은 개발서버에 시험용 픽셀 아이디가 켜져 있어야 한다(메타 픽셀 사양서 1-검증과 같은 준비).
