# 아웃바운드 시딩·타이업 인플루언서 추천 도구

**작성일:** 2026-07-08
**상태:** 기획 초안 (대화 진행 중 — 사용자 확인 필요 항목 다수)

> 영업팀이 직접 컨택해서 모집하는 인플루언서 명단(현재 구글시트)을 시스템으로 이관하고,
> 브랜드가 원하는 카테고리·유형·등급·예산·인원 수를 입력하면 **적합도 순으로 추천**하는 관리자 도구.
> 진행할수록 **성과 데이터가 항목별로 쌓여** 추천이 정교해지는 구조.

### 기존 REVERB 구조와의 관계 (조사 결과)
- **관리자 페인 추가**: 신규 페인 1개 = 5곳 수정 — `dev/js/admin-core.js:128` `switchAdminPane`의 `loaders` 등록 / `dev/admin/index.html` 사이드바 메뉴 + 페인 본문 / `dev/build.sh:78` `ADMIN_JS_FILES` 번들 순서 / `dev/lib/shared.js:523` `PANE_REFRESHERS` 등록. 참고 페인: `admin-lookups.js`(단순 CRUD), `admin-settlements.js`(서버 권한 게이트 포함)
- **신규 테이블 패턴**: 마이그레이션 최신 225번까지 존재 → 신규는 226번부터(번호는 개발 세션이 생성 시 확정). 표준: `CREATE TABLE IF NOT EXISTS` + `COMMENT` + `ENABLE ROW LEVEL SECURITY` + 동적 권한 정책 `has_permission('<feature>.view','read')` + `updated_at` 트리거. storage.js는 `fetchXxx` + `fetchAllPaged`(1000행 초과 대비) 패턴
- **기준 데이터(lookup_values)**: 현재 `category`는 5개 대분류(beauty/food/fashion/health/other)뿐 — 시트의 세분류(색조·기초·키즈맘)와 **1:1 매핑 불가**. `channel`은 instagram/x/qoo10/tiktok/youtube/lips/cosme. **팔로워 등급(마이크로/미들/메가) 개념은 코드에 없음** — 신규 정의 필요
- **브랜드 노출 화면**: `sales/seeding.html`("나노 인플루언서 시딩 신청" 브랜드 폼)이 이미 존재 — 별도 Vercel 프로젝트 `reverb-sales`. anon이 SECURITY DEFINER RPC로 쓰기(RLS 우회), 오리엔시트는 `?token=` 링크 + `get_orient_sheet` RPC 조회 패턴. **브랜드에게 추천 리스트를 "보여주기만" 하는 건 토큰 기반 조회 RPC로 정확히 재사용 가능**
- **기존 influencers 테이블**: `influencers.id = auth.users.id` 1:1(회원가입 트리거로만 행 생성) → **auth 계정 없는 영업 명단은 이 테이블에 넣을 수 없음.** 조회도 마스킹 뷰 `influencers_admin_view` 경유(정산·개인정보·권한 결합). 섞으면 파이프라인 오염 → **별도 테이블 신설이 정합적**
- **SNS 핸들 매칭 훅**: `dev/lib/shared.js` `normalizeSnsFields`/`extractSnsHandle` 존재 → 신규 명단에도 같은 정규화로 핸들 저장 시, 향후 그 인플이 globalreverb 가입할 때 대조·연결 여지를 열어둘 수 있음

## 의심·경우의 수 (반대론자 검증)

### 깨질 수 있는 지점
1. **"적합도"의 성립 근거** — 초기엔 성과 데이터가 0이라, 실제로는 "성과 기반 추천"이 아니라 "카테고리·등급·예산 필터+정렬"이다. 성과가 힘을 쓰려면 진행 건이 어느 정도 쌓여야 함(콜드스타트)
2. **표본 50명** — 필수 조건을 빡빡하게(색조는 색조만) 걸면 후보가 3~4명으로 붕괴 → 카테고리는 **계열(대분류)로 느슨하게** 필수 처리로 결정됨
3. **데이터 품질** — 빈 가격/팔로워, 깨진 글자, 중복 소속사 → 이관 시 정제 규칙 필요. 빈 가격 인플을 예산 필터에서 어떻게 처리할지(제외 아님·하위 표시)
4. **가용성(스케줄)** — 아무리 잘 맞아도 지금 진행 불가면 추천 무의미. 그런데 시트 월별 컬럼은 "과거"지 "미래 가용성"이 아님 → 가용성 데이터는 신규 관리 필요, 1단계 제외 후보
5. **부익부 편향** — 성과 좋은 인플만 계속 상위 → 신규·미검증 인플이 기회를 못 받아 성과가 안 쌓임. 노출 보정 필요
6. **원가·협상 메모 노출(UX/보안)** — 브랜드 뷰에 실단가·협상 코멘트가 새면 사고 → 뷰 분리 필수(내부/브랜드)

### 사용자 의도 해석 확인
- "유형" = **모집 형식(릴스/피드/스토리/틱톡) + 캠페인 목적(신제품 홍보/세일/브랜딩) 둘 다** (사용자 확정)
- "리스트 수" = 추천 상위 N명 개수로 해석
- "성과" = 콘텐츠 반응(참여율)만인지, 운영 성실도(마감 준수)·브랜드 만족도까지인지 → 설계에서 3종 다 포함 제안

## 제안 / 설계

### A. 확정된 뼈대 (대화로 합의)
- 성격: **독립 도구로 시작** (기존 셀프서비스 체험단과 별개 사업 라인)
- 위치: **REVERB 관리자에 신규 페인** + 데이터는 **신규 테이블로 이관**
- 순위 요소: 카테고리 일치 + 등급·팔로워 + 가격 효율 + 성과 (4개 모두)
- 뷰 2종: **내부용**(원가·협상 전부) / **브랜드용**(가린 버전)
- 매칭: **카테고리 계열 필수 필터** + 나머지 가점, 예산 초과는 제외 않고 하위 표시
- **권한**: 최고 관리자 + 캠페인 관리자 (제한 등급 캠페인 매니저 제외 — 정산 화면 패턴). 신규 페인은 `menu.<pane>` + `<feature>.view` 권한 키로 동적 권한에 편입
- **가용성**: 1단계는 **단순 상태만**(진행가능 / 불가 / 조율중) 표시·필터. 상세 스케줄은 후속
- **브랜드 뷰**: **sales 서브도메인 화면**(브랜드 전용). 단 "어느 브랜드에 어떤 리스트"를 식별해야 하므로 접근은 링크(토큰)/식별 방식 병행 — 5단계에서 구체화

### B. 데이터 모델 (신규 테이블 — 번호는 개발 세션이 확정)

**① 인플루언서 마스터** (`outbound_influencers` 가칭)
- 기본: 한글명, 계정 ID, 카테고리(세분), 계열, 등급 티어
- 채널별: 인스타/틱톡/유튜브/X 핸들 + 팔로워수 (정규화 핸들 저장)
- 가격: 피드/릴스/스토리/틱톡/2차사용 단가 (선택 입력, 빈값 허용)
- 운영: 컨텍 창구, 소속사, 최근 협상 메모, 가용 상태(1단계는 단순 on/off 정도)
- `is_active`, `created_at`, `updated_at`

**② 진행 이력** (`outbound_engagements` 가칭) — 성과 축적의 핵심, 진행 1건 = 1행
- 어느 브랜드, 진행 시기, 채널·형식(릴스/피드/스토리/틱톡), **실제 단가**
- 결과물 링크(게시물 URL)
- **운영 성과**: 마감 준수 여부, 재작업/반려 여부, 재기용 여부
- 관리자 기록

**③ 콘텐츠 성과** (`outbound_engagement_metrics` 가칭, ②에 연결) — 항목별 기록
- 조회수 / 좋아요 / 댓글 / 저장 → **참여율 자동 계산**
- 수집 방식: **관리자 수동 입력**(진행 후 계속 기록). API 자동수집은 약관 벽으로 보류
- 측정 시점(게시 후 며칠)

**뷰별 성과 노출 정책 (사용자 확정)**
- **관리자**: 정량(참여율·조회수)·정성(별점·재기용) 모두 노출·입력
- **브랜드 뷰**: 1단계는 **정성 평가만** 노출(별점·재기용 의향·만족도). 정량 지표(참여율·조회수)는 **데이터가 충분히 축적된 뒤 노출**로 전환

**④ 브랜드 만족도** (②에 연결) — 진행 후 정성 평가
- 별점(1~5), 재기용 의향, 코멘트

**⑤ 기준 데이터** — 신규 lookup: 세분 카테고리 + 계열 매핑 + 등급 티어(팔로워 구간)

### C. 적합도 점수 계산

```
후보 = 카테고리 계열이 일치하는 인플만 (필수 필터)
적합도 점수 = Σ 가중치 × 각 축 점수
  · 등급·팔로워 근접도 : 요구 구간에 가까울수록 +
  · 요구 채널 적합      : 요구 채널에 실한 팔로워 있으면 +
  · 예산 대비           : 예산 내 +, 초과 시 표시하되 감점(제외 아님)
  · 성과 점수 (아래)     : 쌓일수록 비중 상승
브랜드가 "저비용 우선 / 큰 인플 우선" 선택 시 가중치 프로파일 전환
```

**성과 점수** (④②③ 종합, 사용자 요구 "성과로 추천" 반영):
- 진행 횟수·최근성 + 평균 참여율 + 평균 만족도 + 재기용률 가중
- 콜드스타트: 성과 없으면 **중립값**(순위에서 성과 축 비활성) → A층으로만 정렬. 진행 쌓이면 자동 반영
- 부익부 보정: 신규·저노출 인플에 소폭 가점(선택)

### C-2. 브랜드 입력 항목 (확정)
- **카테고리** (필수 — 계열 필터의 기준)
- **유형** 2종:
  - 모집 형식: 릴스 / 피드 / 스토리 / 틱톡 → 그 형식 단가가 있고 그 형식 성과가 좋은 인플 가점
  - 캠페인 목적: 신제품 홍보 / 세일 프로모션 / 브랜딩 등 → **초기엔 기록·필터 참고용**(매칭 데이터 없음), 진행 이력에 "이 목적에서 잘함"이 쌓이면 후속 반영
- **등급·팔로워 구간** (마이크로/미들/메가)
- **예산** (선택 — 초과는 하위 표시)
- **채널** (선택 — 인스타/틱톡/유튜브 등 중요 채널)
- **인원 수** (추천 상위 N명)

### D. 화면
- **내부용 페인** (`/admin#outbound-recommend` 가칭): 조건 입력(카테고리·유형·등급·예산·인원 수) → 결과 순위 카드/표(적합도·성과·실단가·협상 메모 전체 노출) + 인플 상세(진행 이력·성과 타임라인) + 진행 이력/성과 입력 모달
- **브랜드용 뷰**: 토큰 링크 조회(오리엔시트 패턴 재사용). 원가·협상 메모 제거, 공개 정보 + 적합도만
- **데이터 입력**: 시트 → 신규 테이블 초기 이관(1회) + 이후 페인에서 CRUD
