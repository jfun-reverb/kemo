# 관리자 페이지 진입 시 화면 깜빡임 — 개발 인수인계

**작성일:** 2026-09-30 · **작성:** 기획 세션 · **받는 쪽:** 개발 세션 · **종류:** 버그 수정(설계 결정 없음)

## 증상

로그인하지 않은 상태에서 관리자 페이지 주소(`/admin/`)로 들어가면, 로그인 화면(`/admin-setpw.html?mode=login`)으로 넘어가기 직전에 **관리자 화면(사이드바·대시보드 틀)이 잠깐 보인다.** 운영과 개발서버 모두 같다(운영 산출물에도 같은 가림막 코드가 있음을 확인).

## 현재 상태 (작성일 기준, `origin/dev` 52328b65)

- `dev/admin/index.html:68` — 가림막 `<style id="admin-cloak">`가 몸통을 감추고, 로딩 화면 `#admin-boot`(75줄)만 보이게 둔다.
- `dev/admin/app.js:204-259` — 페이지 뼈대가 준비되면(`DOMContentLoaded`) 첫 화면을 고르고, **251~255줄에서 가림막과 로딩 화면을 걷은 뒤** 258줄에서 `init()`을 부른다.
- `dev/admin/app.js:96-` `init()` — 이 안에서 처음으로 로그인 여부를 확인한다.
  - 99줄 `getSession()` → 로그인 정보가 없으면 106줄에서 로그인 화면으로 이동
  - 110줄 `admins` 조회 → 관리자가 아니면 113줄 「관리자 권한이 없습니다」 안내 + 1.5초 뒤 `/`로 이동
  - 123~127줄 권한 불러오기 + 메뉴 숨김(`applyLookupMenuVisibility`)
  - 199줄 `catch` — 초기화 오류 안내

## 원인

**가림막을 걷는 시점(251줄)이 로그인 확인(99줄)보다 앞선다.** 가림막이 걷힌 뒤 로그인 확인이 끝나기까지 관리자 화면이 드러난다. 로그인 정보가 있는 사람은 그대로 대시보드로 가므로 알아채지 못한다.

같은 이유로 **권한 때문에 숨겨야 할 메뉴도 잠깐 보였다가 사라질 수 있다**(123~127줄도 가림막을 걷은 뒤에 돈다).

## 고칠 방향

가림막과 로딩 화면을 걷는 두 줄(251~255)을 **`init()` 안에서 관리자 확인과 메뉴 숨김이 끝난 뒤**로 옮긴다. 걷는 코드는 공용 함수 하나로 두고(아래 세 곳에서 부르므로), 걷는 순서는 지금처럼 가림막 → 로딩 화면 짝을 유지한다.

| 경우 | 지금 | 바꾼 뒤 |
|---|---|---|
| 로그인 정보 없음 | 관리자 화면이 보였다가 이동 | **로딩 화면을 띄운 채** 이동(걷지 않는다) |
| 관리자가 아닌 계정 | 안내가 보임 | 🔴 **걷고 나서 안내를 띄운다** — 안 걷으면 안내가 가림막에 가려 **보이지 않는다**(`toast`는 몸통 안에 그려진다) |
| 정상 관리자 | 화면 → 메뉴 숨김 순서 | 메뉴 숨김까지 끝낸 뒤 걷는다 |
| 초기화 오류(199줄) | 오류 안내가 보임 | 🔴 **반드시 걷는다** — 안 걷으면 「불러오는 중…」에 **영영 멈춘다**. 지금보다 나빠지는 유일한 경우 |

### ⚠️ 지켜야 할 것

1. **첫 화면 고르기(230~249줄)는 그대로 가림막 뒤에서 한다.** 새로고침 때 이전 페인이 번쩍이는 문제를 막은 코드다(커밋 `e5563194`·`d3b53bed`).
2. **로딩 화면을 지우지 말 것.** 가림막만 남기면 브라우저가 이전 화면을 붙든 채 몇 초 멈춘다(커밋 `269038d5`, `index.html:63-67` 주석).
3. **정상 관리자는 로딩 화면을 서버 조회 1~2번만큼 더 오래 본다**(`admins` 조회 + 권한 조회). 받아들이는 비용으로 본다. 대시보드 데이터 불러오기(189~198줄)까지 기다리지는 않는다 — 그 앞, 권한·메뉴 처리 직후에 걷는다.
4. `init()` 중간에서 `return` 하는 모든 자리를 확인한다. 걷지 않고 끝나도 되는 곳은 **다른 주소로 이동하는 자리뿐**이다.

## 완료 기준

- [ ] 로그인하지 않은 채 `/admin/`, `/admin/#campaigns`로 들어가면 관리자 화면이 **한 번도** 안 보이고 로딩 화면 → 로그인 화면으로 간다
- [ ] 관리자가 아닌 계정으로 `/admin/`에 들어가면 「관리자 권한이 없습니다」가 **보인다**
- [ ] 정상 관리자는 지금처럼 대시보드·새로고침한 페인으로 들어간다(이전 페인 번쩍임 없음)
- [ ] 캠페인매니저 계정에서 숨김 메뉴가 잠깐도 안 보인다
- [ ] 아웃바운드 전용 주소(`/admin/?app=outbound`)도 같게 동작한다
- [ ] 초기화 중 오류가 나면 로딩 화면에 멈추지 않는다(개발자 도구로 네트워크를 끊어 확인)

확인은 브라우저로 눈으로 본다(`.claude/rules/browser-qa.md`). 순간적인 깜빡임이라 **느린 네트워크 흉내(개발자 도구 Throttling)** 를 켜면 잘 보인다.

### 초안 대비 변경 사항
- 없음 — 인수인계 방향 그대로. 걷는 코드를 `revealAdminShell()`(`dev/admin/app.js`) 하나로 모으고, 부르는 곳을 `init()` 의 세 자리로 한정했다: ①관리자 확인 + 권한 메뉴 숨김(`applyLookupMenuVisibility`·`applyOutboundModeUI`·`updateSidebarProfile`) 직후 ②관리자 아닌 계정 — 안내 **전** ③`catch` — 오류 안내 **전**.
- 로그인 없음은 걷지 않고 로딩 화면 그대로 로그인 화면으로 이동한다. `init()` 안 `return` 은 두 곳뿐이고 둘 다 이동하는 자리다(관리자 아닌 계정은 걷은 뒤 1.5초 뒤 이동).
- 첫 페인 고르기(`DOMContentLoaded` 안)와 로딩 화면(`#admin-boot`)은 그대로 둔다.

### 구현 중 기술 결정 사항
- 대시보드 데이터(캠페인·인플루언서·신청 전건)는 기다리지 않는다 — 걷은 뒤 기존처럼 표 안 스피너로 불러온다. 정상 관리자가 로딩 화면을 더 보는 시간은 `admins` 조회 + 권한 조회 두 번뿐.
- ⚠️ 로컬 확인에서 옛 판은 로그인 없이 들어갔을 때 가림막이 걷힌 관리자 화면이 표본에 잡혔다(재현). 새 판은 `/admin/`·`/admin/#campaigns`·`/admin/?app=outbound` 모두 표본 0건이고 최종 착지는 로그인 화면이다. 다만 표본 간격이 드물어(탭 타이머 제한) 이것만으로 「0회」를 증명하지는 못한다 — 근거의 주축은 **걷는 코드가 로그인 확인 뒤에만 있다**는 구조 확인이고, 관리자 로그인 경로는 개발서버에서 눈으로 확인한다.
