## 조각별 상세

### 작업 1 — 개발서버 출발 상태 만들기

- **하는 일:** 사양서 「리포트 대장」의 여섯 리포트를 개발서버에 만들고 「병합 전에 해 둘 것」 2항을 끝낸다. **코드는 한 줄도 안 고친다.**
- **담당 파일:** 없음 — 개발서버 관리자 화면에서 손으로 한다.
- **산출 계약:**
  - 리포트 여섯 — 「리뷰어」·「인스타단일」·「두채널」·「혼합」·「립스」·「기타」. 이름을 **사양서와 글자 그대로** 붙인다(아래 조각이 전부 이 이름으로 가리킨다).
  - 사양서 「고를 때의 전제」 네 줄을 **먼저** 만족시킨다 — 특히 🔴 「혼합」의 「큐텐·엣코스메 모집 건에만 결과물을 낸 회원 중 인스타그램 계정을 등록한 사람이 한 명 이상」. 없으면 시험 회원의 계정을 등록해 둔다. 안 하면 작업 6의 「혼합」 확인이 **구현이 틀려도 통과**한다.
  - 「리뷰어」 관리자 화면 요약의 **「리뷰 N」 값을 적어 둔다.**
  - 「리뷰어」를 공유하고 열 고르기에서 **「구매 영수증 (URL)」 한 칸만 끄고 저장**해 둔다.
- **선행 의존:** 선결 「기타 건수」(「기타」에 담을 것이 있는지).
- **완료 정의:** 여섯 리포트가 개발서버 리포트 목록에 있고, 「리뷰어」가 「공유 중」이며 그 저장 배열에 `receipt_url` 이 **없다.** 적어 둔 「리뷰 N」 값이 인수인계 메모에 있다.
- **필요 검문소:** 없음(코드 변경 0).

### 작업 2 — 데이터 싣기 (서버 함수 + 회원 조회 칸)

- **하는 일:** 공유용 서버 함수가 회원 묶음에 SNS 계정 넷을 함께 내려주게 하고, 관리자용 회원 조회에도 그 네 칸을 더한다. 사양서 「서버」 절.
- **담당 파일:** 마이그레이션 **1개**(번호는 이 조각이 파일을 만들 때 확정) · `dev/lib/storage.js`(`fetchInfluencersForReport` 의 조회 칸 목록, `:1893`)
- **산출 계약:**
  - 서버 응답 `users[회원id]` 에 **`ig`·`tiktok`·`x`·`youtube`** 네 열쇠. 조건에 안 맞으면 `NULL`, `share_columns` 에 `-ch_{코드}_acct` 가 있으면 그 채널은 전원 `NULL`.
  - 관리자용 `fetchInfluencersForReport` 반환 객체에도 같은 네 열쇠.
  - 「코드 ↔ 회원 표의 칸」 네 짝을 서버 함수 안에 적는다(작업 3의 채널 대장과 **사본 관계**).
- **선행 의존:** 작업 1(출발 상태가 굳은 뒤에 손댄다).
- **완료 정의:** 개발서버에서 「인스타단일」 공유 링크를 열어 서버 응답을 보면 `users` 안에 네 열쇠가 있고, 인스타그램 모집 건에 낸 회원의 `ig` 에 값이 있다. 관리자 쪽은 개발자 도구에서 `fetchInfluencersForReport` 결과에 네 칸이 실리는 것을 본다.
- **필요 검문소:** `reverb-supabase-expert`(의무) → `reverb-reviewer`(커밋 직전)
- **주의·롤백:**
  - 🔴 **`CREATE OR REPLACE` 로만.** `DROP` 후 `CREATE` 하면 413 이 로그인 없는 역할에 준 실행 권한이 풀려 **공유 링크가 전부 죽는다.** 적용 직후 414 파일 하단의 권한 검증 조회를 다시 돌려 눈으로 본다.
  - **베이스는 414**(413 아님). 413 을 베이스로 잡으면 영수증 사진 주소가 통째로 사라진다.
  - 🔴 **마이그레이션을 개발 데이터베이스에 적용한 뒤에 코드를 병합한다.** 반대여도 화면은 안 깨지지만(계정 열이 안 그려질 뿐) 검증이 「고쳤는데 안 보인다」로 흐려진다.
  - **되돌리기:** 414 파일을 그대로 다시 실행하면 이전 정의로 돌아간다. `storage.js` 는 조회 칸 넷을 빼면 된다.
  - ⚠️ 마이그레이션 파일은 **이 조각 한 세션만** 만든다. 만들기 직전 `ls supabase/migrations/ | tail -5` 로 마지막 번호를 확인한다.

### 작업 3 — 표 만들기 토대 (이 작업의 심장)

- **하는 일:** 채널 대장·열 계산 함수·공유 열 판정 두 함수·계정 칸·기타 결과물 칸을 만들고 `_excelSnsUrl` 을 옮긴다(유튜브 채널 아이디 갈래 포함). 사양서 「채널 대장」·「열쇠 이름」·「어떤 열이 생기나」·「칸에 무엇이 들어가나」·「공유 화면 열 고르기」.
- **담당 파일:** `dev/js/report-rows.js`(주) · `dev/js/admin-excel.js`(`_excelSnsUrl` 의 원래 정의 제거만)
- **산출 계약:** 아래 이름은 **다음 두 조각이 그대로 부른다.**
  - **사양서가 정한 이름 — 글자 그대로**
    - 채널 대장 상수 **`REPORT_CHANNELS`**(7줄 — `qoo10`·`cosme`·`lips`·`instagram`·`tiktok`·`x`·`youtube`)
    - 열쇠 — **`ch_{코드}_acct`**·**`ch_{코드}_url`**·**`ch_{코드}_kind`**·**`ch_{코드}_at`**·**`ch_etc_url`**·**`ch_etc_at`**·**`ch_etc_kind`**·**`ch_etc_more`**
    - 행에 싣는 값 **`_channels`**(표에 안 그린다)
    - 저장 형식 — 끈 새 열쇠는 **`-열쇠`**
    - 옮겨 오는 함수 이름 **`_excelSnsUrl`**(그대로, `function` 선언 형태)
    - 기존 열쇠 `ch_qoo10_url`·`ch_qoo10_at`·`ch_cosme_url`·`ch_cosme_at` 는 **바꾸지 않는다**
  - **사양서가 이름을 안 정한 것 — 이 조각이 정해 「구현 결과」에 적는다**
    - 행 배열을 받아 열 목록을 돌려주는 함수
    - 옛 열쇠 16개 얼린 목록(🔴 **여기에 앞으로 아무것도 더하지 않는다**)
    - 「꺼져 있는가」 판정 함수 — **열 고르기 창과 공유 화면이 같이** 쓴다
    - 「그릴 것인가」 판정 함수 — **공유 화면과 브랜드용 엑셀이 같이** 쓴다
- **선행 의존:** 작업 2 · 선결 「주소 모양 건수」
- **완료 정의:** 이 조각만으로는 화면이 안 바뀐다(작업 4·5 가 부르기 전까지). 콘솔에서 `REPORT_CHANNELS` 가 7줄이고, 「인스타단일」의 행을 열 계산 함수에 넣으면 `ch_instagram_acct`·`ch_instagram_url`·`ch_instagram_at` 이 목록에 들어온다. `_excelSnsUrl('youtube', 'UC…')` 가 `/channel/` 주소를 돌려준다. **인플루언서·신청자·결과물 엑셀을 각각 한 번씩** 내려받아 SNS 열에 전체 주소가 그대로 들어가는지 본다(옮기다 깨진 것이 없는지).
- **필요 검문소:** `reverb-reviewer`(커밋 직전)

### 작업 4 — 관리자 화면

- **하는 일:** 관리자 리포트 표·엑셀·요약·열 고르기 창이 작업 3 의 계산된 열을 돌게 한다. 사양서 「고칠 자리 대장」의 `admin-reports.js` 줄.
- **담당 파일:** `dev/js/admin-reports.js`
- **산출 계약:** 저장 배열의 형식 — 옛 열쇠는 켠 것을 `열쇠` 로, 새 열쇠는 **끈 것만** `-열쇠` 로. **창에 안 나온 새 열쇠의 `-열쇠` 는 그대로 보존**한다(작업 5 가 이 배열을 읽는다).
- **선행 의존:** 작업 3
- **완료 정의:** 사양서 **「관리자 화면 (+ 관리자용 엑셀)」 표의 여섯 줄** — 「리뷰어」·「인스타단일」·「두채널」·「혼합」·「립스」·「기타」. 특히 「리뷰어」에서 열이 17개 그대로이고 요약 「결과물 N」이 적어 둔 「리뷰 N」과 같다 / 「두채널」에서 머리글과 몸통의 칸이 끝까지 맞고 열이 눌리지 않는다 / 🔴 「혼합」에서 큐텐만 한 사람의 줄은 인스타그램 계정 칸이 비어 있다.
- **필요 검문소:** `reverb-reviewer`(커밋 직전)
- ⚠️ 빈 상태 `colspan="18"`(`:396`)은 **그대로 둔다.** 날짜 칸 판정(`:295`)은 **열쇠가 `_at` 로 끝나는가**로 바꾼다. 열 고르기 창의 체크 상태에는 **「꺼져 있는가」만** 쓴다(「그릴 것인가」를 쓰면 값 없는 옛 열이 꺼진 채 굳는다 — 사양서 🔴).

### 작업 5 — 공유 화면

- **하는 일:** 브랜드 공유 화면의 열 계산·칸·요약·엑셀이 작업 3 의 함수를 쓰게 한다.
- **담당 파일:** `dev/report.html`
- **산출 계약:** 없음(가장 바깥 잎).
- **선행 의존:** 작업 3
- **완료 정의:** 사양서 **「공유 화면 (+ 브랜드용 엑셀)」 표의 일곱 차례**를 감당할 모양이다(실제 통과 확인은 작업 6 에서 한 번에). ⚠️ **`_cols` 를 쓰는 다섯 자리**(`:179` 머리글 · `:180` 빈 상태 줄 · `:196` 칸 · `:223`·`:225` 브랜드용 엑셀)를 전부 눈으로 본다 — 열 계산만 바꾸고 엑셀을 안 보면 「화면에는 있는데 엑셀에는 없는 열」이 조용히 생긴다.
- **필요 검문소:** `reverb-reviewer`(커밋 직전)

### 작업 6 — 개발서버 검증

- **하는 일:** 사양서 「검증」 절을 순서대로 실행하고 결과를 「구현 결과」에 적는다.
- **담당 파일:** 없음 (브라우저)
- **산출 계약:** 사양서가 「그렇게 했다고 적는다」고 시킨 것을 반드시 기록 — 「기타」에 담을 것이 없었으면 그 사실 / 「옛 화면」(차례 넷)을 손 대입으로 확인했으면 그 사실 / 「?」·「값」만으로 열이 생기는 경우·유튜브 채널 아이디를 코드·콘솔로 확인했으면 그 사실 / 차례 일곱을 건너뛰었으면 그 사실.
- **선행 의존:** 작업 4 · 작업 5 **둘 다**
- **완료 정의:** **관리자 화면 표 여섯 줄을 먼저 끝내고**(차례 다섯이 「리뷰어」의 구성을 바꾼다), 그다음 공유 화면 차례 하나~일곱을 **차례를 바꾸지 않고** 통과. 각 줄에서 브랜드용 엑셀의 열이 화면과 같은지도 본다. 「그 밖」도 확인.
- **필요 검문소:** **브라우저 직접 확인**(`.claude/rules/browser-qa.md`). `reverb-qa-tester` 는 권장이며 자동 호출하지 않는다(크롬 하나를 여러 세션이 나눠 쓴다).
- ⚠️ 차례 둘 「주소 모양 계정」은 시험 회원의 값을 바꾼다 — **끝나면 반드시 되돌린다.**

### 작업 7 — 운영 배포

- **하는 일:** 개발서버 검증이 끝난 변경을 운영에 올린다.
- **선행 의존:** 작업 6 · 선결 「공유 중 건수」
- **완료 정의:**
  1. **선결 「공유 중 건수」 결과를 사용자에게 먼저 알린다** — 0이 아니면 「배포하는 날 이 리포트들의 브랜드 화면에 게시물 링크·계정 열이 저절로 생기고, 열 목록이 저장된 리포트에서는 빈 열이 빠진다」를 건수와 함께(사양서 깨질 가능성 카).
  2. 🔴 **운영 데이터베이스에 마이그레이션을 먼저 적용**하고 권한 검증 조회로 확인한 뒤 코드를 병합한다.
  3. 운영 병합은 **사용자 확인 필수**(`.claude/rules/git.md`).
  4. 배포 뒤 운영에서 리포트 하나를 열어 표가 멀쩡한지, 공유 링크 하나가 열리는지 눈으로 본다.
- **주의·롤백:** 마이그레이션은 414 파일을 다시 실행하면 되돌아간다. 코드는 병합 되돌리기.
- ⚠️ 🔴 **지금 `dev` 와 `main` 의 격차에는 오리엔시트 개편·메타 픽셀이 들어 있다**(메모리 `project_dev_main_drift`). 이 변경을 운영에 올리는 방식(그 배포와 함께 / 골라 담기)은 **배포 시점에 개발 세션이 실측해 사용자와 정한다.** 리포트 네 파일은 2026-09-17 기준 `main`·`dev` 가 같아 골라 담기가 가능한 상태다.

### 작업 8 — Notion 「관리자 가이드」 갱신

- **하는 일:** 리포트 관리 장을 실제 화면에 맞춘다(`.claude/rules/notion-sync.md` — 실무자 가이드의 정본은 Notion).
- **선행 의존:** 작업 7(**운영 배포 뒤에** 고친다 — 아직 없는 화면을 있다고 적지 않는다)
- **완료 정의:** 네 가지가 반영돼 있다 — 새로 생기는 채널 열과 「쓰일 때만」 규칙 / 열 고르기 창이 채널별로 묶이고 날짜 항목에 앞말이 붙은 것 / 요약의 낱말이 「리뷰」에서 「결과물」로 바뀐 것 / 브랜드 화면에서 값 없는 열이 빠진다는 것. 🔴 Notion 접근이 안 되면 무엇을 어떻게 고쳐야 하는지 사용자에게 넘긴다.

## 🧭 배분 제안

### 권고 — **1명 순차** (개발 세션 하나가 작업 1 → 8)

1. **여덟 중 여섯이 작업 3 의 결과에 매달린다.** `report-rows.js` 는 쪼갤 수 없는 단일 파일이고, 그 앞(작업 1·2)과 뒤(작업 6·7·8)는 성격상 순차다.
2. **유일하게 갈라지는 작업 4·5 를 병렬로 하면 빌드 산출물 둘이 충돌한다.** 아끼는 시간보다 합치는 비용이 크다.
3. **검증(작업 6)이 구조적으로 순차다.** 사양서가 「관리자 화면 표를 먼저 끝낸다」·「앞줄이 남긴 상태를 뒷줄이 쓴다」·「차례를 바꾸지 않는다」고 못박았다.

### 두 세션을 꼭 써야 한다면

| 개발 2 | (작업 3 병합을 기다렸다가) **작업 5** 만 |

조건 셋 — 개발 2 는 작업 3 이 **개발 브랜치에 병합된 뒤** 시작한다(산출 계약의 함수 이름이 굳기 전에 시작하면 두 번 고친다) · 나중에 병합하는 쪽이 `origin/dev` 를 합치고 **다시 빌드**한다 · **검증(작업 6)은 개발 1 이 혼자** 돌린다.
