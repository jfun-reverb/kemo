## 현재 상태 (`origin/dev` 확인)

- 번역 칸(마이그레이션 235): `body_translated` · `translated_lang`(`ko`|`ja`) · `translate_status`(`pending`|`done`|`failed`|`skipped`)
- 번역 서버 함수 `supabase/functions/translate-message/index.ts`
  - `targetLangFor(sender_kind)`: 회원 글 → `ko`, 운영팀 글 → `ja`
  - 🔴 **감지된 원본 언어 == 목표 언어면 `skipped`** — 운영팀이 일본어로 쓰면 목표가 `ja` 라 번역하지 않는다 → 요청 2의 원인
- 관리자 말풍선 `dev/js/admin-messaging.js`(번역 병기 블록, `hasTrans` 분기)
  - 회원 글: **한국어 번역이 본문 위치**, 일본어 원문이 아래 「원문」 작은 글씨 → 요청 1의 대상
  - 운영팀 글: 한국어 원문이 본문, 아래 「일본어 번역(자동)」 + 「인플루언서 화면에는 위 일본어가 본문으로 표시됩니다」 — 라벨이 **일본어 번역이라고 못 박혀 있다**
- 🔴 **회원 말풍선** `dev/js/messaging.js`: 받은 글(운영팀 글)에 번역이 있으면 **번역을 본문 위치**에 그린다. **번역 언어(`translated_lang`)를 보지 않는다**
- 관리자 대화 목록 미리보기(`admin-messaging.js` 두 자리 — 캠페인 문의·서비스 문의 목록)는 회원 글이면 한국어 번역을 우선 쓴다

## 고칠 것

### ① 번역 서버 함수 — 같은 언어면 반대 언어로

- 감지된 원본 언어가 목표 언어와 같으면 건너뛰지 말고 **반대 언어로 다시 번역**한다(`ja` ↔ `ko`). `translated_lang` 에는 **실제 번역한 언어**를 적는다
  - 운영팀이 일본어로 씀 → `ko` 번역(관리자가 읽을 한국어)
  - 회원이 한국어로 씀 → `ja` 번역(드문 경우 — 대칭으로 둔다)

- 두 번째 호출은 **같은 원문**(`MAX_TRANSLATE_LEN` 으로 자른 것)을 반대 언어로 보낸다 — 첫 호출의 결과를 다시 번역하지 않는다. 두 번째 호출이 실패하면 `failed`(첫 호출의 같은 언어 결과는 저장하지 않는다)
- 호출이 한 번 더 드는 것은 「운영팀 일본어 글」·「회원 한국어 글」뿐이다. 일괄 발송은 행마다 한 번씩 돌므로 일본어 일괄문이면 행 수만큼 늘어난다
- 감지 언어는 **문자열이 정확히 `ja`·`ko` 일 때만** 반대 언어로 돌린다(`zh-CN` 처럼 지역 표기가 오거나 값이 없으면 지금처럼 목표 언어 번역을 쓴다)
- 재진입 걱정 없음 — 웹훅은 INSERT 에만 걸리고 번역 저장은 UPDATE 이며, 이미 처리된 행은 함수가 건너뛴다

### ② 회원 화면 — 일본어 번역일 때만 본문으로 (🔴 ①과 같은 배포)

- `messaging.js` 받은 글 분기에 **`translated_lang === 'ja'` 조건**을 더한다. 아니면 원문만 그린다
- 🔴 **① 만 먼저 나가면 운영팀의 일본어 글이 회원에게 한국어 번역으로 보인다.** 배포 순서: **화면(②) 먼저 → 서버 함수(①)** — 화면이 먼저 나가도 지금 데이터에는 `ko` 번역이 운영팀 글에 없어 아무 영향이 없다. 화면은 **운영(`main`)까지** 나간 뒤, 옛 회원 앱을 들고 있는 브라우저가 충분히 줄어든 다음에 서버 함수를 내보낸다(옛 앱은 한국어 번역을 본문으로 그린다). 서버 함수 배포(`supabase functions deploy translate-message`)는 개발·운영 각각

### ③ 관리자 말풍선 — 원문 위, 번역 아래

- **회원 글·운영팀 글 모두**: 본문 = 원문(`body`), 아래 = 번역(`body_translated`) + 라벨
- 라벨은 **`translated_lang` 으로** 정한다 — `ko` 면 「한국어 번역(자동)」, `ja` 면 「일본어 번역(자동)」
- 운영팀 글의 안내 「인플루언서 화면에는 위 일본어가 본문으로 표시됩니다」는 **`translated_lang === 'ja'` 일 때만**(일본어로 썼으면 회원은 원문 그대로 본다). 위치가 아래로 바뀌므로 문구를 「인플루언서 화면에는 이 일본어 번역이 본문으로 표시됩니다」로
- 목록 미리보기(두 자리)는 **이번 범위 밖** — 한국어로 빨리 훑는 용도라 지금처럼 번역 우선 유지. ⚠️ 회원이 한국어로 쓴 드문 경우엔 `ja` 번역이 생겨 미리보기가 일본어를 보일 수 있다(허용). 🔴 **미리보기를 새로 쓰는 쪽은 번역 방향(`sender_kind`·`translated_lang`)을 확인할 것** — 서비스 문의 여러 대화 뷰(506)에 이미 `last_message_preview_translated` 칸이 있다(아직 화면에서 안 쓴다)
- 관리자 대화 내용 검색은 번역문으로도 찾는다 — 이번 변경으로 운영팀 일본어 글의 한국어 번역도 검색된다(의도된 개선)

## 기존 데이터

- 이미 `skipped` 로 남은 운영팀 일본어 글은 **다시 번역하지 않는다**(원문만 보인다). 필요하면 개발 세션이 판단 — 🔴 방법은 `translate_status` 를 **`NULL`** 로 되돌리고 서비스 키로 함수를 **직접 호출**(웹훅은 INSERT 에만 걸려 UPDATE 로는 안 돈다. `pending` 으로 돌리면 함수가 「이미 처리됨」으로 건너뛴다)

## 확인할 것

1. 회원 일본어 글 → 관리자 화면에 일본어 원문 위, 「한국어 번역(자동)」 아래
2. 운영팀 한국어 글 → 관리자 화면에 한국어 원문 위, 「일본어 번역(자동)」 + 인플루언서 안내 아래 · 회원 화면에 일본어 번역이 본문
3. 운영팀 일본어 글 → 관리자 화면에 일본어 원문 위, 「한국어 번역(자동)」 아래(인플루언서 안내 없음) · **회원 화면에는 일본어 원문만**(한국어가 보이면 실패)
4. 번역 실패·첨부만 있는 글 → 원문만(지금과 같음)
5. 캠페인 문의·서비스 문의 양쪽 말풍선 · 일괄 발송 글도 같은 규칙
