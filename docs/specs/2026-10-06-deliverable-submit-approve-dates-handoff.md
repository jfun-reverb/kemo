# 인수인계 — 회원 활동관리 결과물 옆에 제출일·승인일 표시

**상태:** 📄 인수인계 — 개발 세션 착수 대기 (2026-10-06)
**종류:** 미세 조정 + 기록 방식 정정(데이터베이스 트리거 1개 — 표·칸 추가 없음)

## 요청 (2026-10-06 사용자)

회원 활동관리 화면의 영수증·결과물 옆 날짜가 무엇인지 헷갈린다 → **제출일과 승인일을 둘 다 보여 준다.**

## 현재 상태 (`origin/dev` 확인)

- 날짜 칸은 **세 자리** — `dev/js/application.js` 의 `ac-row-date`: 1916줄(영수증 등 `r.submitted_at || r.created_at`) · 1985줄(리뷰 이미지 채널별 `row.submitted_at || row.created_at`) · 2187줄(게시물 URL `d.submitted_at`). 임시저장 행은 날짜 대신 삭제 버튼
- 회원 조회 `fetchDeliverablesForUser`(`dev/lib/storage.js`)는 `select('*')` 라 **`reviewed_at` 이 이미 화면에 와 있다**
- 🔴 **`submitted_at` 은 「제출한 날」이 아니다** — 행이 처음 만들어질 때(`035` 기본값 `now()`) 한 번 찍히고, 그 뒤 바뀌지 않는다:
  - 임시저장 → 「제출하기」(`submitDrafts`)는 `status` 만 `pending` 으로 바꾼다 → **임시저장한 날**이 남는다
  - 반려 뒤 재제출도 날짜를 안 바꾼다 → **처음 올린 날**이 남는다. (재제출은 `insertDraftDeliverable` 이 그 행을 **임시저장으로 되돌린 뒤** `submitDrafts` 가 검수 대기로 올린다 — 즉 반드시 임시저장을 거친다)
  - 예외: 관리자 대리 등록·게시물 교체(`admin_create_deliverable_proxy`, 현재 원본 184)는 `submitted_at = now()`
- 같은 칸을 다른 곳도 「제출일」로 쓴다 — **착수 전 대조 대상(전수는 개발 세션이 규칙 D 로 다시 센다)**: 관리자 결과물 관리(`admin-deliverables.js` `latest_submitted_at` 필터·정렬, 상세 「제출일」, 제출 이력 정렬, 「제출일 · 검수일」 표시) · 신청 관리(`admin-applications.js` 정렬·최신 제출일) · 엑셀(`admin-excel.js` 제출일 열·그룹 최신 고르기) · `storage.js` 조회 정렬(검수 대기 `order('submitted_at')` 등) · 리포트 최신 고르기(`report-rows.js`) · 회원 쪽 `application.js` 제출 목록 정렬·`mypage.js` 종류별 최신 · 🔴 **검수 결과 메일**(`supabase/functions/notify-deliverable-decision` — 채널별 최신 고르기와 본문·텍스트 판의 「提出日」(제출일))
- 메일 양식(`docs/email-templates/deliverable-*`)의 칸 이름은 그대로라 문구 수정은 없다 — 메일의 「提出日」 값이 「처음 올린 날」 → 「마지막으로 제출한 날」로 바뀐다(의도에 맞음)

## 고칠 것

### ① 제출 시각을 실제로 기록한다 — 서버 트리거

- `deliverables` 에 **BEFORE UPDATE 트리거**: 🔴 **임시저장(`draft`)이던 행이 검수 대기(`pending`)가 되는 순간에만** `NEW.submitted_at := now()` (`WHEN (OLD.status = 'draft' AND NEW.status = 'pending')`). 처음 제출(임시저장 → 제출하기)과 반려 뒤 재제출(임시저장을 거친다)이 모두 이 길을 지난다. 함수는 `SECURITY INVOKER` · `search_path` 고정
- 화면 코드(`submitDrafts` 등)에 넣지 않는 이유: 제출 경로가 여럿이고, 서버에서 한 번 하면 빠지는 경로가 없다
- 🔴 **「검수 대기가 아니던 행이 검수 대기가 되는 순간」으로 넓히지 않는다** — 관리자 되돌리기(`revertDeliv` → 승인·반려 → 검수 대기)도 그 조건에 걸려, 제출일이 **관리자가 되돌린 날**로 바뀌고 검수 대기 정렬에서 오래 기다린 건이 맨 뒤로 밀린다
- 기존 트리거(274 제출 마감 가드·상태 이벤트·알림·`updated_at`·정산 잠금·탈퇴 차단)는 이 칸을 읽거나 쓰지 않아 순서 충돌이 없다(리뷰 확인)
- 대리 등록(184)은 이미 `now()` 를 넣으므로 그대로. 승인으로 바뀌는 순간에는 건드리지 않는다
- 🔴 **기존 행은 고치지 않는다** — 과거의 실제 제출 시각은 어디에도 없다(이벤트 기록 `deliverable_events` 에 남아 있을 수 있으나 되살리기는 이번 범위 밖)
- ⚠️ **관리자 화면·검수 결과 메일의 「제출일」도 함께 정확해진다**(위 「착수 전 대조 대상」). 뜻이 「처음 올린 날」 → 「마지막으로 제출한 날」로 바뀌는 것이라, 검수 대기 정렬이 실제 제출 순서가 되는 등 대부분 의도에 맞는다. 착수 전 대조(규칙 D)에서 그 자리들 중 「처음 올린 날」이어야 하는 자리가 있는지 확인한다

### ② 회원 화면에 두 날짜

| 상태 | 보일 것 |
|---|---|
| 승인 | `提出日 2026/08/19` (제출일) + `承認日 2026/08/20` (승인일 — `reviewed_at`) |
| 검수 대기·반려 | `提出日` 만 |
| 임시저장 | 지금처럼 삭제 버튼(날짜 없음) |

- 세 자리(1916·1985·2187줄) 모두 같게. 날짜 줄을 그리는 **공용 함수 하나**로 만든다(세 벌 복사 금지)
- 날짜 형식은 `formatDate`(`YYYY/MM/DD`) 그대로
- 번역 키 `ja`·`ko` 둘 다 — 「提出日」(제출일)·「承認日」(승인일)
- 승인인데 `reviewed_at` 이 비어 있는 옛 행이 있으면 승인일 줄을 그리지 않는다(빈 날짜 금지)
- 회원 앱은 Apple 지침 화면 — 두 줄이 좁은 오른쪽 칸에서 넘치지 않는지 모바일 폭(375px)에서 확인

## 확인할 것

1. 임시저장 → 다음 날 「제출하기」 → 제출일이 **제출한 날**
2. 반려 → 재제출 → 제출일이 **재제출한 날**
3. 승인 → 제출일 + 승인일 두 줄 · 검수 대기·반려는 제출일만
4. 대리 등록 결과물 → 제출일 = 승인일(등록한 날)
5. 관리자 결과물 관리의 「최근 제출일」 필터·정렬·상세 제출일, 엑셀 제출일 열, 검수 결과 메일의 「提出日」이 새 제출 시각을 따른다
6. 일본어·한국어 둘 다 · 375px 폭
7. **승인 → 관리자 되돌리기 → 제출일이 바뀌지 않는다** · 검수 대기 정렬 위치도 그대로
