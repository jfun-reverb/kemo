## 사양서 stale 점검

1. 직전 작업표 572·574줄·S25의 「기록용 판정 = 화면식 `applied_reverb === 0 && ext_participants > 0`」은 이미 의미가 없다.
   - 587이 그 칸 셋을 지웠다.
   - 브랜드 화면은 88e88bfc 부터 합계만 읽는다.
   - → 브랜드 화면에서 바꿀 자리가 없다(조각 9는 확인만 한다). 직전 작업표의 그 줄들은 조각 12에서 「폐기」로 정리한다.
2. ⑥ 「복제는 등록 전에 바꿀 수 있다」는 지금 구조(즉시 저장)와 맞지 않는다. → S3로 정했다. 사양서 문장을 고친다.
3. ⑥은 조치 경고를 말하지 않는다. → S2.
4. ⑥은 노출 토글의 뜻을 말하지 않는다. → S5.
5. 인플루언서 일일 메일·마감 임박 메일은 응모 행에서 출발한다. 그래서 조각 1이 응모를 관리자 통과 조항보다 **앞**에서 막으면 저절로 0이 된다.
6. ⑥ 「폼 칸을 하나도 숨기지 않는다」와 오프라인 행사 조합이 부딪친다. → S4.
7. 피그마 a05-07 문구의 「일일 메일」은 「인플루언서 일일 메일」로 고친다(조각 10).

## 조각별 상세

### 조각 1. 칸·불변·응모 거부·행사 조합 (새 마이그레이션 A)

**산출 계약**
- `ALTER TABLE public.campaigns ADD COLUMN is_record_only boolean NOT NULL DEFAULT false` + 칸 설명(만든 뒤 불변 · 인플루언서 비노출 · 브랜드 응답에 싣지 않는다).
- 트리거 `trg_campaigns_record_only_lock`(`BEFORE UPDATE OF is_record_only`)
  - 값이 바뀌고 `auth.uid() IS NOT NULL` 이면 `RAISE 'record_only_locked: …'` 로 거부한다.
  - 로그인 없는 실행은 통과한다(S7).
  - 함수는 `SECURITY INVOKER` 로 둔다.
- 검사 제약 `campaigns_record_only_not_event CHECK (NOT (is_record_only AND event_mode IS TRUE))`(S4).
- `check_application_deadline()` — **326 베이스** `CREATE OR REPLACE`
  - 보관 삭제 검사 바로 뒤, **관리자 통과 조항보다 앞**에 `RAISE 'recruit_not_open: 기록용 캠페인에는 응모할 수 없습니다 (record_only)'` 를 넣는다.
  - 나머지는 326과 글자 그대로 둔다.
- `NOTIFY pgrst, 'reload schema';` + 기록 줄.

**완료 정의** — 🔴 로그인한 브라우저로 확인한다(SQL 편집기는 서비스 키라 재현이 안 된다).
- 칸·트리거·제약이 카탈로그에 보인다.
- 관리자 콘솔에서 기록용 값을 바꾸는 `update` 가 `record_only_locked` 로 거부된다. 같은 캠페인의 제목 수정은 성공한다.
- 회원이 기록용 `active` 캠페인에 응모하면 거부되고 「このキャンペーンは現在応募を受け付けていません」("이 캠페인은 현재 응모를 받지 않습니다")가 뜬다.
- 관리자로 응모를 넣어도 거부된다.
- 기록용 + 행사 삽입이 거부된다.

**검문소:** reverb-supabase-expert · reverb-reviewer · 다른 개발자에게 「326 재정의」를 알린다

**롤백**
- 운영 순서를 거꾸로 따라간다(생성 화면을 먼저 걷고 숨김을 나중에): 화면 10·11 → 6~8 → 5 → 4 → 3 → 2 → 이 조각. 롤백 시작 전에 기록용 캠페인이 0건인지(있으면 보관 삭제) 확인한다.
- 이 조각은 트리거·제약을 지우고 326 함수 블록을 다시 실행한 뒤, 맨 마지막에 칸을 지운다.

### 조각 2. 캠페인 조회 정책 (새 마이그레이션 B)

**산출 계약**
- `DROP POLICY IF EXISTS campaigns_select_public ON public.campaigns;`
- `CREATE POLICY campaigns_select_public … FOR SELECT USING (is_record_only = false OR (SELECT public.is_admin()));`
- 정의자 권한 함수(브랜드·홍보 메일·공유 리포트·관리자)와 서비스 키에는 영향이 없다.

**착수 전 확인**
- 두 서버 각각에서 `SELECT p.proacl::text FROM pg_proc p WHERE p.proname='is_admin';` 결과에 `anon=X` 가 있는지 본다. 🔴 없으면 멈추고 기획에 넘긴다 — 로그아웃 목록이 통째로 실패한다.
- `pg_policies` 에서 캠페인 조회 정책이 하나뿐인지 본다.

**완료 정의(브라우저)**
- 로그아웃 목록 장수가 적용 전과 같다.
- 기록용 시험 캠페인이 로그아웃·회원·브랜드 계정 콘솔 직접 조회로는 0행이고, 관리자로는 1행이다.
- 브랜드 캠페인 목록 화면에는 보인다.
- 회원 응모이력·활동관리 화면이 적용 전과 같다.

**검문소:** reverb-supabase-expert · reverb-reviewer(지목: 비관리자가 `campaigns` 를 읽는 자리를 세 형태로 다시 셌는가)

**롤백:** `USING (true)` 로 다시 만든다(칸을 지우기 전에).

- 일반·초대 전용·준비 캠페인 동작은 적용 전과 같다.

### 조각 10. 등록·편집 폼·확인 모달·복제 (kemo-af — 핫스팟 단독)

**등록 폼:** 제목 줄 아래, 첫 폼 카드 위에 연보라 상자를 둔다.

**오리엔시트 발행 경로:** 오리엔시트 「이 카드로 발행」(`applyOrientCardPrefill`, admin-orient.js:2384)은 같은 등록 폼(`#adminPane-add-campaign`)을 열어 값을 채운 뒤 같은 `addCampaign` 으로 저장한다. 그래서 체크·모달은 등록 폼 몫으로 저절로 따라온다 — `admin-orient.js` 는 확인만 하고, 그 함수가 체크를 덮어쓰면(초기화 뒤 채우는 순서) 이 조각에서 고친다.

**확인 모달(a05-08)** — 입력 검증 뒤, 동적 생성 `modal-overlay open`.
- 제목: 「기록용 캠페인으로 등록하시겠습니까?」
- 본문: 「「{캠페인명}」은 인플루언서에게 보이지 않는 기록용 캠페인으로 등록됩니다. 등록한 뒤에는 일반 캠페인으로 바꿀 수 없습니다 — 인플루언서 모집이 필요하면 새 캠페인을 등록해 주십시오.」
- 버튼: 「취소」(폼으로, 입력 유지) · 「기록용으로 등록」(검정)
- 체크가 꺼져 있으면 모달 없이 등록한다.

**노출 문구(S5)** — `setCampVisibilitySub` 가 노출 토글과 기록용 체크를 **함께** 보고 문구를 고른다. 둘 중 하나를 바꾸면 즉시 다시 그린다.

| 기록용 체크 | 노출 토글 | 문구 |
|---|---|---|
| 꺼짐(일반) | 켜짐 | 지금 그대로 — 「등록 후 바로 인플루언서에게 공개됩니다」 |
| 꺼짐(일반) | 꺼짐 | 지금 그대로 — 「「준비」 상태로 저장되어 인플루언서에게 보이지 않습니다. 나중에 목록에서 공개할 수 있습니다」 |
| 켜짐(기록용) | 켜짐 | 「등록 후 브랜드 페이지에 보입니다 (인플루언서에게는 보이지 않습니다)」 |
| 켜짐(기록용) | 꺼짐 | 「「준비」 상태로 저장되어 브랜드 페이지에도 보이지 않습니다. 나중에 목록에서 공개할 수 있습니다」 |

**복제(S3):** 원본이 기록용이면 삽입 전에 고르는 창을 띄운다 — 「기록용으로 복제」·「일반 캠페인으로 복제」·「취소」. 원본이 일반이면 묻지 않고 `false` 로 복제한다.

**행사 조합(S4):** 기록용과 오프라인 행사를 둘 다 켜고 저장하면 「기록용 캠페인은 오프라인 행사로 만들 수 없습니다」 안내 후 중단한다.

**오류 문구** — `friendlyError` 에 둘을 등록한다.
- `record_only_locked` → 「기록용 여부는 등록한 뒤 바꿀 수 없습니다」
- `campaigns_record_only_not_event` → 행사 조합 안내 문구

**완료 정의(개발서버, 마우스로)**
- 등록: 체크를 켜면 모달이 뜬다. 「취소」면 입력이 유지되고, 「기록용으로 등록」이면 저장된다. 체크를 끄면 모달이 없다.
- 편집: 체크가 잠겨 있고, 다른 칸을 저장해도 기록용 값이 그대로다. 일반 캠페인은 체크가 꺼진 채 잠겨 보인다.
- 복제: 기록용 원본이면 창이 뜨고, 고른 값으로 복제된다.
- 다시 들어오면 체크가 꺼져 있다.
- 오리엔시트 「이 카드로 발행」에서도 같은 모달을 거친다.

**검문소:** reverb-reviewer(지목: `refreshPane('campaigns')` · 모달 ESC·바깥 클릭 · 겹침 순서) · reverb-qa-tester 권장
