**작성일:** 2026-07-15
**작성 주체:** 기획 세션
**성격:** 베타 2차 「브랜드 포털」 조기 기획. 로드맵이 "최대 불확실·조기 기획 권장"으로 지목한 항목. 이 문서는 **완성 사양서가 아니라 방향 골격 + 미결 관문 목록**이다. 세부(블록별 상세 설계·DB·RLS·법률)는 후속 단계에서 채운다.

## 0. 이 기획이 여는 것 — 세 번째 사용자 유형

지금까지 REVERB JP의 사용자는 **인플루언서**(일본어 앱)와 **관리자**(한국어 앱) 둘뿐이다. 브랜드 포털은 **브랜드사(광고주)** 라는 세 번째 사용자 유형을 처음으로 시스템에 들인다. 그래서 인증·접근제어·개인정보가 전부 새 영역이다.

## 1. 현재 상태 (2026-07-15, 코드·DB 직접 조사)

### 브랜드가 지금 시스템과 닿는 지점 — 전부 "입력(쓰기)"뿐, "조회(읽기)" 0
- **광고주 신청 폼**(`sales/reviewer.html`·`seeding.html`) — 로그인 없이 `submit_brand_application` 원격 호출 함수로 제출. **현재 공개 접수 차단 중**(마이그레이션 206).
- **오리엔시트 작성 폼**(`dev/sales/orient.html`) — 관리자가 발급한 토큰(`?token=`) 링크로, 로그인 없이 캠페인 콘텐츠 작성·제출. 익명 함수 3종(`get_orient_sheet`/`save_orient_draft`/`submit_orient_sheet`, 마이그레이션 187).
- **브랜드가 자기 캠페인 현황·결과물·정산을 "보는" 경로는 전혀 없음.**

### 보여줄 데이터·집계는 이미 있음 (단, 관리자 전용 잠금)
- `get_brand_ops_overview(회사)` / `get_brand_ops_detail(브랜드)` — 모집률·결과물 승인률·캠페인 목록·견적 집계(마이그레이션 120·148·149·150). 둘 다 **`is_admin()` 가드** → 브랜드가 직접 못 읽음. 브랜드 몫만 떼주는 조회 함수 신설 필요.
- 진행현황 비용 카드 산식(견적·운영비, `admin-applications.js:234~`).

### 인증·계정 구조
- 인플루언서·관리자 모두 같은 로그인(`signInWithPassword`) → 로그인 후 `admins` 테이블 조회로 분기(`auth.js:156`).
- ⚠️ **자동 등록 트리거(`handle_new_user`, 마이그레이션 014)**: 어떤 신규 계정이든 무조건 `influencers` 행을 만든다. **브랜드가 정식 로그인 계정을 만들면 인플루언서로 섞임** → 정식 계정 방식 도입 시 이 트리거부터 수정 필요.
- 브랜드측 로그인 계정 개념 없음. 브랜드 대표 담당자 이메일은 `brands.contacts`(jsonb, 정본)에 텍스트로만 존재.

### 검증된 재사용 패턴
- **토큰 기반 익명 조회 함수**(오리엔시트 3종 + 수신거부 토큰 마이그레이션 140) — 로그인 없이 토큰으로 자기 데이터만, 자원 열거 방지(`success:false`). **1차 포털 조회의 최적 템플릿.**

### 충돌 가능성 있는 기존 동작
- 오리엔시트 토큰은 **1시트 스코프**(그 시트 하나만). 브랜드 포털은 **브랜드/회사 단위** 접근이 필요 → 브랜드 단위 토큰 신설.
- 모든 브랜드 관련 테이블 SELECT가 `is_admin()` 전용 → 브랜드는 **직접 테이블 조회 불가**, 반드시 SECURITY DEFINER + 스코프 가드 함수로만.

## 3. 의심·경우의 수 (반대론자 모드)

### 깨질 수 있는 경우의 수
1. **(법률·최중요) 결과물 개별 링크 = 인플루언서 개인정보 제3자 제공** — 브랜드에게 "이 인플루언서가 우리 캠페인에 참여해 이 게시물을 올렸다"(SNS 계정·게시물 연결)를 노출하는 것. APPI(일본)/PIPA(한국) 관점에서 **개인정보처리방침 개정 + 동의(또는 캠페인 참여 시 결과물 공유 동의 근거) 확인**이 필요. 영수증은 명백한 민감정보라 브랜드 노출 제외 권장. → **법률 딥리서치가 출시 전제**(아웃바운드 명단 제3자 제공 관문과 동류, 메모리 `project_outbound_roster_privacy` 참고).
2. **(통제) 브랜드 자체 오리엔시트 생성 → 무제한 생성·스팸·잘못된 발행** — 현재는 관리자가 발급을 통제하고, 발행 시 일본어 미보완 차단 게이트가 있다. 브랜드가 스스로 만들면 이 통제가 사라짐 → **관리자 검토 게이트(제출된 오리엔시트를 관리자가 확인 후 캠페인 발행) 유지 + 브랜드 생성 수량·자격 제한** 필요.
3. **(인증 함정) 정식 계정 도입 시 자동 등록 트리거** — 2차에서 브랜드 로그인 계정을 만들면 `handle_new_user`(014)가 브랜드를 인플루언서로 등록. 트리거 분기 수정 없이는 데이터 오염.
4. **(보안) 토큰 유출** — 1차 토큰 링크가 유출되면 제3자가 브랜드 현황을 봄. 만료·재발급·브랜드 스코프 제한 필요. 특히 결과물 링크가 포함되면 유출 시 개인정보 노출.
5. **(데이터 매핑) 회사 vs 브랜드 단위** — 한 회사에 여러 브랜드, 한 브랜드에 여러 캠페인. 토큰/계정을 **브랜드 단위로 발급할지 회사 단위로 발급할지** 결정 필요(담당자 이메일은 브랜드에 붙어있음).
6. **(UX·빈 상태) 신규 브랜드** — 캠페인이 아직 없는 브랜드가 포털에 들어오면 텅 빈 화면. 안내 문구·"진행 중 캠페인 없음" 상태 필요.
7. **(환경) 세 번째 앱 신설** — `brand/` 전용 페이지 + 빌드 + 도메인(brand.globalreverb.com?) + Vercel 프로젝트 추가 여부. 1차 토큰 조회는 오리엔시트처럼 `sales/` 계열 정적 페이지로 시작 가능.

### 의도 모호점 (확인 완료 / 미결)
- ✅ 포털 성격 = 단계적(토큰→계정)
- ✅ 오리엔시트 = 브랜드 자체 생성
- ✅ 결과물 = 개별 링크
- ⬜ **토큰/계정 발급 단위 = 회사 vs 브랜드** (미결)
- ⬜ **결과물 개별 링크의 법률 판정** (딥리서치 필요)
- ⬜ **브랜드 자체 오리엔시트 생성의 통제 게이트 구체안** (미결)

## 4. 단계 설계 골격

### 1차 — 토큰 링크 조회 포털 (개인정보 관문 없는 것부터)
- **인증**: 브랜드 단위 접근 토큰(오리엔시트 토큰 패턴 확장). 로그인 없음.
- **화면**(`sales/` 계열 정적 페이지 후보):
  - **A. 모집 현황** — 지원·선정·모집률 (기존 `get_brand_ops_detail` 집계를 브랜드 스코프 wrapper로 재사용)
  - **B. 진행 단계·일정** — 캠페인 상태·마감일
  - **C. 오리엔시트** — 브랜드 자체 생성·작성·제출 (통제 게이트 포함)
- **신규 필요**: 브랜드 스코프 조회 함수(SECURITY DEFINER + 토큰 가드, anon GRANT), 브랜드 토큰 발급·관리(관리자 화면), 브랜드 자체 오리엔시트 생성 함수 + 관리자 검토 게이트.
- **D. 결과물 개별 링크는 법률 관문 통과 후** 1차 후반 또는 별도로.

### 2차 — 정식 로그인 계정
- 브랜드 계정 테이블(`brand_users`, auth_id) + `is_brand()` 판정 + 자동 등록 트리거(014) 분기 수정.
- 브랜드 스코프 접근제어(자기 회사/브랜드만) 전면 신설.
- 세 번째 앱(`brand/`) + 자체 로그인 폼.
- 회원가입·온보딩(사업자·담당자 정보).

## 5. 미결 관문 · 다음 액션

1. **법률 딥리서치 (결과물 개별 링크 제3자 제공)** — `deep-research` 스킬. APPI/PIPA 관점에서 "가입 인플루언서의 캠페인 결과물(SNS 게시물·계정)을 대행 브랜드에게 포털로 노출"이 제3자 제공인지, 캠페인 참여 동의로 커버되는지, 개인정보처리방침 개정·별도 동의가 필요한지. (영수증 제외 전제)
2. **발급 단위 결정** — 토큰/계정을 회사 단위 vs 브랜드 단위로.
3. **브랜드 자체 오리엔시트 생성 통제 게이트 설계** — 수량·자격 제한 + 관리자 검토 후 발행.
4. **1차 화면 배치·와이어프레임** — A·B·C 블록 레이아웃 (인플루언서 앱 Apple HIG 준하되 브랜드는 PC/모바일 병행 검토).
