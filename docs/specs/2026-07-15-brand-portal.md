## 0. 이 기획이 여는 것 — 세 번째 사용자 유형

지금까지 REVERB JP의 사용자는 **인플루언서**(일본어 앱)와 **관리자**(한국어 앱) 둘뿐이다. 브랜드 포털은 **브랜드사(광고주)** 라는 세 번째 사용자 유형을 처음으로 시스템에 들인다. 그래서 인증·접근제어·개인정보가 전부 새 영역이다.

## 1. 현재 상태 (2026-07-15, 코드·DB 직접 조사)

### 브랜드가 지금 시스템과 닿는 지점 — 전부 "입력(쓰기)"뿐, "조회(읽기)" 0
- **광고주 신청 폼**(`sales/reviewer.html`·`seeding.html`) — 로그인 없이 `submit_brand_application` 원격 호출 함수로 제출. **현재 공개 접수 차단 중**(마이그레이션 206).
- **오리엔시트 작성 폼**(`dev/sales/orient.html`) — 관리자가 발급한 토큰(`?token=`) 링크로, 로그인 없이 캠페인 콘텐츠 작성·제출. 익명 함수 3종(`get_orient_sheet`/`save_orient_draft`/`submit_orient_sheet`, 마이그레이션 187).
- **브랜드가 자기 캠페인 현황·결과물·정산을 "보는" 경로는 전혀 없음.**

### 보여줄 데이터·집계는 이미 있음 (단, 관리자 전용 잠금)
- `get_brand_ops_overview(회사)` / `get_brand_ops_detail(브랜드)` — 모집률·결과물 승인률·캠페인 목록·견적 집계(마이그레이션 120·148·149·150). 둘 다 **`is_admin()` 가드** → 브랜드가 직접 못 읽음. 브랜드 몫만 떼주는 조회 함수 신설 필요.
- 진행현황 비용 카드 산식(견적·운영비, `admin-applications.js:234~`).

### 인증·계정 구조
- 인플루언서·관리자 모두 같은 로그인(`signInWithPassword`) → 로그인 후 `admins` 테이블 조회로 분기(`auth.js:156`).
- ⚠️ **자동 등록 트리거(`handle_new_user`, 마이그레이션 014)**: 어떤 신규 계정이든 무조건 `influencers` 행을 만든다. **브랜드가 정식 로그인 계정을 만들면 인플루언서로 섞임** → 정식 계정 방식 도입 시 이 트리거부터 수정 필요.
- 브랜드측 로그인 계정 개념 없음. 브랜드 대표 담당자 이메일은 `brands.contacts`(jsonb, 정본)에 텍스트로만 존재.

### 검증된 재사용 패턴
- **토큰 기반 익명 조회 함수**(오리엔시트 3종 + 수신거부 토큰 마이그레이션 140) — 로그인 없이 토큰으로 자기 데이터만, 자원 열거 방지(`success:false`). **1차 포털 조회의 최적 템플릿.**

### 충돌 가능성 있는 기존 동작
- 오리엔시트 토큰은 **1시트 스코프**(그 시트 하나만). 브랜드 포털은 **브랜드/회사 단위** 접근이 필요 → 브랜드 단위 토큰 신설.
- 모든 브랜드 관련 테이블 SELECT가 `is_admin()` 전용 → 브랜드는 **직접 테이블 조회 불가**, 반드시 SECURITY DEFINER + 스코프 가드 함수로만.

## 3. 의심·경우의 수 (반대론자 모드)

### 깨질 수 있는 경우의 수
1. **(법률·최중요) 결과물 개별 링크 = 인플루언서 개인정보 제3자 제공** — 브랜드에게 "이 인플루언서가 우리 캠페인에 참여해 이 게시물을 올렸다"(SNS 계정·게시물 연결)를 노출하는 것. APPI(일본)/PIPA(한국) 관점에서 **개인정보처리방침 개정 + 동의(또는 캠페인 참여 시 결과물 공유 동의 근거) 확인**이 필요. 영수증은 명백한 민감정보라 브랜드 노출 제외 권장. → **법률 딥리서치가 출시 전제**(아웃바운드 명단 제3자 제공 관문과 동류, 메모리 `project_outbound_roster_privacy` 참고).
2. **(통제) 브랜드 자체 오리엔시트 생성 → 무제한 생성·스팸·잘못된 발행** — 현재는 관리자가 발급을 통제하고, 발행 시 일본어 미보완 차단 게이트가 있다. 브랜드가 스스로 만들면 이 통제가 사라짐 → **관리자 검토 게이트(제출된 오리엔시트를 관리자가 확인 후 캠페인 발행) 유지 + 브랜드 생성 수량·자격 제한** 필요.
3. **(인증 함정) 정식 계정 도입 시 자동 등록 트리거** — 2차에서 브랜드 로그인 계정을 만들면 `handle_new_user`(014)가 브랜드를 인플루언서로 등록. 트리거 분기 수정 없이는 데이터 오염.
4. **(보안) 토큰 유출** — 1차 토큰 링크가 유출되면 제3자가 브랜드 현황을 봄. 만료·재발급·브랜드 스코프 제한 필요. 특히 결과물 링크가 포함되면 유출 시 개인정보 노출.
5. **(데이터 매핑) 회사 vs 브랜드 단위** — 한 회사에 여러 브랜드, 한 브랜드에 여러 캠페인. 토큰/계정을 **브랜드 단위로 발급할지 회사 단위로 발급할지** 결정 필요(담당자 이메일은 브랜드에 붙어있음).
6. **(UX·빈 상태) 신규 브랜드** — 캠페인이 아직 없는 브랜드가 포털에 들어오면 텅 빈 화면. 안내 문구·"진행 중 캠페인 없음" 상태 필요.
7. **(환경) 세 번째 앱 신설** — `brand/` 전용 페이지 + 빌드 + 도메인(brand.globalreverb.com?) + Vercel 프로젝트 추가 여부. 1차 토큰 조회는 오리엔시트처럼 `sales/` 계열 정적 페이지로 시작 가능.

### 의도 모호점 (확인 완료 / 미결)
- ✅ 포털 성격 = 단계적(토큰→계정)
- ✅ 오리엔시트 = 브랜드 자체 생성
- ✅ 결과물 = 개별 링크
- ⬜ **토큰/계정 발급 단위 = 회사 vs 브랜드** (미결)
- ⬜ **결과물 개별 링크의 법률 판정** (딥리서치 필요)
- ⬜ **브랜드 자체 오리엔시트 생성의 통제 게이트 구체안** (미결)

## 4. 단계 설계 골격

### 1차 — 토큰 링크 조회 포털 (개인정보 관문 없는 것부터)
- **인증**: 브랜드 단위 접근 토큰(오리엔시트 토큰 패턴 확장). 로그인 없음.
- **화면**(`sales/` 계열 정적 페이지 후보):
  - **A. 모집 현황** — 지원·선정·모집률 (기존 `get_brand_ops_detail` 집계를 브랜드 스코프 wrapper로 재사용)
  - **B. 진행 단계·일정** — 캠페인 상태·마감일
  - **C. 오리엔시트** — 브랜드 자체 생성·작성·제출 (통제 게이트 포함)
- **신규 필요**: 브랜드 스코프 조회 함수(SECURITY DEFINER + 토큰 가드, anon GRANT), 브랜드 토큰 발급·관리(관리자 화면), 브랜드 자체 오리엔시트 생성 함수 + 관리자 검토 게이트.
- **D. 결과물 개별 링크는 법률 관문 통과 후** 1차 후반 또는 별도로.

### 2차 — 정식 로그인 계정
- 브랜드 계정 테이블(`brand_users`, auth_id) + `is_brand()` 판정 + 자동 등록 트리거(014) 분기 수정.
- 브랜드 스코프 접근제어(자기 회사/브랜드만) 전면 신설.
- 세 번째 앱(`brand/`) + 자체 로그인 폼.
- 회원가입·온보딩(사업자·담당자 정보).

## 5. 법률 딥리서치 결론 (2026-07-15, 완료)

> `deep-research` 실행(101개 에이전트, 19개 1차/2차 소스, 24개 클레임 검증 통과·1개 반증). 일본 개인정보보호위원회(PPC)·한국 개인정보보호위원회(PIPC) 1차 자료 기반. **결론: 결과물 개별 링크 노출은 무거운 법적 관문이며 변호사 확인이 전제.**

### 핵심 판정 (must / should)
1. **결과물 개별 링크(공개 SNS 게시물 URL·계정명) 노출 = "제3자 제공"으로 판정될 가능성 높음** (위탁 아님). 브랜드가 자기 캠페인 성과를 자기 이익으로 열람하므로, 데이터의 실질 이용 주체가 브랜드 → 위탁(委託) 구성은 무리. 한국 대법원 2016도13263 다요소 판례도 이 방향.
2. **공개된 정보라도 개인정보** (양국 공통). 일본 APPI는 공표 정보도 구별 없이 보호, 한국 PIPA는 처리자·수령자가 보유한 정보와 쉽게 결합해 식별 가능하면 개인정보. **브랜드는 이미 자기 캠페인 응모자·배송정보를 알아** 계정명이 마스킹돼도 재식별됨.
3. **캠페인 참여 동의로 자동 커버 안 됨** — must: "브랜드에게 결과물(개인정보) 제공"에 대한 **별도 명시 동의 + 개인정보처리방침 개정** 필요. (한국 PIPA 17조 5개 고지사항 / 일본 APPI 27조 사전 동의)
4. **국경 간 이전 관문 추가** — 일본 거주자 데이터를 한국 브랜드가 열람 = 국외 관련 이전. 일본 APPI 28조상 "외국 제3자 제공 인정" 취지의 **별도 사전 동의** 또는 상당조치 계약 체계 필요(한국은 PPC 적정성 인정국 아님). ⚠️ 한국 PIPA 국외이전 근거조문은 조사 중 특정 클레임이 **반증**됨 → 변호사가 실제 조문 확정 필요.
5. **★ 별표(`*`) 마스킹은 법적 부담을 완화하지 못함** (사용자 질의 핵심 판정). SNS 계정명은 그 자체로 공개·검색 가능해 부분 마스킹해도 재식별. 가명처리해도 양국 모두 **여전히 개인정보**이고, 동의 면제(통계·과학연구·공익보존)는 **상업적 브랜드 노출에 적용 안 됨**. → 마스킹으로 관문을 우회할 수 없음.
6. **영수증·구매내역 브랜드 노출 제외 = 타당** (목적 비례·최소 제공 원칙). 단 논거는 "민감정보라서"보다 "비공개 최소제공".
7. **집계 숫자(게시 N건·승인 여부)는 규제 밖에 둘 여지** — 단 참여자 소수면 브랜드가 개인 역추정 가능 → **진정한 익명·캠페인 단위 집계**여야 안전.

### 실무 체크리스트 (제3자 제공 구성 전제)
- (a) **개인정보처리방침**: 브랜드 제공 사실·수령 브랜드 범주·제공 항목(게시물 URL·계정명·게시 여부)·목적·보유기간·국외이전(한국) 사실 추가. **배포 시점에 동기화**(선제 반영 금지 — `release-timing.md`).
- (b) **인플루언서 동의**: 캠페인 응모/가입과 **분리된** "브랜드 제공 + 일본→한국 국외이전" 명시 동의(체크박스).
- (c) **안전조치**: 브랜드별 접근제어(자기 캠페인만)·열람 로그·영수증 등 서버 마스킹·최소 항목 노출.

### 법률 자문이 반드시 필요한 지점
① 위탁 vs 제3자 제공 최종 판정(계약 구조·이익 귀속) ② 일본→한국 국경 간 이전 적법 경로 + 한국 PIPA 국외이전 근거조문 확정(반증된 지점) ③ 동의 문안·방침 개정문의 양국 이중 준수.

### 이 결론이 기획에 주는 함의 + 사용자 결정 (2026-07-15)
- **결과물 개별 노출 = 무거운 관문** — 제3자 제공 + 국외이전 + 별도 동의 + 방침 개정 + 변호사 확인이 모두 전제. 별표 마스킹으로도 못 줄임(SNS 계정 재식별).
- **사용자 결정: 결과물 3종(SNS 게시물 링크 · 리뷰 캡처 이미지 · 영수증·구매내역) 개별 노출 진행.** 근거 = 타 인플루언서 시딩 플랫폼도 결과물을 브랜드에 제공하는 **업계 표준**. → 딥리서치와 배치 안 됨: 타 플랫폼도 **인플 동의를 받아** 적법화한 것이라, "동의 받으면 가능"의 방증. 막힌 건 "동의 없이 마스킹 우회"뿐.
- **진행 전제 3종 (must)**: ①인플루언서 동의(응모/가입 시 "결과물 브랜드 제공 + 일본→한국 국외이전" 명시) ②개인정보처리방침 개정(배포 시점 동기화) ③국외이전 경로 변호사 확인(우리 특유 관문 — 타 플랫폼은 일본 내수라 국경 없음).
- **⚠️ 영수증 특별 취급 (반대론자 기록)**: 영수증·구매내역은 비공개 민감정보(구매처·금액·이름·주소·결제수단). SNS 공개 게시물과 층위가 다름. → **개인정보(이름·주소·결제수단) 마스킹 후 노출** 권장(여기선 마스킹이 "정보 최소화"로 유효 — 계정 재식별 무효와 별개 층위). 원본 그대로 노출은 위험. 영수증 포함으로 변호사 확인 비중↑.

- ✅ 니즈 4블록: 모집현황·진행일정·오리엔시트(브랜드 자체생성)·결과물

## 8. 인플루언서 동의 설계 (2026-07-15)

### 현재 상태 (핵심 발견 — 완전 신설 아님, 강화·확장)
- **개인정보처리방침 §3.1 「브랜드 제공」이 이미 존재** — 제공 항목에 "게시된 콘텐츠 링크", 목적에 "콘텐츠 확인·캠페인 리포트 작성", **"신청·승인 시점에 동의한 것으로 간주"**. 즉 SNS 링크 제공은 이미 방침·동의 구조로 운영 중.
- **약관 근거**: 제19조(콘텐츠 링크 1년 무상 사용권을 회사·브랜드에 부여), 제11조(브랜드 콘텐츠 링크 활용), 제18조(브랜드 리포트 목적 SNS 데이터 이용).
- 동의 컬럼: `influencers.terms_agreed_at`·`privacy_agreed_at`(마이그022)·`age_consent_at`(마이그185), `applications.caution_agreed_at`+`caution_snapshot`(마이그067). 재동의 선례 = 연령 게이트(응모 직전 소급, 유일한 실제 재수집 동의). 약관 개정 재동의는 「묵시적 동의 + 사전 통지」 방침(사양서 `2026-05-28-policy-versioning.md`).

### 결정 (사용자, 2026-07-15): 방침 개정 + 동의 간주
현행 §3.1 방식(신청·승인 시 동의 간주)을 **유지·확장**. 명시 체크박스 신설 안 함.

**개정할 항목** (개인정보처리방침, 한·일 동시):
1. §3.1 브랜드 제공 **항목에 리뷰 캡처·영수증 추가** (영수증은 개인정보[이름·주소·결제수단] 마스킹 후).
2. §3.1 제공 **목적에 "브랜드 포털 열람" 추가**.
3. §5 국외이전에 **"한국 브랜드가 한국에서 열람" 경로 추가**(현재 §5는 클라우드 인프라만).

**기존 회원(약 1,400명)**: 별도 소급 게이트 없이 **방침 개정 + 사전 통지**(묵시적 동의, policy-versioning 패턴). 통지 인프라(마이그153 `policy_notice_*` + Edge Function `notify-policy-change`) 재사용.

### ⚠️ 반대론자 기록 — 안전지대 / 위험지대
| 결과물 | 동의 간주 적합성 | 대응 |
|---|---|---|
| SNS 게시물 링크 | ✅ 안전(이미 운영 중) | 방침 목적 확장만 |
| 리뷰 캡처 | 🟡 주의 | 항목 추가 + 캡처 내 개인정보 마스킹 |
| 영수증 | ⚠️ 위험(민감정보) | 마스킹 필수 + **변호사 확인** |
| 국외이전(한국 브랜드) | ⚠️ 가장 위험 | APPI 28조 외국이전 본인동의 원칙 → **변호사 확인이 핵심** |

- **동의 간주 vs 명시 동의**: 딥리서치는 제3자 제공·국외이전에 **명시 동의 권장**. 사용자 결정은 동의 간주(가벼움)이나, **영수증·국외이전 두 항목은 변호사 판단에 열어둠** — 변호사가 "명시 동의 필요"라 하면 그 두 항목만 명시 체크박스로 전환.
- **필수 동의 강제 시** 한국 PIPA상 "동의 거부권·거부 시 불이익" 고지 필요(변호사 영역).
- 방침 개정문·최종 동의 문안은 `/약관확인` + 변호사 확인 전제. **개정은 브랜드 포털 실제 배포 시점에 동기화**(선제 반영 금지 — `release-timing.md`).

### 인플루언서 안내 문구 톤 (2026-07-15 사용자 지시)
- **딱딱한 법률용어·위협적 표현 지양** — "국외이전", "당신 정보가 (해외로) 넘어갑니다" 같은 표현 금지. 인플루언서가 겁먹지 않게.
- **목적 중심의 쉬운 말** — 예: 「**한국 브랜드가 검수를 위해 결과물을 확인할 수 있습니다**」(주체=한국 브랜드 / 목적=검수 / 행위=확인). 인플루언서 안내 초등학생 눈높이 규칙(`.claude/rules/ui.md` 「인플루언서 안내 문구」)과 일치.
- ⚠️ **단 법적 고지 완전성은 유지** — 톤은 부드럽게 하되, "한국 브랜드가 본다"는 **사실 자체를 숨기거나 모호하게 하면 동의 무효 위험**. 사용자 제안 표현은 주체·목적·행위를 다 담아 부드러움 + 고지 요건을 함께 충족. 톤은 순화, 사실은 정확 — 최종 고지 완전성은 변호사 검토.
- 이 톤 원칙은 인플루언서에게 보이는 동의 체크박스·안내 배너·통지 메일 문구 전반에 적용.
