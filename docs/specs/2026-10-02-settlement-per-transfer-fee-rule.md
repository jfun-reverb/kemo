# 정산 — 송금별 수수료 요율·고정액 지정 (수수료 근거 남기기)

**작성일:** 2026-10-02 · **작성:** 개발 세션(사용자 지시 — 이 세션이 작성) · **받는 쪽:** 개발 세션
**상위:** `docs/specs/2026-09-30-settlement-transfer-fee-record.md`(송금 묶음·수수료) · `docs/specs/2026-10-01-settlement-sheet-backfill.md`(같은 날 「수수료 근거 줄」 — 이 문서 배경 ①) · 규칙 `.claude/rules/settlement.md`(Read 로 열 것)

## 배경 (사용자 2026-10-02)

송금완료 기록 창의 수수료 「수정」은 **수수료 금액만** 바꾼다. 그러면 나중에 「이 송금은 왜 수수료가 이 금액인가 — 그때 요율·고정액을 어떻게 봤길래?」에 답할 수 없다.

- 사용자 첫 제안: 공식 `보낸 금액 × 요율 + 고정액 = 수수료`에서 요율·고정액을 고치면 수수료가, 수수료를 고치면 요율·고정액이 맞춰지게.
- 검토 결과(사용자 승인): **수수료 → 요율 역산은 하지 않는다.** 미지수 둘에 식 하나라 어느 쪽을 움직일지 미리 정해야 하고, 역산한 요율(예: 4.444%)은 근거가 아니라 결과라 같은 의문을 다시 만든다.
  - 대신 ① **금액을 직접 고친 송금은 「규칙 계산 ¥A · 차이 ±¥B」로 근거를 남긴다** — 시트 소급 화면 작업에 넣어 **2026-10-02 운영 반영 완료**(조회 `fee_rule_jpy`, 마이그레이션 502).
  - ② **요율·고정액을 그 송금에 직접 지정** — 이 사양서.

## 확정된 결정

## 현재 상태 (2026-10-02, `origin/dev` 기준 — 코드 직접 확인)

### 관련 코드·데이터베이스
- **확인 창 수수료 「수정」**: `dev/js/admin-settlements.js` — `editBulkFee(bi)`·`onBulkFeeInput`·`resetBulkFee`(「자동으로」) · 묶음 상태 `feeOverride`(금액) · 렌더 `_renderBulkBundles` 의 `feeHtml`. 미리보기 `_scheduleBulkFeePreview` → `previewSettlementFees(totals)`(storage.js)
- **미리보기 `preview_settlement_fees(p_totals bigint[]) RETURNS jsonb`**(488): 현재 규칙 한 줄(`settlement_fee_rule`)로 합계 배열마다 `_settlement_fee_calc`. 반환 `{rate_percent, fixed_jpy, rounding, fees[]}`. 권한 `settlement.view` 읽기. 🔴 **계산식은 `_settlement_fee_calc` 한 곳 — 화면에 식을 두지 않는다**(작업표 조각 11 금지)
- **기록 `record_settlement_transfers(p_bundles jsonb)`**(현재 원본 486): 묶음에 `fee_jpy` 가 오면 그 값 + `fee_manual=true`, 없으면 현재 규칙으로 계산 + `fee_manual=false`. **어느 쪽이든 규칙 사본 3칸(`fee_rate_percent`·`fee_fixed_jpy`·`fee_rounding`)엔 현재 규칙**을 넣는다
- **건별 송금액 정정 `correct_settlement_payment`**(486): 묶음이 `fee_manual=false` 이고 사본 3칸이 다 있으면 **사본으로** 수수료를 다시 계산한다(설정 창의 지금 규칙이 아니라)
- **묶음 정정 `correct_settlement_transfer`**(현재 원본 502): 송금일·수수료 금액·거래번호·메모만. 요율 칸 없음. **수수료를 지금과 다른 값으로 바꾸면 `fee_manual=true`**(같은 값이면 추정 표시만 지우고 `fee_manual` 그대로 — 502)
- **시트 소급 `backfill_settlement_transfers_from_sheet`**(501): 시트 합산 탭의 실제 수수료 묶음은 `fee_manual=false` + 사본 3칸 비움
- **조회 `get_settlement_transfers`**(502): 사본 3칸 + `fee_rule_jpy`(사본으로 계산한 값) + `fee_manual` 을 준다. 화면 근거 줄 `_transferFeeNoteHtml`
- **규칙 표 `settlement_fee_rule`**(484): `rate_percent` 0~100, `fixed_jpy` 0 이상, `rounding` round/floor/ceil. 「수수료 설정」 창(`admin-settlements.js` 3591~)에서만 바꾼다 + 변경 이력 표

### 충돌 가능성 있는 기존 동작
- **「규칙 계산」 표시와의 관계**: 송금별 요율로 기록한 묶음은 `fee_manual=false` 이고 사본 = 그 송금의 요율 → `fee_rule_jpy` = 실제 수수료 → 「고친 값」·「차이」가 **안 나온다**. 그래서 「설정과 다른 요율」은 **따로 표시해야** 보인다(아래 설계 ① 칸·조회 + ② 송금 내역 표시)
- **시트 소급(501)**: 영향 없음 — 소급은 자체 수수료 규칙(추정 = 현재 규칙, 실제값 = 사본 비움)을 쓴다
- **도입일·옛 경로 거부**: 무관(출처 `app` 그대로)
- 그 밖 충돌 없음 — 확인 영역: 회차·월별 집계(수수료 값만 본다) · 엑셀(수수료·수수료 수정 열) · 인플루언서 알림(없음)

## 의심·경우의 수

1. 🔴 **(UX) 운영자가 「앞으로 모든 송금」을 바꾸려던 것인데 한 송금에만 넣는다** — 페이팔 요율이 실제로 오르면 설정 창에서 바꿔야 한다. → 요율 칸 옆에 안내 + 설정 창으로 가는 글 링크(설계 ②)
2. **(UX) 같은 날 여러 묶음에 같은 바뀐 요율을 반복 입력** — 확인 창에 묶음이 수십 개면 피로하다. → 단추는 두지 않는다(결정 4) — 설정 창 안내(경우의 수 1)로 대신한다
3. **(데이터) 「설정과 다르다」를 무엇과 비교하나** — **요율을 정하는 그 순간**의 설정 규칙과 비교해야 한다(나중에 설정이 바뀌면 옛 송금이 모두 「다름」으로 보이면 안 된다). → 서버가 **`fee_rule_custom boolean`** 을 세운다 — **기록 때는 기록 순간 설정**, **정정 창에서 체크 칸을 켜고 저장할 때는(값이 사본과 같아도) 정정 순간 설정**과 비교해 다르면 true. 🔴 **비교 대상은 요율·고정액 두 값뿐이고 끝수는 비교하지 않는다**(정정은 사본 끝수를 쓰므로 설정 끝수가 그 뒤 바뀌었으면 끝수만 달라진다 — 그걸 「이 송금만」으로 보이면 안 된다. 화면·엑셀도 요율·고정액만 보여 준다). 사본과 이력 표를 나중에 맞대는 방식은 시각 비교가 필요해 틀리기 쉽다
4. **(데이터) 끝수 처리도 바꾸나** — 요율·고정액만 바꾸고 끝수 처리는 사람이 고르지 않는다(사용자 제안 범위). 끝수 기준은 하나로 정한다 — **기록 = 기록 순간 설정 끝수**, **정정 = 그 묶음 사본 끝수(사본이 비었으면 정정 순간 설정 끝수)**. 정정이 사본 끝수를 쓰는 것은 그 송금이 실제로 계산된 방식을 유지하기 위해서다(설정 끝수가 그 뒤 바뀌어도 옛 송금 수수료가 흔들리지 않게). 페이팔이 다른 끝수로 뗀 경우는 금액 직접 입력(결정 2)으로
5. **(데이터) 건별 송금액 정정 뒤 다시 계산** — 수수료 금액을 고치지 않은 동안(`fee_manual=false`)은 사본이 그 송금의 요율이므로 정정 때 그 요율로 다시 계산된다(486 동작 그대로 — 원하는 결과). 수수료를 다른 금액으로 고친 뒤에는 꺼진다(설계 ②)
6. **(동시성) 미리보기와 저장 사이에 설정이 바뀜** — 송금별 요율을 넣은 묶음은 **요율·고정액만** 넣은 값이 이긴다. 끝수와 「설정과 다름」 판정은 경우의 수 3·4 의 기준대로 — **기록은 끝수·판정 모두 기록 순간 설정**(그 사이 끝수가 바뀌면 미리보기와 1엔 다를 수 있다 — 기록 값이 이긴다), **정정은 끝수 = 그 묶음 사본(미리보기도 같은 사본 끝수를 보내므로 어긋나지 않는다 — 단 사본이 빈 묶음(시트 실제값)은 미리보기·저장 모두 그 순간 설정 끝수라 그 사이 끝수가 바뀌면 기록과 같이 1엔 다를 수 있다, 저장 값이 이긴다), 판정 = 정정 순간 설정**. 확인 창에서 체크 칸을 켜지 않은 묶음(결정 6)은 요율을 보내지 않으므로 지금처럼 기록 순간 규칙. 정정 창에서 켜지 않으면 수수료를 다시 계산하지 않는다(수수료 금액을 직접 고치지 않는 한 그대로 — 설계 ②)
7. **(UX) 「자동으로」의 뜻** — 지금은 금액 입력을 지우고 설정 규칙으로 돌아간다. 요율 칸이 생기면 「자동으로」는 **체크 칸을 끄고 금액 입력도 지워** 셋 다 설정 규칙으로 되돌린다(결정 6)
8. **(입력 검증) 터무니없는 값** — 요율 0~100·고정액 0 이상(484 와 같은 범위)은 서버가 거부. 그 안이라도 요율 10% 초과면 화면에 경고 한 줄(설계 ②)

### 의도와 다르게 읽힐 수 있는 곳
- 「요율 지정」은 **기록할 때**(확인 창)와 **기록 뒤**(정정 창, 결정 5) 둘 다다
- 「설정과 다른 요율」은 **경고가 아니라 근거 표시**다(그 송금이 그렇게 정해졌다는 사실)

## 설계

### ① 데이터베이스 — 마이그레이션 5개(번호는 개발이 만들 때 정한다. (가)가 먼저)
- **(가) 칸** — `settlement_transfers.fee_rule_custom boolean NOT NULL DEFAULT false`(기존 행 false)
- **(나) 기록 재정의** — `record_settlement_transfers`(베이스 **486**, 인자 그대로 → `CREATE OR REPLACE`, 권한 보존). 묶음 입력에 선택 칸 `fee_rate_percent`·`fee_fixed_jpy`:
  - 둘 다 오면 그 값 + 설정의 끝수로 `_settlement_fee_calc` → `fee_jpy`, 사본 3칸 = (그 요율, 그 고정액, 설정 끝수), `fee_manual=false`, `fee_rule_custom` = (그 요율·고정액이 설정과 다른가 — 끝수는 비교하지 않는다, 경우의 수 3)
  - 하나만 오면 거부(`bundle_fee_rule_incomplete`) · 범위 밖이면 거부(`bundle_fee_rule_invalid`)
  - `fee_jpy`(금액)와 요율이 **함께 오면 거부**(`bundle_fee_conflict`) — 화면은 둘 중 하나만 보낸다
  - 🔴 486 의 나머지(도입일·잠금·페이팔·검사 순서) 그대로
- **(다) 미리보기 재정의** — `preview_settlement_fees`: 입력을 `p_totals bigint[]` 와 같은 길이의 선택 배열 `p_rates numeric[]`·`p_fixeds integer[]`·`p_roundings text[]`(NULL 원소 = 설정 규칙)로. `p_roundings` 는 **정정 창 미리보기**가 그 묶음의 사본 끝수를 보내 (마)와 같은 값을 보이게 하려는 것이다(확인 창은 보내지 않는다 — 기록은 설정 끝수). 범위 밖 끝수 값은 거부(`bundle_fee_rule_invalid`). 🔴 서명이 바뀌므로 **`DROP` 후 `CREATE` + 실행 권한 3줄 재설정**(488 과 같은 대상). 반환에 묶음별 `custom` 표시 추가(요율·고정액만 비교 — 끝수는 비교하지 않는다, 경우의 수 3)
- **(라) 조회** — `get_settlement_transfers`(베이스 502)에 `fee_rule_custom` 칸 추가 → `DROP` 후 `CREATE` + 실행 권한 3줄 재설정(502 와 같은 대상 — `PUBLIC`·`anon` 회수, `authenticated` 부여)
- **(마) 정정 재정의** — `correct_settlement_transfer`(베이스 **502**). 선택 인자 `p_fee_rate_percent numeric`·`p_fee_fixed_jpy integer` 추가 → 🔴 서명이 바뀌므로 **`DROP` 후 `CREATE` + 실행 권한 3줄 재설정**(502 와 같은 대상). 502 의 나머지(잠금·버전 충돌 −1·추정 표시 해제·같은 수수료면 `fee_manual` 그대로·건별 `paid_at` 따라가기) 그대로
  - 요율·고정액이 둘 다 오면: 끝수는 **그 묶음의 사본 끝수**(사본이 비었으면 그 순간 설정 끝수)로 `_settlement_fee_calc(그 묶음 보낸 금액 합계, …)` → `fee_jpy`, 사본 3칸 = (그 요율, 그 고정액, 그 끝수), `fee_manual=false`, `fee_estimated=false`, `fee_rule_custom` = (그 요율·고정액이 **정정 순간의 설정**과 다른가 — 끝수는 비교하지 않는다, 경우의 수 3)
  - 하나만 오면 `bundle_fee_rule_incomplete` · 수수료 금액과 함께 오면 `bundle_fee_conflict` · 범위 밖이면 `bundle_fee_rule_invalid`(기록과 같은 코드)
  - 정정 이력(`settlement_transfer_events`)의 prev/next 에 사본 3칸·`fee_rule_custom` 을 남긴다
  - storage.js 래퍼 `correctSettlementTransfer` 에 인자 둘 추가(기존 호출은 넘기지 않으면 그대로)

### ② 화면 `dev/js/admin-settlements.js`
- **확인 창 「수정」** → 묶음 아래에 체크 칸 「이 송금 요율 직접 정하기」(기본 꺼짐 — 결정 6) + 그 아래 「요율(%)」·「고정액(엔)」(처음 값 = 설정 규칙, 체크 칸을 켜야 입력 가능) · 「또는 수수료 직접 입력」. 체크 칸을 켠 동안 요율·고정액을 바꾸면 미리보기를 다시 물어 수수료·총지출이 바뀐다. **체크 칸이 켜져 있을 때만** 요율·고정액을 보낸다(설정과 같은 값이어도) — 꺼져 있으면 보내지 않아 기록 순간 규칙으로 계산된다(경우의 수 6). 체크 칸을 끄면 요율 칸이 설정 규칙으로, 수수료·총지출이 설정 규칙 미리보기로 돌아간다(저장될 값과 화면 값이 어긋나지 않게). 🔴 **체크 칸과 금액 직접 입력은 양방향으로 배타**다 — 체크 칸을 켜면 금액 칸이 잠기고(입력값은 비우고 미리보기 값만 보여 준다) 금액을 보내지 않는다. 금액 칸에 값을 넣었으면 체크 칸을 켤 수 없다(꺼진 채 흐리게). 잠기거나 흐린 칸의 값은 보내지 않는다(서버의 `bundle_fee_conflict` 는 화면을 우회한 호출의 방어선)
  - 요율 칸 옆 안내: 「이 송금에만 적용됩니다. 앞으로의 모든 송금은 「수수료 설정」에서 바꿉니다」 + 「수수료 설정」 글 링크(설정 창을 연다 — 경우의 수 1)
  - 요율이 10% 를 넘으면 칸 아래 경고 한 줄 「요율이 10%를 넘습니다. 맞는지 확인해 주세요」(막지는 않는다 — 경우의 수 8)

- **정정 창**(`openTransferCorrectModal`): 수수료 칸 아래 체크 칸 「이 송금 요율 직접 정하기」(기본 꺼짐 — 결정 6) + 「요율(%)」·「고정액(엔)」(처음 값 = 그 송금의 사본, 비었으면 설정 규칙, 체크 칸을 켜야 입력 가능). 체크 칸을 켜면 수수료 칸이 서버 미리보기 값으로 바뀌어 보이고 — 미리보기에 **그 묶음의 사본 끝수**(`p_roundings`, 비었으면 NULL)를 함께 보내 저장 값과 같게 한다 — (수수료 칸은 잠긴다 — 아래 배타 규칙), 저장 때 요율·고정액만 보낸다. 🔴 **체크 칸이 켜져 있을 때만 보낸다**(값이 처음 값·설정과 같아도 — 사본이 빈 시트 실제값 묶음에 설정 요율을 근거로 남길 수 있게). **꺼져 있으면 요율·고정액을 보내지 않는다 — 수수료 금액도 고치지 않았다면** 수수료·`fee_manual`·`fee_rule_custom`·사본은 그대로다(수수료 금액을 다른 값으로 고치면 502 대로 바뀌고 `fee_manual=true` — 결정 2)(그래야 송금일만 고치려던 정정이 직접 고친 수수료를 덮거나, 설정이 바뀐 뒤의 평범한 송금을 「이 송금만」으로 바꾸지 않는다 — 완료 기준 6·9). **체크 칸을 끄면** 요율 칸과 수수료 칸이 창을 열었을 때 값으로 돌아가고 수수료 칸 잠금이 풀린다(미리보기 값이 수수료 금액 정정으로 새어 나가지 않게). 🔴 **체크 칸과 금액 직접 입력은 양방향으로 배타**다 — 체크 칸을 켜면 금액 칸이 잠기고(입력값은 비우고 미리보기 값만 보여 준다) 금액을 보내지 않는다. 금액 칸에 값을 넣었으면 체크 칸을 켤 수 없다(꺼진 채 흐리게). 잠기거나 흐린 칸의 값은 보내지 않는다(서버의 `bundle_fee_conflict` 는 화면을 우회한 호출의 방어선). 같은 안내 문구·설정 링크·10% 경고
- **송금 내역** 수수료 아래 줄 — 🔴 **「고친 값」(`fee_manual`)이 우선**한다:
  - `fee_manual` 이면 지금의 「고친 값 · 규칙 계산 ¥A · 차이 ±¥B」 그대로(**사본이 비어 있으면** — 시트 실제값 묶음을 정정한 경우 — 비교할 규칙이 없어 「고친 값」만). 규칙 계산값은 사본으로 계산되므로 `fee_rule_custom` 인 송금이면 **그 송금 요율로 계산한 값**이다 — 그 경우 줄 끝에 「(이 송금 요율 4.4% + ¥50)」를 붙인다(요율 칸에 설정과 같은 값을 넣고 기록했으면 `fee_rule_custom=false` 라 덧붙이지 않는다)
  - `fee_manual` 이 아니고 `fee_rule_custom` 이면 「요율 4.4% + ¥50(이 송금만)」
  - ⚠️ `fee_rule_custom` 인 송금의 수수료를 **다른 금액으로** 정정하면(502 가 `fee_manual` 을 켠다 — 같은 값이면 그대로) 486 규칙대로 **이후 건별 송금액 정정 때 자동 재계산이 꺼진다**(고친 값은 사람이 정한 값). `fee_rule_custom` 은 **마지막으로 요율을 정한 순간(체크 칸을 켜고 기록 또는 정정 저장 — 값이 같아도)의 사실**이라 수수료 금액 정정으로는 내리지도 올리지도 않는다(바뀌는 것은 체크 칸을 켜고 기록·저장할 때뿐 — 값이 같아도)
- **엑셀**: 「수수료 요율」·「수수료 고정액」 두 열 — 사본 값. 판정 순서: ①`fee_manual` 이면 아래 「직접 입력」(시트 실제값 묶음을 다른 금액으로 정정한 경우도 여기) ②사본이 비어 있으면 「시트 실제값」(정정 안 한 시트 실제값 묶음 — 501 은 `fee_manual=false`) ③그 밖은 사본 값. 🔴 **수수료 금액을 직접 입력·정정한 송금(`fee_manual`)은 두 열에 「직접 입력」**(사본엔 **마지막으로 요율을 정한 순간(체크 칸을 켜고 기록 또는 정정 저장 — 값이 같아도)의 규칙** — 설정 규칙 또는 이 송금 요율 — 이 들어 있지만 그 수수료는 그 요율로 계산된 것이 아니다. 수수료 금액 정정으로는 사본이 안 바뀐다). 그중 `fee_rule_custom` 인 송금은 「직접 입력(이 송금 요율 4.4% + ¥50)」으로 화면과 같은 근거를 남긴다

## 완료 기준
1. 확인 창에서 체크 칸 「이 송금 요율 직접 정하기」를 켜고 요율·고정액을 바꾸면 수수료가 서버 계산으로 바뀌어 보이고(화면에 식 없음), 기록된 묶음의 사본 = 넣은 요율·고정액, `fee_manual=false`, 설정과 다르면 `fee_rule_custom=true`. 체크 칸을 켜지 않은 묶음은 요율을 보내지 않아 기록 순간 규칙으로 계산된다
2. 수수료 금액을 고치지 않은 동안(`fee_manual=false`) 그 묶음의 건별 송금액을 정정하면 **넣은 요율로** 수수료가 다시 계산된다
3. 수수료 금액 직접 입력은 지금처럼 「고친 값」 + 「규칙 계산 · 차이」. `fee_rule_custom` 인 송금의 수수료를 다른 금액으로 정정해도 「고친 값」이 우선하고 끝에 「(이 송금 요율 …)」
4. 요율과 수수료 금액을 함께 보내거나, 요율·고정액 중 하나만 보내거나, 범위 밖이면 서버가 거부하고 아무것도 안 쓴다(수수료 금액만 보내는 것은 정상 — 결정 2)
5. 송금 내역에 「요율 … (이 송금만)」이 보이고 엑셀 두 열(판정 순서대로 — 직접 입력(`fee_rule_custom` 인 송금은 「직접 입력(이 송금 요율 …)」) · 시트 실제값 · 그 밖은 사본 값) · 확인 창의 설정 링크·10% 경고
6. 설정 창 규칙을 나중에 바꿔도 옛 송금의 「이 송금만」 표시가 바뀌지 않는다
7. 도입일·옛 경로 거부·시트 소급 동작이 그대로
8. 확인 창 「자동으로」는 체크 칸을 끄고 금액 입력도 지워 요율·고정액·금액 셋 다 설정 규칙으로 되돌린다
9. 정정 창에서 체크 칸을 켜고 저장하면(값이 사본과 같아도) 수수료가 그 요율·고정액으로 다시 계산되고 사본·`fee_manual=false`·`fee_rule_custom`(정정 순간 설정 기준)이 저장되며 이력에 옛 값이 남는다. 정정 창 미리보기 수수료 = 저장된 수수료(사본 끝수 기준 — 사본이 빈 묶음은 그 사이 설정 끝수가 바뀌면 1엔 다를 수 있다, 경우의 수 6). 함께 보내기·하나만·범위 밖은 기록과 같은 코드로 거부. **체크 칸을 켜지 않고**(또는 켰다가 끄고) 송금일 등만 정정하면 수수료·`fee_manual`·`fee_rule_custom`·사본이 바뀌지 않는다. 사본이 빈 묶음에 체크 칸을 켜고 설정과 같은 요율로 저장하면 사본이 채워지고 `fee_rule_custom=false`. 사본이 있는 묶음에 값을 그대로 두고 체크 칸만 켜 저장하면 그 요율로 수수료가 다시 계산되고(직접 고친 수수료도 덮인다 — `fee_manual=false`) `fee_rule_custom` 은 정정 순간 설정 기준으로 다시 판정된다. 체크 칸과 수수료 금액 입력은 한쪽만 켜진다
