# 관리자의 회원 배송지·전화번호 대리 수정 (한국 거주 회원 대응 포함)

**작성일:** 2026-10-22 · **작성:** 기획 세션

## 배경

한국에 사는 일본인 인플루언서가 「주소 입력에서 일본 도도부현만 고를 수 있어 한국 주소를 넣을 수 없다」고 가끔 문의한다. 극소수라 **회원이 직접 한국 주소를 고르는 기능은 만들지 않고**, 운영팀에 요청한 회원만 관리자가 대신 고친다(2026-10-22 사용자 결정).

## 현재 상태 (2026-10-22, `origin/dev` 기준)

### 관련 코드·DB·UI 진입점
- **주소 입력 위치**: 가입 때는 받지 않는다. 마이페이지 프로필(`dev/index.html:1238-1251`) — 우편번호(`profileZip`, 일본 우편번호 검색 `lookupZipProfile` → zipcloud, `ui.js:729`) · 도도부현(`profilePrefecture`, 47개 `<select>`) · 시구정촌·번지(`profileCity`) · 건물명(`profileBuilding`).
- **저장**: `saveProfile`(`mypage.js:549`)이 프로필 **전체 칸을 한 번에** `updateInfluencer` 로 저장하고, 합친 주소 문장 `address = 〒{zip} {pref}{city} {building}` 도 이 순간에만 만든다.
- **응모 전 필수 검사**: 우편번호·도도부현·시구정촌·전화번호가 비면 응모 막음(`application.js:1348-1351`).
- **응모 배송지 복사본**: 응모 창 배송지 칸 `applyAddress` 를 프로필 `address` 로 미리 채우고(`application.js:876`, 자유 입력 칸) `applications.address` 에 저장(`:1089`). 프로필을 나중에 고쳐도 기존 응모의 배송지는 그대로다.
- **배송지를 읽는 자리**: 배송 리스트(557 — 개발서버만)는 `applications.address` 에서 `^〒\s*([0-9０-９\-－]{7,8})\s+` 로 우편번호를 떼어 낸다(`557:185`) · 신청자 엑셀(`admin-excel.js`) · 관리자 회원 상세(`admin-influencers.js:416-422`).
- **관리자 회원 상세는 읽기 전용**(`openInfluencerDetail`, `admin-influencers.js:362`). 마이그레이션 313이 관리자의 `influencers` 직접 수정을 막았다(본인 행만 수정 가능) → 관리자 수정은 **정의자 권한 서버 함수**가 필요하다(상태 변경 함수 059~062 와 같은 방식).
- **민감정보 가림**: `influencers_admin_view`(212·312)가 `has_permission('influencer.sensitive_pii','read')` 가 거짓인 등급에게 전화·우편번호·건물·상세주소를 비운다. 캠페인 매니저는 213 에서 「숨김」.
- **도도부현 밖 값**: `classifyPrefecture`(`admin-core.js:750`)가 47개 목록 밖의 값을 「海外(해외)」로 분류해 목록 필터에 쓴다. 일괄 메시지 지역 필터(389)는 `i.prefecture = ANY(...)` 로만 본다.
- **탈퇴 파기**: `purge_withdrawn_personal_data` 현재 원본 **520** — `influencers` 의 전화·우편번호 등을 비운다.
- **전화번호 표시** `formatPhoneDisplay`(`ui.js`)는 한·일 번호를 모두 정규화한다.
- 🔴 **개인정보처리방침** `docs/PRIVACY_ja.md:134` 「会員は日本居住者を前提とします」(회원은 일본 거주자를 전제로 합니다) — 한국어판도 같은 취지.

### 이 제안과 충돌 가능성 있는 기존 동작
1. **마이페이지 저장이 한국 주소를 지운다** — 도도부현 `<select>` 에 「韓国(한국)」이 없으면 화면에 빈칸으로 보이고, 회원이 다른 칸만 고쳐 저장해도 `prefecture` 가 빈 값으로 덮인다(`mypage.js:553`). → 설계 ③ 으로 막는다.
2. **관리자가 칸만 고치면 응모 창이 옛 주소로 채워진다** — 합친 문장 `address` 를 서버 함수가 함께 다시 만들어야 한다.
3. **배송 리스트 우편번호 떼어 내기가 한국 우편번호(5자리)에 안 맞는다** — 한국 주소는 우편번호가 따로 안 나오고 주소 칸에 통째로 남는다(설계 ④).
4. 방침의 「일본 거주자 전제」 — 결정 8 로 고친다.

### 미해결 백로그·관련 작업
- 관리자 개인정보 열람 기록(552, `recordAdminDataAccess` — 개발서버만)이 있다. 이번 수정도 같은 표에 남길지는 개발 대조 때 판단(아래 「착수 전 알아야 할 것」).

## 의심·경우의 수

1. **(UX) 회원이 모르게 주소가 덮인다** — 위 충돌 1. 읽기 전용 표시로 막는다(결정 4).
2. **(UX) 이미 당선된 응모의 배송지가 옛 주소로 남는다** — 수정 창에서 진행 중 응모를 골라 함께 바꾼다(결정 3).
3. **(보안) 남이 회원인 척 주소 변경을 요청** — 사유 필수 + 회원 이메일로 확인 메일(결정 6). 문의 대화 연결은 선택(근거가 메일·LINE 일 수 있다). 🔴 **사후 통지라 발송 전 차단은 못 한다** — 진행 중 응모 배송지도 바뀌므로 회원이 메일을 보기 전에 상품이 나갈 수 있다(「알려진 미해결」 본인 확인).
4. **(권한) 보이지 않는 값을 고치는 등급** — 수정은 결정 5 의 조건(새 항목 「쓰기」 + 민감정보 열람)이 있어야 한다. 하나만 켜면 버튼이 안 보이고 서버도 거부한다.
5. **(데이터) 이력 표가 개인정보 사본이 된다** — 탈퇴 파기 함수에 이력 비우기 추가(결정 7).
6. **(데이터) 탈퇴 진행 중·확정 회원** — 확정 회원은 수정 거부(차단 장치 `account_withdrawn` 과 같은 방향).
7. **(동시성) 회원이 마이페이지에서 저장하는 순간 관리자도 저장** — 나중 저장이 이긴다. 관리자 창은 열 때 값과 저장 직전 값을 대조해 다르면 「회원이 방금 바꿨습니다」로 거부(`stale`).
8. **(의도 모호) 「진행 중 응모」의 범위** — 이번 사양은 `pending`·`approved` 이고 캠페인이 끝나지(`closed`) 않은 응모로 정한다. 배송 완료 여부는 지금 운영 데이터에 없다(배송 리스트는 개발서버만) → 이미 발송된 건도 목록에 뜰 수 있어 관리자가 체크로 고른다.

## 설계

### ① 데이터베이스 (마이그레이션 — 번호는 개발이 정한다)
마이그레이션 4개 — 순서대로:
1. **수정 이력 표** — 회원·관리자·시각·사유·근거 문의 대화(선택)·바뀐 칸별 전·후 값·함께 바꾼 응모 목록(응모별 전·후 배송지)·**메일 상태 칸**(대기/선점 시각/보냄/실패). 행 단위 보안 정책은 **읽기만** 결정 5 의 조건을 갖춘 관리자, 쓰기는 서버 함수만.
2. **관리자 수정 함수** — 입력: 회원, 새 값, 열 때 값(`p_prev`), 사유, 근거 대화, 함께 바꿀 응모 목록. 하는 일: 권한 확인(새 항목 쓰기 **그리고** `influencer.sensitive_pii` 읽기) → 탈퇴 확정이면 거부 → `p_prev` 대조(`stale`) → `influencers` 의 칸들과 **합친 문장 `address`** 를 다시 만든다 → 고른 응모의 `applications.address` 를 바꾼다(그 회원의 응모인지·진행 중인지 서버가 다시 확인) → 이력 한 줄(메일 상태 「대기」) → 이력 번호 반환. 같은 마이그레이션에 서비스 키 전용 **메일 선점·결과 보고 함수**(⑤ 가 부른다). 권한 카탈로그 새 항목(`influencer.contact_edit` 가칭) 시드 3행.
   - 한국 주소 저장 칸: `zip`=5자리 우편번호 · `prefecture`=`韓国` · `city`=주소 · `building`=건물명. 합친 문장은 `〒` 없이 `韓国 {우편번호} {주소}{건물}`. (`classifyPrefecture` 가 「海外」로 셈 — 필터 그대로 동작)
   - 🔴 서버도 값 형식을 검사한다: 일본이면 47개 도도부현 + 7자리 우편번호, 한국이면 5자리 우편번호.
3. **진행 중 응모 조회 함수** — 수정 창이 띄울 목록(응모·캠페인 이름·상태·현재 배송지). 권한 확인은 ①2 와 같다(결정 5 의 조건, 없으면 거부).
4. **탈퇴 파기 함수 재정의** — 520 베이스, 결정 7 의 값을 비운다(행은 남김 — 「언제 누가 어느 칸을 고쳤나」만).

### ② 관리자 화면 (`admin-influencers.js` 회원 상세)
- 배송지 카드에 「수정」 버튼 — 결정 5 의 조건을 갖춘 등급에게만 보인다.
- 수정 창(동적 모달): 국가 선택(일본/한국) → 일본이면 지금과 같은 칸(우편번호 검색 포함), 한국이면 우편번호·주소·건물명 / 전화번호 / **사유(필수)** / 근거 문의 대화(선택 — 그 회원의 일반 문의 목록) / 진행 중 응모 체크 목록(기본 전부 해제) / 저장 전 확인(바뀌는 칸·응모 수 요약).
- 저장 뒤 `refreshPane` 으로 목록·상세 갱신. 상세 맨 아래 「상태 관리」 카드를 **「회원 관련 이력 관리」**로 바꾼다 — 인증·위반 관리는 그대로 두고, 그 아래 이력 목록에 인증·위반·블랙 기록과 배송지·전화번호 수정 기록을 **시간순(최근 순)으로 합쳐** 보여 준다. 종류 필터(전체 / 상태 / 배송지·전화번호). 배송지·전화번호 줄은 결정 5 의 조건을 갖춘 등급에게만 — **서버가 그 조건 없이는 주지 않고**, 건수·필터에서도 빠진다. 그 줄에서 메일이 「대기」·「실패」이거나 선점 뒤 15분이 지난 줄에는 「확인 메일 다시 보내기」(창을 닫거나 통신이 끊겨 메일이 안 나간 경우).

### ③ 회원 화면 (`mypage.js`)
- 도도부현이 `韓国` 일 때(빈 값 = 미등록과 그 밖의 값은 지금처럼 입력 칸) 주소 칸들을 **글로 보여 주고** 안내 「住所の変更はお問い合わせください」(주소 변경은 문의해 주세요) + 문의 창구 링크 + 「日本の住所に変更する」(일본 주소로 바꾸기) 버튼. 버튼을 누르면 빈 일본 주소 칸이 열린다.
- 🔴 읽기 전용 상태에서는 `saveProfile` 이 주소 칸을 **저장 내용에서 뺀다**(다른 칸 저장이 주소를 덮지 않게).
- 응모 전 필수 검사는 그대로 통과한다(우편번호·도도부현·시구정촌 값이 있다).

### ④ 배송 리스트·엑셀
- 한국 주소는 `〒` 가 없어 우편번호가 따로 안 떼어지고 주소 칸에 통째로 나간다. 이번 범위에서는 **그대로 둔다**(극소수, 운영팀이 눈으로 확인). 국가 표시 열을 늘리지 않는다.

### ⑤ 확인 메일
- 새 서버 함수(가칭 `notify-member-contact-changed`) — 관리자 화면이 저장 성공 뒤(또는 「다시 보내기」로) 이력 번호로 부른다. 호출자 토큰으로 결정 5 의 조건을 확인하고(없으면 거부), 이력 줄의 메일 상태를 선점하고(「대기」·「실패」이거나 선점 뒤 15분이 지난 줄만 — ② 버튼 조건과 같은 집합) 받는 사람·내용을 서버에서 정한다(브라우저가 보낸 주소를 믿지 않는다). 결과 보고는 선점 시각을 대조한다(어긋나면 무시). 이미 「보냄」이면 다시 안 보낸다 — 단 보낸 뒤 보고 전에 끊기면 15분 뒤 두 번째 메일이 나갈 수 있다(받아들임: 같은 안내가 한 번 더 갈 뿐 정보는 새지 않는다).
- 본문(일본어): 「登録住所・電話番号が運営事務局により変更されました」(등록 주소·전화번호가 운영 사무국에 의해 변경되었습니다) + 변경 일시 + 「お心当たりがない場合はお問い合わせください」(짐작 가는 바가 없으면 문의해 주세요). 🔴 **새 주소·전화번호 값은 메일에 싣지 않는다**(메일이 남에게 가도 정보가 새지 않게 — 조사 자료 예시와 다르게 한 이유). 인플루언서 메일 **4줄 푸터 필수**.
- 양식은 `docs/email-templates/` 가 정본 → 동기화 스크립트.
- 개발서버는 실제로 보내지 않고 응답에 본문만 싣는 두 겹 잠금(다른 브랜드 메일 함수와 같은 방식).

## 착수 전 알아야 할 것 (개발 대조용)
- 결정 8 문안 — 한국어: 「회원은 원칙적으로 일본 거주자를 대상으로 하며, 회원의 요청에 따라 운영팀이 일본 외 지역(한국 등)의 배송지를 등록하는 경우가 있습니다.」 / 일본어: `会員は原則として日本居住者を対象としますが、会員のご依頼により、運営チームが日本国外（韓国など）の配送先を登録する場合があります。` · 이름표 일본어 `（日本国外の住所は郵便番号・住所）`. §5 이전 표는 그대로(한국 개인정보 보호법 공개 형식을 이미 갖춤). 부칙에 개정 줄 추가. ⚠️ 같은 문단의 「이용 시 동의한 것으로 간주」(간주 동의)는 이번 범위 밖 — 별도 과제.
- 결과물 대리 등록·영수증 수정처럼 「관리자가 회원 데이터를 고치는」 기존 함수(`admin_create_deliverable_proxy` 511, `update_receipt_admin`)의 권한 확인·이력 방식을 먼저 볼 것.
- 관리자 개인정보 기록(552)에 수정도 남길지 — 동작 종류 검사 제약 현재 원본은 **584**.
- 이름 전파 점검: `influencers` 의 `prefecture`·`zip`·`address`·`phone` 을 읽는 자리를 세 형태(그대로·변수·조회문 안쪽)로 전수 — 한국 값(`韓国`, 5자리 우편번호)을 받았을 때 깨지는 자리가 없는지.
