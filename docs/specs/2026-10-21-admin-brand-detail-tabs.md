> **출시:** 브랜드 페이지 1차와 **같은 날** 운영에 낸다(2026-10-21 사용자 결정 — `2026-07-15-brand-portal.md` §16-5 6번). 피그마의 「먼저 따로 출시 가능」 꼬리표는 이제 판단 자료일 뿐이고 먼저 내보내는 화면은 없다.

> - **출시 전 보호:** 새 페이지는 새 파일에 만들고 `_brandAccountEnabled()`(개발서버) 판정 한 줄로만 연다 — 운영은 출시 날까지 지금 페이지. 출시 뒤 옛 경로 정리 조각이 따로 있다

> - 서버의 「브랜드 계정 즉시 재연결」 갈래(533 `admin_upsert_brand_owner_account`)는 닫아 `conflict_brand` 로 돌려준다 — 화면은 a03-01c 로 간다
> - 같은 날 오전 다른 세션이 만든 같은 기능 작업표와 **합쳤다** — 정본은 위 작업표, 연결 요청 인계는 `docs/specs/2026-10-21-brand-link-request-handoff.md`. 회사 모달의 「브랜드 N개」는 활성 브랜드만(브랜드 화면과 같은 기준)
> - 떠날 때 확인(4-9): 떠나는 **길은 일곱**(작업표 M2)이고, 그 길들을 코드가 가로채는 **자리는 넷**으로 묶인다(작업표 조각 6). 「한 곳」은 틀린 표현이고, 뒤로가기는 주소가 이미 바뀐 뒤라 「머물기」면 주소를 되돌린다(작업표 조각 6)

## 1. 범위

**넣는 것**
- 브랜드 상세 페이지를 탭 4개(브랜드 정보 · 담당자·계정 · 오리엔시트 · 캠페인) + 오른쪽 영업 메모로 다시 짠다 (a03-00d·00·00a·00b·00c·00e·00f·09·10·13·90a·93)
- 담당자 줄 단위 저장 모달 (a03-08·08a~08e)
- 회사 정보 바로 고치기 모달 (a03-07·07a·07b)
- 브랜드 페이지 계정 동작 전부 (a03-01·01a·01b·01c · 02·02a·02b · 03·03a · 04·04a · 05·05a·05b · 90 · 91·91a · 92) — 서버 함수는 대부분 개발서버에 이미 있다(533)
- 저장 충돌 확인 (a03-10) — 서버 저장 함수 새로
- 권한 항목 「브랜드 페이지 계정 관리」(`brand.account_manage`)를 권한 관리 화면 목록에 등록

**빼는 것**
- 🚫 **계정 이용 제한·결과물 열람 정지**(a03-11·12·94) — 서버가 아직 없는 별도 기능이라 **따로 사양서**를 쓴다(2026-10-21 사용자 결정). 브랜드 결과물 작업표 「4c 보류」와 같은 기능. 이 문서에서는 머리 「…」 메뉴에 그 항목을 넣지 않고, 계정 줄 「…」는 그리지 않는다 — 별도 사양서가 더한다(아래 4-0·4-3)
- 🚫 로그인 이메일 바꾸기(a03-06, §16-5 5번 — 1차에 넣지 않음)
- 🚫 관리자의 대기 초대 대신 취소(§16-7 — 만들지 않음)
- 🚫 「새 브랜드」 등록 모달의 탭·저장 방식 변경 — 지금처럼 모달 하나에서 담당자 여러 줄을 함께 넣어 한 번에 등록한다. 단 같은 그리기 함수를 쓰므로 D14(세 칸 빼기)는 모달에도 적용되고, 그 밖에는 **깨지지 않게만** 한다(6절 ⑨)

  - ⚠️ `CLAUDE.md`·`.claude/rules/brand-admin.md` 의 「브랜드 상세 모달」은 옛 이름이다(개발 세션이 이번 작업 문서 커밋에서 고친다).
- 본문 = 2열(왼쪽 폼 · 오른쪽 영업 메모 `#brandMemoPanel`). 왼쪽은 절 다섯이 이어진다: 기본 정보 → 담당자(`#brandContactsWrap` + 개발서버만 계정 줄 `#brandAccountStatusRow`) → 브랜드 콘텐츠(소개·어필·Qoo10·Instagram·X) → 브랜드 공개 기본 열(개발서버만) → 맨 아래 탭 둘(오리엔시트/캠페인, `setBrandDetailTab`).
- 머리(sticky): 돌아가기(들어온 곳마다 글자·목적지가 다름 — `BRAND_DETAIL_BACK`) · 제목 · 상태 드롭다운 · 삭제 · 병합 · 「제공 기록」(최고 관리자 + 개발서버) · 「오리엔시트 발급」 · **「저장」**.
- 들어오는 곳 다섯: 브랜드 목록 · 서베이 목록 · 운영 현황 「브랜드 정보」 · 오리엔시트 발급 창 계정 경고(`osGoBrandAccount`) · 배송 탭 「브랜드 상세 열기」.
- **저장 안 한 변경 경고 없음.** 캠페인 진행현황으로 건너갈 때 confirm 하나뿐(`brandDetailOpenCampProgress`) — ⚠️ 이 함수는 `closeBrandDetailModal()` 을 불러 `_brandsCurrentId` 를 비운다.

### 저장
- `saveBrandDetail` → `_collectBrandFormPatch` → `updateBrand`(`storage.js`, `from('brands').update(patch)` 직접). **판 번호·충돌 판정 없음**, **`contacts` 통째**, 소개·어필·Qoo10 포함.
- 저장 뒤 `_brandAccountAfterBrandSave` 가 대표 줄이 바뀌었으면 `admin_upsert_brand_owner_account` + 설정 메일을 **자동으로** 부른다(임시 구현).
- 공개 기본 열은 칸 안 「기본 열 저장」 → `admin_set_brand_publish_default_brand`(544). 규칙 `brand-account.md` 가 「`saveBrandDetail` 에 넣지 않는다」로 적고 있다 — **D3 로 뒤집힌다**.

### 계정 쪽 관리자 화면
- 대표 계정 줄 한 줄뿐(`renderBrandAccountRow`). 상태 넷(계정 없음·메일 대기·메일 보냄·설정 완료) + 조회 실패 「확인 불가」. 판정은 역할 하드코딩 `isCampaignAdminOrAbove`.
- 서버(533, 개발서버만)에 있지만 화면이 **안 부르는 것**: `admin_check_brand_account_email` · `admin_link_brand_owner_account` · `admin_release_brand_account` · `admin_set_brand_member_limit` · `admin_change_brand_owner`, 그리고 `admin_get_brand_account_status` 의 533 확장 칸(`members[]`·`member_limit`·`seat_used`·`pending_invite_count`·`release_cancel_count`·`can_manage`·`last_active_at`).
- 🔴 권한 항목 `brand.account_manage` 는 서버(530 시드 · 533 가드 · `notify-brand-account-setup`)에만 있고 **화면 권한 목록(`ADMIN_PERMISSION_CATALOG`, `dev/lib/shared.js`)에 없다** — 권한 관리 화면에서 못 바꾼다.
- 겹침 확인 함수(533)는 `email_kind` 와 함께 **인플루언서 한자 이름·관리자 이름을 관리자 누구에게나** 돌려준다 → D6 으로 고친다.

### 회사
- 브랜드 상세 안 회사 칸 = 드롭다운 + 읽기 전용 요약 카드(「회사 관리에서 수정합니다」). **「수정」 없음.**
- 🔴 `openCompanyModal`(`dev/js/admin-company.js`)은 회사를 「회사 관리」 화면의 목록 보관값(`_companiesCache`)에서 찾는다 — 그 화면을 안 열었으면 빈 폼인데 수정 대상 아이디는 잡혀 있어, **저장하면 기존 회사를 빈 값으로 덮는다.** `onSaved` 콜백은 새 회사 등록 전용.
- 권한: `canEditCompanies()`(역할 하드코딩). 카탈로그의 `company.cud` 는 화면이 안 쓴다.

### 서버의 이력·충돌 재료
- `brand_profile_history`(536) — 브랜드·회사 표 트리거가 관리자 저장·브랜드 저장 **모두** 칸 단위로 남긴다(누가·언제·옛 값·새 값). a03-10 의 「바뀐 칸·누가·언제」는 여기서 읽는다.

## 4. 설계

### 4-0. 페이지 틀
- 머리: 「← 목록」 · 브랜드명 · 번호 칩 · 상태 배지(표시만) / 요약 한 줄 「회사 ○○ · 대표 담당자 ○○ (브랜드 페이지 사용 중) · 멤버 n / m명 · 초대 대기 k 포함」 / 오른쪽 「병합」 · 「오리엔시트 발급」 · 「…」.
  - 요약 줄의 숫자는 서버 값 그대로 — 「n / m」 = `seat_used` / `member_limit`, 「초대 대기 k 포함」 = `pending_invite_count`(0이면 그 구절을 뺀다). 계정 기능이 꺼진 환경·조회 실패면 멤버 구절을 통째로 뺀다(0으로 그리지 않는다).
  - ⚠️ 피그마 캠페인 탭 그림(186:602)만 「번호 칩 → 브랜드명」 순서다 — 다른 그림을 따른다.
- 탭 줄: 「브랜드 정보 / 담당자·계정 (n) / 오리엔시트 (n) / 캠페인 (n)」. 저장 안 한 변경이 있으면 「브랜드 정보」 옆에 점.
  - 🔴 탭 전환은 **형제 영역의 표시만 바꾼다** — 특히 **브랜드 정보 탭 영역은 탭 전환으로 다시 그리지 않는다**(편집 폼이라 다시 그리면 값이 사라진다. `brand-admin.md`). 다른 세 탭은 자기 영역만 다시 받아 그려도 된다(담당자·계정 탭은 누를 때마다 — 6절 ③, 캠페인 탭은 처음 누를 때 — 4-8).
- 오른쪽 영업 메모: 지금 그대로(즉시 저장, 네 탭 공통).
- 「…」 메뉴(D4): 「제공 기록」(지금 조건 그대로) · 「삭제」(지금 조건 그대로). 항목이 하나도 없으면 「…」를 그리지 않는다. 이용 제한·열람 정지 항목은 별도 사양서가 여기에 더한다.
- 「목록」(D12)·사이드바·뒤로가기 → 저장 안 한 변경이 있으면 a03-09.
- 브랜드 목록(a03-13)은 지금 그대로 둔다(브랜드 이름 → 이 페이지).
- 들어오는 곳 다섯은 그대로 `openBrandDetail(id)` 를 부르되 **들어온 곳 인자는 돌아가기에 쓰지 않는다**(`BRAND_DETAIL_BACK` 제거).
  - 오리엔시트 발급 창 계정 경고에서 들어오면 **담당자·계정 탭을 연다**(그 경고가 「담당자·계정 탭에서…」라고 안내한다 — §16-5 8번). 이것만 D7 의 예외.

### 4-1. 브랜드 정보 탭 (a03-00d · 00e)
- 칸: 「기본 정보」(회사 선택 + 상태 · 회사 요약 상자 · 브랜드명 한·일·영) → 「SNS 정보」(공식 Instagram · X) → 「브랜드 공개 기본 열」(D3 — 「새 브랜드」 모달에는 지금처럼 그리지 않는다).
- 회사 요약 아래 「이 정보는 「회사 관리」에 있습니다. 수정」 → a03-07(4-4). 매니저(`company.cud` 쓰기 없음)는 「보기」 → a03-07b.
  - 회사 선택을 바꾸고 아직 저장 안 했으면 「수정」은 **새로 고른 회사**를 연다.
- 맨 아래 띠(변경이 있을 때만): 「저장하지 않은 변경이 있습니다 — 이 탭의 내용은 「저장」을 눌러야 저장됩니다.」 + 「되돌리기」(A4) · 「저장」.
- **변경 판정** = 저장된 값과 지금 칸 값이 다름. 담당자 줄 저장·계정 동작·영업 메모·회사 모달 저장은 세지 않는다(바로 저장되므로).
- 「저장」 → 새 서버 함수(5-1)에 **바뀐 칸 + 연 순간 값(`p_prev`)** 을 보낸다.
  - `ok` → 띠·점이 사라지고 토스트 「브랜드 정보를 저장했습니다.」, 머리 배지·제목·요약 줄 갱신, `refreshPane('brands')`
  - `stale` → a03-10(4-6)
  - 그 밖 실패 → 값 그대로 + 토스트 「브랜드 정보를 저장하지 못했습니다. 잠시 후 다시 시도해 주십시오.」(이름 중복은 지금 문구 유지)
  - 권한 거부 → 「권한이 바뀌어 저장할 수 없습니다. 페이지를 새로고침해 주십시오.」
- 🔴 보내지 않는 것: `contacts`(D8) · 소개·어필·Qoo10(D14) · 공개 기본 열은 `report.share` 쓰기가 없으면 보내지 않음(D3).
- 매니저 보기(a03-00e): 브랜드 정보는 매니저도 저장할 수 있다(지금과 같다). 공개 기본 열 칸은 권한에 따라 읽기 전용. 「병합」·「…」의 「삭제」는 캠페인 관리자 이상만.

### 4-2. 담당자·계정 탭 (a03-00 · 00a · 00f · 91 · 91a · 92 · 93 ③④)
- 카드 머리: 「담당자 · 브랜드 페이지 계정」 · 「멤버 n / m명 · 초대 대기 k 포함」 · 「멤버 상한 바꾸기」(권한) · 「+ 담당자 추가」.
- 표 열: 이름 · 이메일 · 역할(대표/멤버/담당자) · 브랜드 페이지 계정 · 관리.
  - 줄 = 담당자 줄 ∪ 계정 줄(대표·멤버). 같은 사람 판정은 이메일(A8). 담당자 목록에 없는 멤버도 계정 줄로 보인다.
  - **초대 줄(대기·만료·거절함)은 없다** — 숫자로만(§16-5 11번).
  - 계정 칸: 대표 줄 = a03-91 ⓐ~ⓔ / 연결 요청 보냄이면 a03-91a(「요청 취소」, 권한 필요) / 멤버 줄 = 「사용 중」 + 「마지막 접속」(a03-92) + 「해제」(권한 필요) / 계정 없는 담당자 줄 = 「계정 없음」.
  - 대표 줄이 아예 없으면 카드 머리 아래 한 줄에 「브랜드 연결 추가」와 4-3 의 안내(「계정 만들기」는 대표 줄이 생겨야 보인다)를 둔다(권한이 있을 때만).
  - 카드 머리의 멤버 숫자도 머리 요약 줄과 같은 규칙(실패·계정 기능 꺼짐이면 뺀다).
- 대표 계정 줄 상태와 버튼(사양 §16-4 「대표 담당자 계정 줄의 상태와 버튼」 그대로):

| 상태 | 계정 칸 | 버튼 |
|---|---|---|
| ⓐ 계정 없음 | 회색 「계정 없음」 | 「계정 만들기」 · 「브랜드 연결 추가」 |
| ⓑ 미발송 | 「메일 미발송」 | 「다시 보내기」 · 「해제」 |
| ⓒ 설정 메일 보냄 | 「메일 보냄 · ~까지 유효(예상)」(본인 재요청이면 「(본인 요청)」) | 「다시 보내기」 · 「해제」 |
| ⓓ 링크 만료 | 주황 「링크 만료」 | **「다시 보내기」 강조** · 「해제」 |
| ⓔ 설정 완료 | 초록 「사용 중 · M/D 설정」 + 「마지막 접속」 | 「대표 담당자 바꾸기」 · 「해제」 |

  - ⓑ~ⓓ 에서는 「브랜드 연결 추가」·「대표 담당자 바꾸기」를 숨긴다. 「계정 만들기」는 ⓐ 에서만.
  - 🔴 「~까지 유효(예상)」 표시와 ⓓ「링크 만료」 판정은 같은 24시간 값에 기대므로 **둘 다** 인증 공용 설정 24시간을 개발·운영 둘 다 바꾼 뒤에만 켠다(§16-4). 그 전에는 ⓒ「메일 보냄」만 보이고 ⓓ로 넘어가지 않는다.
- 🔴 **「계정이 있는 동안」에는 연결 요청 중(a03-91a 「보냄」)도 든다** — 수락되는 순간 서버가 이메일로 대표 표시를 옮기므로, 요청 중에 대표 줄 이메일이 바뀌거나 대표 표시가 옮겨지면 엉뚱한 줄로 간다. 그래서 4-5 의 대표 줄 잠금·대표 이동 막기·A10 의 「계정이 없는 브랜드」와 5-2 의 서버 거부는 「대표 계정 ⓑ~ⓔ 또는 연결 요청 보냄」을 기준으로 한다. 만료·거절·취소되면 ⓐ 로 돌아가고(따로 「다시 요청」 단추는 없다 — ⓐ 단추로 다시 보낸다), 계정 칸은 「계정 없음 · 연결 요청 만료됨/거절됨/취소됨」 한 칩으로 그린다. 수락되면 새 대표가 담당자 목록에 없을 때 서버가 줄을 더해 대표 표시를 붙인다(대표 바꾸기와 같은 §16-4 화면 정책 ②).
- 권한 「브랜드 페이지 계정 관리」가 없으면(a03-00f) 계정 버튼 전부 **안 보임**, 상태 표시는 보임. 「수정」·「+ 담당자 추가」는 남는다.
- 계정 상태 조회 실패(a03-93 ④): 계정 칸 「확인 불가 / 계정 상태를 불러오지 못했습니다 / 다시 불러오기」, 「계정 만들기」 등 계정 버튼은 숨긴다. 🔴 실패를 「계정 없음」으로 그리지 않는다.
- 담당자 0명(a03-93 ③): 「담당자가 없습니다. 「+ 담당자 추가」를 눌러 등록하십시오.」
- 🔴 이 탭의 모든 동작 뒤에는 **이 탭 영역·탭 숫자·머리 요약 줄만** 다시 그린다(페이지 전체 금지 — 브랜드 정보 탭의 고치던 값이 사라진다). 화면이 들고 있는 담당자 목록 사본(지금 이름 `_brandFormContacts` — 머리 요약 줄의 대표 담당자 이름과 담당자 모달이 쓴다)도 서버 값으로 맞춘다. 브랜드 정보 「저장」은 이 사본을 보내지 않는다(D8).

### 4-3. 계정 동작 (a03-01 ~ 05b · 90)
모두 권한 「브랜드 페이지 계정 관리」. 서버가 같은 권한으로 다시 판정한다. 결과 문구는 피그마 a03-90 토스트.

| 동작 | 창 | 서버 | 갈래 |

- 계정 줄 끝 「…」는 이번에 **그리지 않는다**(항목이 이용 제한뿐 — D2).

### 4-4. 회사 정보 수정 모달 (a03-07 · 07a · 07b)
- 「회사 관리」의 회사 수정 모달과 같은 칸 + 맨 위 「이 회사에 속한 브랜드 N개에 함께 바뀝니다」(N = 그 회사의 활성 브랜드 수 — 브랜드 화면과 같은 기준).
- 🔴 회사 값은 **아이디로 서버에서 새로 받아** 채운다(`_companiesCache` 에 기대지 않는다). 받기 실패면 모달을 열지 않고 토스트.
- 저장 뒤: 회사 요약 상자·회사 선택 칸 이름·머리 요약 줄만 새로 그림. **고치던 브랜드 값은 그대로.** 회사 관리 목록이 보관값을 갖고 있으면 `refreshPane('companies')`.
- 회사명 중복(a03-07a)은 지금처럼 띄어쓰기·대소문자를 같게 보고 거부 — 모달 안에 오류를 보이고 값은 그대로.
- 연결된 회사가 「보관」이면: 「수정」 대신 「보기」(07b)만 — 보관 회사를 브랜드 상세에서 되살리지 않는다.

### 4-5. 담당자 추가·수정 모달 (a03-08 · 08a~08e)
- 「수정」은 담당자 정보가 있는 줄에만. 「+ 담당자 추가」는 빈 폼(08a).
- 저장 = **그 줄만** 서버에 바로(5-2). 브랜드 정보 탭 「저장」과 무관.
- 필수는 이름뿐(08b). 이메일은 형식만 검사(비면 통과 — 단 대표 표시를 켠 줄은 이메일 필수).
- 이메일을 고쳐도 로그인 이메일은 바뀌지 않는다 — 모달에 안내.
- 「대표 담당자로 표시」:
  - 계정이 없으면(ⓐ) 자유롭게 옮긴다(지금과 같다). 🔴 그래도 계정 메일·연결 요청은 나가지 않는다(D10·D11) — 대표 이메일이 다른 브랜드 계정 이메일이어도 저장만 되고, 연결은 「계정 만들기」를 눌렀을 때 a03-01c 로 간다.
  - 계정이 있으면 멤버 계정이 있는 줄로만 옮길 수 있고, 옮기면 a03-02(그 멤버를 고른 채)로 이어진다. 계정 관리 권한이 없는 관리자에게는 계정이 있는 동안 이 체크칸이 **보이지 않는다**(D15 — 계정 동작의 입구). 연결 요청 보냄 상태에서는 멤버가 없어 옮길 줄이 없으므로, 권한이 있는 관리자에게는 체크칸 대신 「연결 요청 중에는 대표 담당자를 바꿀 수 없습니다」(권한이 없으면 위와 같이 아무것도 안 보인다). 대표 이동은 모달의 다른 칸 저장과 섞지 않는다 — 체크를 옮기면 a03-02 가 위에 뜨고, 이름 등 다른 칸은 모달 「저장」으로 따로 저장된다. 막힐 때 08d 안내 둘 중 하나(설정 마친 계정 → 「먼저 대표 담당자가 이 사람을 멤버로 초대해야 합니다」 / 설정 전 → 「먼저 지금 대표 담당자를 해제한 뒤 새 사람으로 계정을 만들어 주십시오」).
  - 계정이 있는 동안 대표 줄 잠금(08e): 체크 해제·삭제·이메일 칸 잠김, 이름·연락처만.
- 삭제: 모달 안 「삭제」 → 확인 창(되돌릴 수 없음 — 다시 입력하면 되므로 확인만).
- 저장 실패(08c): 값 그대로 + 모달 안 오류.

### 4-6. 저장 충돌 확인 (a03-10)
- 브랜드 정보 「저장」이 `stale` 을 받으면 연다.
- 본문 = **연 뒤에 바뀐 칸만** 표로: 칸 이름 · 지금 값 · 내가 넣은 값 · 누가 · 언제(`brand_profile_history` 에서 연 순간 이후 줄).
- 단추: 「다시 불러와서 확인」(브랜드 정보 탭을 서버 값으로 다시 채움 — 내 변경은 버린다고 이 창 문구에 적는다. 확인 창을 더 띄우지 않는다) / 「내 값으로 저장」(지금 서버 값을 새 `p_prev` 로 삼아 다시 저장).
- 이력을 못 읽으면 표 대신 「다른 사람이 그사이 이 브랜드 정보를 고쳤습니다」 한 줄 + 같은 두 단추.

### 4-7. 오리엔시트 탭 (a03-00b · 93 ⑤⑥)
- 지금 「오리엔시트」 묶음을 탭으로 옮긴다(내용 그대로 — 카드·지난 서베이 신청 한 줄 안내). 페이지 열 때 함께 받는다. 실패와 0건 구분.
- 발급·삭제·연결·발행 뒤 이 탭·탭 숫자·머리 「…」 메뉴(삭제 노출 조건이 바뀌므로)만 다시 그린다(`refreshBrandDetailSheets` — 지금도 시트가 생기면 삭제 단추를 뗀다).
- 발급 경고·받는 사람 규칙(§16-5 8·9번)은 이미 개발서버 `admin-orient.js` 에 있다 — 이 작업에서 바꾸지 않는다.

### 4-8. 캠페인 탭 (a03-00c · 93 ⑦⑧⑨)
- 지금 캠페인 탭 그대로(오리엔시트 연결 / 직접 등록, 처음 누를 때 받음, 늦은 응답 버림, 줄에 단추 없음). 탭 이름의 「캠페인 (n)」은 지금처럼 페이지를 열 때 건수만 따로 센다(`countCampaignsByBrand`) — 세기 실패면 숫자를 빼고 이름만.
- 줄마다 「브랜드 공개 중」(초록) / 「브랜드 공개 꺼짐」(회색) 배지 — 이미 개발서버에 있다. 줄을 누르면 진행현황.
  - 🔴 지금 `brandDetailOpenCampProgress` 는 `closeBrandDetailModal()` 로 `_brandsCurrentId` 를 비운다. 새 판은 **떠날 때 확인(a03-09)을 거쳐** 진행현황으로 가고, 사용자가 「머물기」를 고르면 아무것도 비우지 않는다.

### 4-9. 떠날 때 확인 (a03-09)
- 판단 = 4-1 의 변경 판정. 다른 탭으로 옮기는 것은 떠나는 것이 아니다.
- 가로채는 곳 = 관리자 화면의 페이지 이동 **한 곳**(사이드바·「목록」·캠페인 줄·주소의 `#` 바뀜 — A3). 새로고침·탭 닫기는 브라우저 기본 경고(A2).
- 단추: 「머물기」 / 「저장하지 않고 나가기」(A1).
- 다른 브랜드 상세로 바로 가는 길(운영 현황 등)도 같은 확인을 거친다.

## 6. 의심·경우의 수

1. **공개 기본 열을 탭 저장에 합치면(D3) 권한 없는 관리자의 저장이 실패할 수 있다** — 화면이 그 칸을 빼먹고 보내면 서버가 거부해 브랜드명 저장까지 막힌다. → 화면은 `report.share` 쓰기가 없으면 **인자 자체를 안 보낸다.** 시험에 「매니저가 브랜드명만 고쳐 저장」을 넣는다.
2. **(UX) 계정 동작 뒤 다시 그리기가 고치던 값을 지운다** — 탭으로 나눈 이유 자체. → 4-2 「이 탭 영역과 머리 요약 줄만」. 머리 요약 줄을 그리는 함수가 브랜드 정보 탭 입력칸을 건드리지 않는지 리뷰에서 지목.
3. **대표 표시의 서버 이동과 화면 사본이 어긋난다** — 연결 요청 수락·대표 바꾸기는 서버가 `contacts` 의 대표 표시를 옮긴다. 화면이 연 뒤 다른 관리자가 그 일을 하면 담당자 탭은 옛 표시. → 계정 동작 뒤·담당자 탭을 누를 때마다 `contacts` 를 새로 받는다. 브랜드 정보 저장은 `contacts` 를 안 보내므로(D8) 되돌림은 없다.
4. **담당자 줄에 아이디가 없는 옛 데이터** — `brands.contacts` 의 옛 줄(9/23 이전)에 줄 아이디가 없으면 5-2 가 줄을 못 찾는다. → 개발이 착수 때 운영·개발에서 아이디 없는 줄 수를 세고, 있으면 함수가 첫 저장 때 아이디를 붙이거나 일괄 보정. 결정은 작업표에서.
5. **직접 UPDATE 우회** — 화면을 고쳐도 `brands` 직접 UPDATE 정책이 남아 있으면 옛 화면 캐시(배포 직후 새로고침 안 한 관리자)가 `contacts` 를 통째로 보낼 수 있다. → 5-5. 최소한 배포 공지에 「새로고침」.
6. **회사 모달은 충돌 확인 없음(A9)** — 브랜드 대표 담당자가 회사 정보를 고친 직후 관리자가 연 모달로 저장하면 덮는다. 빈도 낮음으로 받아들인다. 사고가 나면 회사 관리 화면과 함께 536 방식으로 바꾼다.
7. **(UX) 들어오는 곳 다섯 중 「돌아가기」가 사라지는 곳** — 운영 현황·서베이에서 들어온 사람이 「목록」을 누르면 브랜드 목록으로 간다(D12 의도). 브라우저 뒤로가기의 목적지는 바꾸지 않는다(들어온 곳으로 간다 — 변경이 있으면 a03-09 는 거친다, A3).
8. **운영 화면 변화가 크다** — 지금 운영 실무자가 쓰는 화면이 하루에 바뀐다(머리 「저장」이 탭 안으로, 담당자가 모달로). → 출시 날 관리자 공지 필수(`/공지초안-관리자`) + Notion 「관리자 가이드」 브랜드 관리 페이지 갱신(`notion-sync.md`).
