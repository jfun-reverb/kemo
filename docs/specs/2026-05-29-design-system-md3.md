## 현재 상태 (2026-05-29 실측, 규칙 A)

### 이미 있는 것 (Material Design 3와 일치 — 재정의 금지)
- **색상**: `dev/css/base.css` `--primary`/`--primary-dark`/`--surface`/`--on-surface`/`--outline` 등 MD3 색 역할(role) 토큰 보유
- **그림자**: `--elevation-1`~`--elevation-4` (MD3 elevation), `--sh`/`--sh-hover` 별칭

- **관리자 버튼 통일 규칙 없음**

- **버튼**: 공용 `.btn`/`.btn-primary`/`.btn-outline`/`.btn-ghost`/`.btn-green`(`components.css`)는 **인플루언서 화면용**. 관리자 화면은 이걸 거의 안 쓰고 `.status-tab-btn`·`.pay-refresh-btn`·`.mf-btn` 등 **기능 전용 one-off ~18종 + 인라인**으로 분산

## 의심·경우의 수 (규칙 B)

1. **변수만 추가하면 검증 불가** — 화면이 안 바뀌므로 "됐다"를 확인할 방법이 없음 → PR 1(토큰)과 PR 2(시범 적용)를 분리하되 PR 2에서 *눈에 보이는 화면 변화*로 검증.
2. **간격·폰트 스냅(snap) = 픽셀 변경 = 회귀** — 6px를 8px로 맞추면 레이아웃이 미세하게 움직임 → 한 번에 전역 치환 금지, **화면 단위로 before/after 스크린샷 비교**.
3. **(UX) compact 밀도가 너무 좁으면 클릭 실수·가독성 저하** — 버튼 최소 높이·터치 영역 하한선 정의(아래 토큰). WCAG/접근성(`PROJECT_CONTEXT.md` 2-3) 색대비·포커스 표시 유지.
4. **(UX) 점진 적용 중 "반쯤 통일된" 화면** — 같은 화면 안에서 옛 버튼·새 버튼이 섞이면 더 지저분해 보임 → **적용 단위 = 화면(페인) 통째**, 부분 적용 금지.
5. **보류 PR 충돌** — 진행 중 화면을 디자인 시스템이 동시에 건드리면 충돌 → **이미 안정화(운영 배포)된 화면부터** 적용, 진행 중 화면은 그 작업 머지 후.
6. **버튼 "통일"의 두 해석** — ① 관리자도 인플 공용 `.btn`을 쓰게 할지, ② 관리자 전용 버튼 표준을 새로 둘지. 밀도가 다르므로(인플=터치, 관리자=compact) **관리자 전용 버튼 표준(`.abtn-*`) 신설**이 맞음(아래 설계).
7. **현재 구현 충돌점**: 색상·그림자·모서리 토큰은 이미 MD3라 **재정의하면 회귀** → 간격·폰트·버튼만 신규. 확인 완료.

## 설계

> 전략 = **토큰 정의 + 점진 적용**(확정). 밀도 = **compact**(확정). 순서 = **버튼부터**(확정). 범위 = **관리자 먼저, 인플 나중**(확정).
> 토큰은 양쪽 공용을 위해 `base.css`에 둠(인플 확장 시 재사용). 관리자 적용만 우선.

### 1. 간격(spacing) 토큰 — MD3 4dp 그리드 기반, compact
`base.css :root`에 추가:
```
--sp-0:2px;   /* 마이크로: 배지 안쪽, 칩 */
--sp-1:4px;   /* 타이트: 아이콘-텍스트 간격 */
--sp-2:8px;   /* 기본 작은 여백 */
--sp-3:12px;  /* 셀·버튼 좌우 패딩 */
--sp-4:16px;  /* 카드·섹션 패딩 */
--sp-5:24px;  /* 블록 간 큰 간격 */
--sp-6:32px;  /* 페인 외곽 */
```
- 혼재값 스냅 가이드(화면 적용 시): 3→4, 5/6/7→8(또는 4), 10→8/12, 14→12/16, 18→16, 20→24, 28→24/32. **전역 일괄 치환 금지** — 화면 단위.

### 2. 폰트 크기 토큰 — 5단계 (사용자 결정 2026-05-29: 7→5 축소)
> 11·12·13·14px이 1px 차이라 화면에서 거의 구분 안 됨 → 비슷한 12·14px 제거, 5단계로 단계차이를 또렷하게. 역할 기반 이름.
```
--fs-caption:11px;  /* 배지·캡션 */
--fs-body:13px;     /* 관리자 본문 기본 + 버튼 라벨 */
--fs-subtitle:16px; /* 소제목 */
--fs-title:20px;    /* 페인 제목 */
--fs-display:24px;  /* 대시보드 KPI 숫자 */
```
- 스냅: 9·10·12 → caption(11), 14·15 → body(13), 17·18 → subtitle(16), 22 → title(20), 32 → display(24).
- 버튼 라벨은 별도 단계 없이 body(13px) 사용(compact).

### 3. 관리자 버튼 표준 `.abtn-*` (compact) — 점 "버튼부터"
- `admin.css`에 신설. compact 높이.
- 베이스 `.abtn`: `min-height:32px; padding:6px 12px; font-size:var(--fs-body); border-radius:var(--r8); font-weight:600;` (compact — MD3 기본 40px보다 낮음. 하한 32px로 클릭 영역 확보)
- 변형 **4종 (사용자 결정 2026-05-29: 6→4 축소)** — 핑크 단색 팔레트에서 구분 안 되던 `elevated`·`tonal` 제거:
  - `.abtn-filled` — 채움(주요 액션). `background:var(--primary);color:var(--on-primary)`
  - `.abtn-outline` — 외곽선(중립·보조). `border:1px solid var(--outline)`
  - `.abtn-text` — 텍스트(저강조). 배경·테두리 없음
  - `.abtn-danger` — 위험(삭제·회수). 빨강 계열
- 크기 **2단계 (사용자 결정 2026-05-29: 3→2 축소)** — 32·28·24px이 4px차라 비슷해 중간 제거:
  - 기본 32px (폼·툴바·모달), `.abtn-sm` 26px (테이블 행 인라인). 라벨 폰트 13px(body).
- **비활성(`[disabled]`)**: 유형 무관 **연한 회색 바탕**(`background:#ECECEC; color:#9E9E9E; border:#E0E0E0`)으로 덮음 — 흐림(opacity)만으로는 약함(사용자 결정 2026-05-29).
- hover/active/disabled/focus-visible 상태 + `box-shadow:var(--elevation-1)` (filled hover→elevation-2). focus-visible 외곽선 필수(접근성).
- **기존 one-off 버튼 ~18종**은 화면 점진 적용 시 `.abtn-*`로 치환(즉시 전역 교체 아님).

### 4. 기존 클래스 처리 (고문 4번)
- `.mf-btn`/`.admin-select` 등 **구조적 공용 클래스**: 즉시 교체 대신 **내부 px → `var(--sp-*)`/`var(--fs-*)` 연결**(화면 변화 최소, 점진 안전).
- **one-off 버튼 클래스**: 화면 단위 적용 시 `.abtn-*`로 치환 후 제거.

### 5. 점진 적용 거버넌스 (충돌·회귀 방지 — 가장 중요)
- **적용 단위 = 화면(페인) 통째.** 한 화면 안 부분 적용 금지(의심 4).
- **순서**: 이미 운영 안정화된 화면부터. 진행/보류 PR이 건드리는 화면(결과물·메시지·운영현황·채널별결과물)은 **그 작업이 dev/운영 머지된 뒤** 적용.
- 자주 보는 화면 우선 권장 순: 대시보드 → 캠페인 목록 → 신청 관리 → (보류 해소 후) 결과물 → 인플루언서 → 기준데이터/관리자계정.
- 각 화면 PR: 버튼 `.abtn-*` 치환 + 인라인 간격·폰트 `var()` 치환 + **before/after 스크린샷**. reverb-reviewer GO + QA Light(관리자 페인).
- 신규/수정하는 화면은 **무조건 토큰·`.abtn` 사용**(앞으로의 인라인 증가 차단). `.claude/rules/ui.md`에 한 줄 추가 권장: "관리자 신규/수정 화면은 `--sp-*`/`--fs-*`/`.abtn-*` 사용, 인라인 간격·폰트 px 금지".

### 6. 밀도(compact) 정의
- 위 토큰·버튼 높이가 compact 기준. 별도 밀도 토글은 만들지 않음(작업량 절감, 사용자 결정).
- 테이블 행 높이·셀 패딩도 compact 기준 토큰(`--sp-2`/`--sp-3`)으로.

### 7. 인플루언서 페이지 (범위 외 — Apple HIG 별도 트랙)
- **이 사양서는 관리자(PC) 전용.** 관리자는 PC 도구라 Apple iOS HIG 대상이 아니며, 여기 정의한 compact 실용 시스템을 유지한다.
- **인플루언서 모바일 앱은 Apple Human Interface Guidelines를 최우선 기준으로 별도 설계**(2026-05-29 사용자 지시 — 아이폰 유저·하이브리드앱 전환 대비). 관리자 토큰을 그대로 확장하지 않는다(iOS 타입 스케일·평평한 표면·iOS 컨트롤은 관리자 compact 토큰과 방향이 다름). 규칙: `.claude/rules/ui.md` 「Apple Human Interface Guidelines 우선」. 인플 작업 착수 시 별도 사양서 작성.
- `components.css`의 인플 `.btn` 계열은 이번(관리자) 작업에서 건드리지 않음.

- 버튼 종류 = **4종 (filled·outline·text·danger)** ✅ — 핑크 단색에서 구분 안 되던 elevated·tonal 제거
- 버튼 크기 = **2단계 (32·26px)** ✅ — 4px차라 비슷하던 중간 28px 제거 / 비활성 = **연한 회색 바탕**
- 모서리 = **유지 (이번 범위 제외)** ✅ — r12·r16이 데모 박스에선 비슷해 보이나 **용도가 다름**(r12=입력·컨트롤 10곳, r16=카드·컨테이너 9곳, 중복 아님). 통합 시 캠페인 카드·폼 입력 등 **인플루언서 화면 CSS 포함 19곳** 영향 → 「관리자 우선」 범위 밖. 정리 필요 시 디자인 시스템 이식 완료 후 별도 작업
- (권고) 밀도 토글 미도입 / 관리자 버튼은 전용 `.abtn-*` 신설(공용 `.btn` 강제 안 함) / 기존 공용 클래스는 var() 연결, one-off는 화면 적용 시 치환
