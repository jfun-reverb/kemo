1. 🔴 **반쯤 고친 내용으로 발행된다** — 자동 채움이 `data` 를 읽으므로 브랜드가 고치다 만 상태가 캠페인에 들어간다(이번 조사에서 확인, 전수조사 지적보다 크다)
2. **고쳐진 내용과 옛 견적이 함께 보인다** — `data.quote` 는 제출 때만 계산(전수조사 ①-7)
3. 관리자는 수정 여부를 알 길이 없다

### 미해결 백로그
- 운영에서 **이미 제출 뒤 고쳐진 시트는 제출본이 덮어써져 되살릴 수 없다.** 건수는 착수 전에 세어 본다(아래 「착수 전 확인」)

## 의심·경우의 수

1. **처음 제출 전 시트까지 작성본으로 보내면 범위가 커진다**(기술) — 미제출 시트는 발행 대상이 아니므로(「이 카드로 발행」은 제출됨만) 지금처럼 `data` 에 저장해도 문제가 없다 → **`submitted` 일 때만** 작성본 칸을 쓴다
2. **브랜드가 다시 제출을 잊는다**(UX) — 결정 1의 대가. 고친 내용이 관리자에게 안 간다 → 작성 화면 안내 문구를 바꾸고, 완료 화면에도 「제출하지 않은 수정 내용이 있어요」를 띄운다. 관리자는 결정 3 표시로 안다
3. **발행 뒤 남은 작성본**(데이터) — **새 구조(카드 1장)** 시트를 고치던 중 관리자가 발행하면 작성본이 남는다. 이후 저장은 `consumed` 거부라 더 쌓이지 않는다(⚠️ 옛 다카드 일부 발행 시트는 `submitted` 라 계속 저장되고 표시도 뜬다 — 그 시트는 아직 고칠 수 있으니 맞는 표시다. 경우의 수 4·완료 기준 8) → 표시 조건을 「작성본 있음 **그리고** `submitted`」로 해 발행된 시트에는 표시가 안 뜬다. 작성본은 지우지 않고 둔다(증거)
4. **옛 다카드 시트 일부 발행**(데이터) — 작성본에도 발행 카드 복구(328)를 **제출본 기준으로** 걸어야 다시 제출 때 발행 카드가 바뀌지 않는다. 제출 함수가 이미 같은 헬퍼를 거치므로 「다시 제출」 시점에 지켜진다
5. **두 판을 오가는 화면**(UX) — 완료 화면의 견적서는 **제출본**, 작성 화면은 **작성본**(없으면 제출본). 섞이면 브랜드가 고친 값으로 견적서가 바뀐 줄 안다
6. **자동저장마다 웹훅이 불린다**(운영) — 지금도 `data` UPDATE 마다 불리고 게이트 ①이 거른다. 작성본 칸 UPDATE 도 같은 Row filter 를 통과하므로 **동작은 그대로**(새 비용 없음)
7. **관리자 표시가 거짓이 되는 경우**(UX) — 브랜드가 「내용 수정하기」로 들어와 **아무것도 안 고치고** 나가도 자동저장이 돌면 「수정 중」이 뜬다 → 보정한 작성본이 **제출본과 같으면 작성본을 비운다**(NULL — 고쳤다가 원래대로 되돌린 경우도 표시가 사라진다. 아래 설계 ① `save_orient_draft`)

### 의도와 다르게 읽힐 수 있는 곳
- 「수정 중」 표시는 **고친 내용이 있다**는 뜻이지, 브랜드가 지금 화면을 보고 있다는 뜻이 아니다(마지막 저장 시각을 함께 보여 준다)
- 브랜드가 작성본을 버리고 제출본으로 되돌리는 단추는 **만들지 않는다**(결정 범위 밖 — 필요하면 후속)

## 설계

### ① 데이터베이스 — 마이그레이션 2개(번호는 개발이 정한다. ①이 먼저)
- **① 칸 추가** — `orient_sheets.draft_data jsonb NULL`, `orient_sheets.draft_saved_at timestamptz NULL`. 기본값 없음(기존 행 전부 NULL = 작성본 없음)
- **② 함수 3종 재정의** — 🔴 각각 **현재 원본**을 베이스로: `save_orient_draft` = 425, `get_orient_sheet` = 187, `submit_orient_sheet` = **reverb-jp-42 의 변경이 들어간 판**(지금 461)
  - `save_orient_draft`: `status='submitted'` 이면 지금과 같은 보정(카드 번호·발행 카드 복구·서버 키 보존 — **기준은 제출본 `data`**)을 거친 값을 **`draft_data` 에** 쓰고 `draft_saved_at = now()`. 보정한 값이 제출본과 같으면 `draft_data`·`draft_saved_at` 을 NULL 로(경우의 수 7). `data` 는 손대지 않는다. 낙관적 잠금(`version`)·100KB 상한은 지금과 같게. `draft` 상태는 **지금 그대로** `data` 에
  - 🔴 **거부를 새로 걸지 않는다** — 425·429·446 원칙 유지
  - `get_orient_sheet`: 반환에 `draft_data`(있을 때만) 추가. 나머지 무변경
  - `submit_orient_sheet`: 성공 시 `draft_data`·`draft_saved_at` 을 NULL 로. 제출 내용은 지금처럼 **폼이 보낸 값**(폼이 작성본을 보낸다)
- ⚠️ 셋 다 익명 실행 함수다 — 시그니처를 안 바꾸면 `CREATE OR REPLACE` 로 권한이 유지된다. 반환 칸만 늘리므로 시그니처 무변경

### ② 작성 폼 `dev/sales/orient.html`
- 첫 불러오기: **작성 화면을 채울 값 = `res.draft_data ?? res.data`**. 완료 화면·견적서는 계속 `res.data`
- 작성 화면 안내(680) — 「제출하신 내용은 그대로 두고, 고친 내용은 따로 저장돼요. 「다시 제출」을 눌러야 담당자에게 전달돼요.」(문구는 개발이 다듬되 **「다시 제출해야 전달된다」**는 뜻을 반드시)
- 완료 화면 — `draft_data` 가 있으면 「제출하지 않은 수정 내용이 있어요. 「내용 수정하기」로 이어서 고치고 다시 제출해 주세요.」
- 자동저장은 무변경(서버가 갈라 저장)

### ③ 관리자 `dev/js/admin-orient.js` + `dev/lib/storage.js`
- `fetchOrientSheets`·`fetchOrientSheetById` 에 **`draft_saved_at` 만** 추가(작성본 내용 `draft_data` 는 **가져오지 않는다** — 결정 3)
- 표시 조건: `status === 'submitted' && draft_saved_at` → 목록 상태 칸 옆과 상세 머리에 「브랜드 수정 중 · 미제출 {formatDateTime(draft_saved_at)}」. 툴팁/안내: 「보이는 내용은 마지막 제출본입니다. 브랜드가 다시 제출하면 바뀝니다」
- 「이 카드로 발행」 확인 창에도 같은 경고 한 줄(막지 않는다)
- 자동 채움·견적서·상세 내용은 **무변경**(이미 `data` = 제출본)

## 완료 기준

1. 제출 → 「내용 수정하기」 → 글 고침 → 자동저장 → 관리자 상세 내용·견적서는 **그대로**, 목록·상세에 「브랜드 수정 중 · 미제출」
2. 그 상태에서 「이 카드로 발행」 자동 채움이 **제출본 값**으로 채워진다(+ 경고 한 줄)
3. 브랜드가 다시 제출 → 관리자 내용·견적이 새 값으로, 「수정 중」 표시 사라짐, 제출 알림 메일 1통(기존 게이트 규칙대로 — 30분 안 재제출이면 생략)
4. 고친 뒤 창을 닫고 다시 링크를 열면 → **완료 화면이 먼저 뜨는 시트**(새 구조 + 견적 또는 견적 오류 있음 — 「현재 상태」 1396줄 조건)는 완료 화면에 「제출하지 않은 수정 내용」 안내, 「내용 수정하기」에 **고친 값**이 있다. 그 밖의 시트(옛 구조 등)는 완료 화면 없이 작성 화면이 바로 열리며 **고친 값**과 「다시 제출해야 전달된다」 안내(설계 ②의 작성 화면 안내)가 보인다
5. 「내용 수정하기」로 들어와 아무것도 안 고치고 나가면 「수정 중」이 **뜨지 않는다**
6. **새 구조(카드 1장)** 시트를 고치던 중 관리자가 발행 → 브랜드 저장은 거부(지금과 같음), 관리자 표시 없음
7. 미제출(작성 중) 시트의 자동저장은 지금과 똑같이 `data` 에
8. 옛 다카드 일부 발행 시트에서 **발행되지 않은 카드를** 고치면 「수정 중」이 뜨고, 다시 제출해도 **발행된 카드 내용이 안 바뀐다**. 발행된 카드만 고치면 보정 뒤 제출본과 같아져 「수정 중」이 **뜨지 않는다**(경우의 수 7)
9. 서버 키(`issued`·`quote`·`quote_history`·`quote_error`·`notice_ack`)를 폼이 위조해 보내도 작성본·제출본 어디에도 안 들어간다
