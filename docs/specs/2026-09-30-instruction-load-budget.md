## 의심·경우의 수 (규칙 B)

1. 🔴 **전역 규칙은 git 에 없다** — `~/.claude/` 는 이 컴퓨터에만 있다. 프로젝트 규칙에서 「전역과 겹치는 부분」을 지우면, **전역 규칙이 없는 곳**(클라우드 세션·다른 컴퓨터·원격 에이전트)에서는 그 규칙이 통째로 사라진다.
   → 대책: 사용자 확인 1번. 로컬 한 대에서만 쓰면 기본 규칙(「원칙은 `common-xxx.md` §N」 한 줄)으로 줄인다. 🔴 **밖에서도 쓰면 그 한 줄로는 부족하다**(그 파일이 없다) — 뺄 문장마다 **핵심 내용을 한 줄로 남기고** 전역 파일 이름은 참고로만 붙인다. 감량은 작아진다.
2. **조건부 규칙은 기획·고문 세션에서 안 보인다** — 설계 단계에 필요한 내용을 옮기면 기획이 그 함정을 모른 채 사양서를 쓴다. 이미 한 번 겪었다(Apple 지침이 `ui.md` 에만 있어 묻힘 → `planning.md` 에 요지를 되살림).
   → 대책: 조각 D 는 조각 A 의 분류 기준(②~⑥이면 남긴다)을 그대로 쓴다. 「같은 판정이 여러 곳에 있다」류는 남긴다.
3. **스킬로 옮긴 「항상 지킬 규칙」은 안 지켜진다** — 일본어 뜻 병기가 스킬 안에만 있던 동안 세션마다 지켜지기도 안 지켜지기도 했다(`interaction.md` Why).
   → 대책: 스킬로는 **특정 작업에만 쓰는 절차**만 옮긴다. 「항상」 규칙은 스킬 대상이 아니다.
4. **UX — 사용자가 같은 지적을 반복하게 된다** — 규칙이 안 읽혀 세션이 틀리면 비개발자인 사용자가 다시 설명해야 한다. 이 비용은 글자 수보다 크다.
   → 대책: 조각마다 조각 A 의 「되돌리는 기준」(한 주 안에 「있었는데 몰랐다」 지적 → 그 덩어리 통째로 되돌림)을 적용한다.
5. **이유를 빼면 규칙이 약해진다** — `Why:` 에 적힌 사고가 규칙을 지키게 만든다. 통째로 지우면 다음 세션이 「작은 일이니까」로 건너뛴다.
   → 대책: 조각 C 는 이유를 **한 문장으로 남기고** 경위(날짜·파일·수치)만 사양서로 옮긴다. 경고(⚠️·🔴)는 빼지 않는다.
6. **줄이는 사이 다시 는다** — 하루 1,900자면 5만 자 줄이는 데 걸리는 기간에 그 일부가 다시 쌓인다.
   → 대책: 조각 E(증가 억제)를 **먼저** 또는 함께 한다.

### 현재 구현 충돌점
충돌 없음 — 코드·데이터베이스를 바꾸지 않는다. 영향은 「어느 세션이 어떤 규칙을 보나」뿐이다(위 1~4).

### 의도 모호점
- 「효율적 관리」 = **분량을 줄이는 것 + 다시 안 늘게 하는 것** 둘로 본다. 줄이기만 하면 한 달 안에 되돌아온다.
- **목표 후보 = 합계 13만 자 이하**(확정은 사용자 확인 2). 15만 자에 맞추면 곧바로 다시 넘는다. 13만 자면 여유 2만 ÷ 하루 1,900 ≈ 열흘. ⚠️ 목표치는 참고값 — 분류 기준과 부딪히면 **분류 기준이 이긴다**(조각 A 와 같은 원칙).

`paths:` 가 **없는** 규칙만 센다(`globs:` 는 센다). 대상 = `~/.claude/CLAUDE.md` + `~/.claude/rules/*.md` + `CLAUDE.md` + `.claude/rules/*.md`. 글자 수는 **바이트가 아니라 문자**(`python3 -c "len(open(f,encoding='utf-8').read())"`) — 한글은 한 글자가 3바이트라 `wc -c` 는 틀린다. 결과가 세션 시작 경고의 **합계**와 같은지 대조한다(양성 대조 — 파일별 값은 위 「경고와 실측」처럼 조금 어긋날 수 있다). ⚠️ **15만 자 아래로 내려가면 경고가 안 뜬다** — 그때부터는 대조할 경고가 없으므로, 이 방법이 경고와 일치함을 이미 확인한 **작성일 측정(245,753 = 경고 245.7k)**을 근거로 같은 방법을 그대로 쓴다. 방법을 바꾸지 않는다.

### 되돌리는 기준
조각 A 와 같다 — 한 주 안에 「규칙에 있었는데 세션이 몰랐다」 지적이 나오면 그 덩어리를 통째로 원래 자리로 되돌리고 「구현 결과」에 기록.
