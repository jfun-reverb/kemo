## 현재 상태 (2026-10-06 — 규칙 A, `origin/dev` 기준)

### 「종료」의 기준
- `autoEndCampaigns`(`dev/lib/storage.js`)가 `campaignFinishDate(c)` < 일본 시각 오늘이면 상태를 `closed` → `ended` 로 바꾼다. **바뀐 날짜는 기록하지 않는다** — 그래서 「종료 후 1개월」은 상태가 아니라 **날짜(`campaignFinishDate`)로** 센다(D-2).
- `campaignFinishDate(camp)`(`dev/lib/shared.js`) = `submission_end`, 없으면 행사 캠페인(`isEventCampaign`)의 `visit_end`, 그것도 없으면 `null`.

### 대리 등록 — 기간 제한 없음
- 입구 **둘**: 〔가〕 결과물 관리 머리의 「대리 등록」 버튼 → `openAdminProxyModal()`(인자 없음) 〔나〕 검수 창 안 `#delivCombinedProxyBtn` → `openAdminProxyFromCombined()` → 그 안에서 `openAdminProxyModal(presetAppId)` 를 **응모 id 를 넣어** 부른다(응모가 미리 골라진 채 열린다)
- ⚠️ **권한**: 대리 등록은 **캠페인 관리자 이상**만 — 서버 함수가 `is_campaign_admin()` 으로 막는다. 화면은 입구마다 다르다: 〔나〕 검수 창 버튼은 캠페인 매니저에게 **숨긴다**(`renderDelivCombinedBody`), 〔가〕 결과물 관리 머리 버튼은 **매니저에게도 보이고** 저장할 때 서버가 권한 오류로 거부한다(지금 동작 — 이번 범위 밖, 따로 고칠 거리). 이번 변경은 권한을 건드리지 않는다
- 후보 조회 `_loadAdminProxyApprovedApps`(`dev/js/admin-deliverables.js`) — `openAdminProxyModal` 이 **창을 열 때마다 새로 부른다**(받아 둔 값을 재사용하지 않는다) — 승인된 응모 **전건** + 캠페인을 `_proxyFetchByIds('campaigns', 'id, title, brand, brand_ja, brand_en, recruit_type, channel, campaign_no', …)` 로 붙인다. ⚠️ **날짜 칸을 안 가져온다** — 판정하려면 「판정 칸」(판정식 절)을 더해야 한다
- 캠페인 목록 `_renderAdminProxyCampList` — 날짜 거름 없음, 앞 100개까지
- 서버 `admin_create_deliverable_proxy`(현재 원본 **184**, 160 → 161 → 163 → 182 → 184) — 응모가 `approved` 인지·채널·승인 결과물 교체 차단은 보지만 **날짜는 안 본다**

### 「올려두고 미제출」 — 기간 제한 없음
- 응모 집합 `fetchStalledDraftApplications`(`dev/lib/storage.js`) — `deliverables.status='draft'` 인 응모 id 전부. 결과물 관리·신청 관리(`dev/js/admin-applications.js`)가 **같은 함수**로 받아 `stalledChip`(「올려만 둠」 딱지, `dev/js/admin-deliverables.js`)을 붙인다
- 건수·안내 창 목록 `fetchActionableStalledDrafts`(`dev/js/admin-core.js`) — `fetchStalledDraftDetails` 를 받아 **승인 응모 + 인증 상태 「미제출」·「인증샷 제출중」**만 남긴다(2026-10-06 다른 세션이 좁혔다). 결과물 행에 캠페인(`campaigns:campaign_id (…)`)을 붙여 오지만 **날짜 칸은 없다**
- ⚠️ 딱지(응모 집합)와 건수(안내 창)는 **조회 함수가 다르다** — 기간 조건을 한쪽에만 넣으면 딱지는 없는데 건수는 남거나 그 반대가 된다

### 충돌 가능성 있는 기존 동작
- 「올려두고 미제출」 안내 창은 해결책으로 대리 등록을 권한다 — D-5 가 같은 기간으로 맞추므로 **기간 때문에** 「할 수 없는 일」을 권하는 경우가 사라진다(충돌이 아니라 맞물림). ⚠️ 캠페인 매니저는 기간 안에서도 대리 등록 권한이 없어 그 안내가 여전히 할 수 없는 일을 권한다 — 권한 문제라 이번 범위 밖(지금과 같음)
- 정산: 대리 등록으로 인증 성공이 되는 경로가 기간 뒤에 막힌다. 정산 판정 자체는 바뀌지 않는다
- 충돌 없음 확인: 회원 결과물 제출 마감(`get_deliverable_gate`) · 탈퇴 차단 트리거(결과물, 422) · 감사용 계정 격리 — 셋 다 대리 등록 날짜와 무관

## 설계

### 판정식 (이 문서의 단일 정의)

```
기준일 = campaignFinishDate(캠페인)          -- submission_end, 없으면 행사의 visit_end, 없으면 없음
마지막 가능일 = 기준일 + 1개월(달력)          -- 10/15 → 11/15, 2027-01-31 → 2027-02-28 · 윤년 2028-01-31 → 2028-02-29(말일 맞춤)
열림 = 기준일이 없음  또는  일본 시각 오늘 ≤ 마지막 가능일
```

- 서버는 「기준일이 없으면 통과, 있으면 `(now() AT TIME ZONE 'Asia/Tokyo')::date <= (기준일 + interval '1 month')::date` 일 때만 통과」로 쓴다(위 식과 같은 뜻). 행사 판정은 화면의 `isEventCampaign` 과 **같은 칸**(`event_mode`)으로 한다
- 🔴 **「판정 칸」**(이 문서의 단일 정의) = 판정식에 필요한 캠페인 칸 전부 — `submission_end` · `visit_end` · **`event_mode`**(`isEventCampaign` 이 보는 칸 — 서버도 `campaigns.event_mode` 를 그대로 본다). 캠페인을 조회하는 자리는 판정하려면 이 칸을 **모두** 가져와야 한다 — 날짜만 가져오면 행사 캠페인이 마지막 방문일 기준을 잃는다
- 화면 공용 함수(둘 다 이름 확정 — `isProxyWindowOpen` 은 판정 자리 다섯(P-1)이 부르고, `proxyWindowLastDate` 는 문구 ② 를 쓰는 두 자리와 검증 3 이 부른다): `isProxyWindowOpen(camp)` → 참·거짓 / `proxyWindowLastDate(camp)` → 마지막 가능일 **`YYYY-MM-DD` 문자열**(기준일이 없으면 `null`). 문구 ② 의 ○/○ 는 이 문자열을 화면이 월/일로 바꿔 쓴다. `campaignFinishDate` 옆(`dev/lib/shared.js`)에 둔다 — 기준일 함수를 그대로 쓰기 위해서다

### 문구 (이 문서의 단일 정의 — 다른 자리는 번호로 가리킨다)

- ① 목록 안내(자리·조건은 설계 표 「목록」 줄): 「대리 등록 기간이 지난 캠페인은 목록에서 빠집니다」 — 🔴 **기준일을 문구에 쓰지 않는다.** 「마감일」은 행사 캠페인 조건과, 「종료」는 상태가 바뀌는 날(기준일 다음 날)과 어긋난다. 정확한 날짜는 문구 ② 가 보여 주고, 규칙 설명은 실무자 가이드(Notion)에 적는다
- ② 기간 지남 안내(날짜 포함) — 쓰는 자리 둘: 검수 창 회색 버튼의 옆 글·마우스를 올리면 뜨는 설명 / 입구 〔나〕로 미리 고른 응모가 닫혀 있을 때 창 안 알림(토스트): 「대리 등록 기간이 지났습니다(○/○까지)」 — ○/○ = `proxyWindowLastDate` 의 월/일(판정식 절 참조)
- ③ 서버 거부(`proxy_window_closed`)의 화면 오류 안내: 「대리 등록 기간이 지났습니다」 — 서버는 날짜를 돌려주지 않으므로 날짜 없는 판. 기준일을 쓰지 않는 이유는 ① 과 같다

②와 ③을 일부러 다르게 둔다 — ②는 화면이 날짜를 알고, ③은 모른다

### 대리 등록

| 자리 | 바꿀 것 |
|---|---|
| 후보 조회 `_loadAdminProxyApprovedApps` | 캠페인 칸에 「판정 칸」을 더한다. 창을 열 때마다 새로 부르는 지금 동작을 유지한다(검증 4 가 이것에 기댄다) |
| 목록 `_renderAdminProxyCampList` | 후보 조회가 새로 받은 「판정 칸」으로 닫힌 캠페인을 뺀다(D-4). 문구 ① 은 **지금 검색어(없으면 전체)에 맞는 캠페인 중 기간 때문에 빠진 것이 있을 때만**, **한 번만** 띄운다 — 그 검색어로 보일 캠페인이 있으면 **목록 맨 위**, 0건이면 **빈 상태 자리**. 빈 상태 자리에 띄울 때는 「일치하는 캠페인 없음」 **대신** 문구 ① 하나만. 빠진 것이 없으면 문구 ① 을 띄우지 않고 빈 상태는 지금처럼 「일치하는 캠페인 없음」(오타로 0건인데 기간 탓이라 하지 않게). 이 조건의 단일 정의 |
| 검수 창 버튼 `#delivCombinedProxyBtn` | 그 응모의 캠페인이 닫혔으면 회색 + 문구 ②(P-4). 버튼 표시는 `renderDelivCombinedBody` 가 매 렌더마다 정한다(지금은 매니저·「검수 불필요」면 숨김). 그 함수가 받는 캠페인 객체(결과물 조회의 `campaigns:campaign_id (…)` 또는 응모로 따로 받는 `campaigns` 조회 — 두 갈래)에 「판정 칸」이 없으므로 **두 갈래 모두에 더한다** |
| `openAdminProxyModal(presetAppId)`(입구 〔나〕가 응모 id 를 넣어 부르는 경로) | 후보 조회가 **창을 열 때 새로 받은** 「판정 칸」으로(검수 창이 이미 가진 캠페인 객체로 판정하지 않는다 — 검증 4 가 이것에 기댄다) 미리 고른 응모의 캠페인이 닫혔으면 고르지 않고 문구 ② 를 알림으로 띄운다 — **검수 창 버튼이 그려진 뒤 날짜가 넘어간 경우**(창을 연 채 자정이 지남) 버튼은 아직 살아 있어 이 경로로 들어온다 |
| 서버 `admin_create_deliverable_proxy` | 현재 원본 **184** 를 베이스로 **`CREATE OR REPLACE`**(인자 그대로 — 실행 권한 보존). 응모 확인 직후 판정식으로 거부(`proxy_window_closed`) ⚠️ 184 파일 첫머리의 옛 판 `DROP FUNCTION IF EXISTS` 는 **옮겨 오지 않는다**(인자가 같으므로 덮어쓰기만 — 지우면 권한이 풀린다). 끝의 실행 권한 줄은 그대로 둔다. 제출 마감 가드 마이그레이션(274)의 주석에 이 함수의 관리자 면제 서술이 있으니, 새 거부와 어긋나지 않는지 착수 전 대조(규칙 D)에서 본다 |
| 거부 문구 | 화면 오류 안내에 `proxy_window_closed` → 문구 ③ |

### 「올려두고 미제출」

| 자리 | 바꿀 것 |
|---|---|
| 응모 집합 `fetchStalledDraftApplications` | 결과물 행에 캠페인의 「판정 칸」을 붙여 받고, **닫힌 캠페인의 응모는 집합에서 뺀다** → 「올려만 둠」 딱지가 결과물 관리·신청 관리 양쪽에서 함께 사라진다 |
| 건수·안내 창 | **거르는 곳은 `fetchStalledDraftDetails`(`dev/lib/storage.js`) 하나** — 캠페인 조회 칸에 「판정 칸」을 더하고 공용 판정으로 뺀다. 그것을 받아 쓰는 `fetchActionableStalledDrafts`(`dev/js/admin-core.js`)는 고치지 않는다(이미 걸러진 것을 받는다) |

🔴 거르는 곳은 `dev/lib/storage.js` 의 **두 조회 함수**(`fetchStalledDraftApplications`·`fetchStalledDraftDetails`)이고 둘 다 **같은 공용 함수**(P-1)로 거른다 — 한쪽만 고치면 딱지와 건수가 어긋난다(현재 상태 「올려두고 미제출」의 ⚠️ — 조회 함수가 다르다).

## 단계 분할

단계 하나(데이터베이스 1 + 화면). 🔴 **배포는 데이터베이스(서버 함수) 먼저** — 화면만 먼저 나가면 목록·버튼은 막지만 **열어 둔 창이나 직접 호출은 서버가 그대로 받아 기간 뒤 등록이 들어간다**(막겠다고 한 것이 새는 구간). 서버가 먼저면 옛 화면에서 누를 수는 있되 서버가 거부하고 문구가 옛 일반 오류로 뜰 뿐이다(허용 — 몇 분).

## 검증 계획

> **「캠페인을 닫는다」**(이 절의 단일 정의) = 개발서버 SQL 로 그 캠페인의 **기준일 칸**(판정식 — 제출 마감일, 행사 캠페인이고 그것이 비었으면 마지막 방문일)을 **일본 시각 오늘보다 1개월 + 1일 이상 앞 날짜**로 바꾼다. 「당긴다」처럼 양으로 적지 않는다(마감이 먼 미래면 당겨도 안 닫힌다). 대리 등록 후보는 **승인된 응모가 있는 캠페인**만이므로 시험 캠페인은 승인 응모가 있는 것을 고른다.

1. 기준일이 있고 일본 시각 오늘 ≤ 마지막 가능일인 캠페인 → 목록에 보임 · 대리 등록 성공(기준일이 없는 캠페인은 검증 6)
2. 목록 안내 — 전제: **승인된 응모가 있는** 열린 캠페인 1건 이상 + **승인된 응모가 있는** 닫힌 캠페인 1건 이상. ⓐ 검색어 없이 열기 → 열린 것만 보이고 맨 위에 문구 ① ⓑ 닫힌 캠페인에만 맞는 검색어 → 빈 상태 자리에 문구 ① 하나(「일치하는 캠페인 없음」은 안 뜸) ⓒ 열린 캠페인에만 맞는 검색어 → 목록은 보이고 문구 ① 없음 ⓓ 아무것에도 안 맞는 검색어 → 「일치하는 캠페인 없음」
3. **경계일**(화면·서버 둘 다) — 시험 전에 개발서버 SQL 로 `((오늘 − 1개월) + interval '1 month')::date = 일본 시각 오늘` 인지 먼저 확인한다(말일 맞춤 때문에 29~31일에는 성립하지 않을 수 있다 — 그날이면 다른 날 시험). 성립하면 기준일 칸을 ⓐ **오늘 − 1개월**(마지막 가능일 = 오늘) → 목록에 보임 · 검수 창 버튼 살아 있음 · 등록 성공 ⓑ **오늘 − 1개월 − 1일** → 목록에서 빠짐 · 검수 창 버튼 회색 + 문구 ② · 서버 직접 호출도 거부. **말일 맞춤**은 계산만 확인한다 — 서버 `('2027-01-31'::date + interval '1 month')::date` = 2027-02-28, 화면(관리자 앱 개발서버 콘솔) `proxyWindowLastDate({ submission_end: '2027-01-31' })` = `'2027-02-28'` · 윤년: 서버 `('2028-01-31'::date + interval '1 month')::date` = 2028-02-29, 화면 `proxyWindowLastDate({ submission_end: '2028-01-31' })` = `'2028-02-29'`
4. 검수 창 버튼 — 닫힌 캠페인의 응모에서 회색 + 문구 ② · **열린 캠페인 응모의 검수 창을 연 채** 그 캠페인을 닫은 뒤(위 정의) 버튼을 누름 → 창이 열리되 응모가 골라지지 않고 문구 ② 알림
5. 대리 등록 창을 연 채 그 캠페인을 닫은 뒤(위 정의) 저장 → 서버가 `proxy_window_closed` 로 거부하고 **화면에 문구 ③** · 같은 응모로 서버 함수를 직접 호출 → 같은 거부
6. 기준일이 없는 캠페인 → 제한 없음 · 제출 마감일은 없고 마지막 방문일은 있는 행사 캠페인 → 마지막 방문일 기준으로 제한됨
7. 닫힌 캠페인의 대리 결과물 회수 → 그대로 됨(P-5)
8. 「올려만 둠」 — 기간 안에서 **건수에 잡히는 응모**(승인 + 인증 상태 「미제출」 또는 「인증샷 제출중」 + 임시저장 있음)를 먼저 확인하고, 그 캠페인을 닫은 뒤(위 정의) 다시 본다 → 딱지가 결과물 관리·신청 관리 **둘 다**에서 사라지고 안내 창 건수에서도 빠진다 · 다른 열린 캠페인의 같은 경우는 그대로 · 임시저장 행은 데이터베이스에 남아 있음 · 제출 마감일은 없고 마지막 방문일이 있는 행사 캠페인 한 건도 같은 방법으로(마지막 방문일 기준으로 사라지는지)
9. 캠페인 매니저 계정 — 입구 〔나〕(검수 창 버튼)는 지금처럼 안 보이고, 입구 〔가〕(머리 버튼)는 지금처럼 보이되 저장하면 권한 오류(둘 다 변경 없음 확인). 「올려만 둠」 딱지·건수는 캠페인 관리자 이상 계정과 같은 기간 기준으로 사라진다
