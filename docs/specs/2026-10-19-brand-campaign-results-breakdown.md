## 의심·경우의 수 (반대론자)

1. **(데이터·되돌릴 수 없음) 「공개 주소 닫기」는 공개 통의 사본을 지우는 일이다.**
   - 저장소 정책으로는 공개 링크를 막지 못한다(474). 닫는 방법은 공개 통의 영수증 파일(+`thumb/` 사본) 삭제뿐이다(D1 — 영수증 줄이 가리키는 파일만).
   - 복사 검증이 틀린 채 지우면 영수증 사진이 영구히 사라진다.
   - → 조각 20 은 「건수·용량 대조 + 경로 변환 0건 남음 + 표본 열람」을 통과해야만 한다. 지우기 전 원본 목록을 따로 보관한다.
2. **(기술 — 조용한 실패 셋) 저장 형식이 주소 → 경로로 바뀌면 오류 없이 멈추는 자리가 있다.**
   - ①`_receiptUrlToStoragePath` 가 `null` 을 돌려줘서, 캠페인 보관 삭제와 감사용 청소가 **파일을 안 지우고 「완료」** 한다.
   - ②364 정규식이 경로를 그대로 돌려주는데 서버 함수는 여전히 `campaign-images` 에서 지운다. 저장소는 없는 파일 삭제도 성공으로 답해서, 주소 칸만 비고 비공개 통에 개인정보가 영구히 남는다.
   - ③관리자 엑셀의 `getPublicUrl` 갈래가 열리지 않는 주소를 싣는다.
   - → 조각 6 이 셋을 한 헬퍼로 묶는다. 조각 6 완료 정의에 「일부러 지울 대상을 만들어 실제 파일이 사라지는지」를 넣는다.
3. **(권한·환경) 업로드 전환(조각 7)을 출시 전에 운영에 내면 공유 링크가 깨진다.**
   - 비로그인 공유 화면은 서명을 못 하므로 새 영수증이 깨진 사진이 된다.
   - → 업로드 전환은 **공유를 닫은 뒤**(출시 날)로 묶는다. 읽는 쪽 이중 지원(조각 6)만 먼저 나간다.
4. **(UX) 세 숫자가 서로, 그리고 표와 안 맞아 보인다.**
   - 제출 = 임시저장 제외 전부(반려 포함) · 검수 완료 = 승인 · 검수 대기 = 검수 중이다. 그래서 「제출 10 · 완료 6 · 대기 2」에서 반려 2건이 어디에도 안 보인다.
   - 표는 사람 기준이라 줄 수와도 다르다. 영수증을 다시 내면 새 줄이 생겨 「건」이 부푼다(S10).
   - → ~~「건 기준 · 반려 건은 제출에만 포함」~~ → 🔄 피그마 확정 문구 「세 숫자는 결과물 「건」 기준이라 아래 표의 사람 수와 다를 수 있습니다」(bw05-01a·01e·01f). 반려 건 설명은 **피그마가 뺐다**(의도 — 세 숫자 뜻은 제출·검수 완료·검수 대기 이름으로 읽힌다고 봄). 반려가 보이지 않는 문제는 남는다 — 문의가 오면 다시 본다
5. **(UX) 임시 주소 만료.** 화면을 1시간 넘게 열어 두면 「열기」와 사진이 오류 문구 없이 깨진다. → ~~만료되면 그 캠페인 결과를 다시 받는다~~ → 🔄 「열기」 때마다 새로 받는다(S26·조각 5b — 피그마 bw05-04). 표 자체는 서명 주소를 들고 있지 않아 만료가 없다
6. **(데이터·개인정보) 공개를 켠 뒤 새로 생기는 열은 기본 켜짐이다.**
   - `reportShareColOff` 는 새 열쇠를 「`-열쇠` 가 없으면 켜짐」으로 본다.
   - 그래서 관리자가 나중에 틱톡 채널을 더하면 **틱톡 계정 열이 브랜드에게 바로 보인다.** 사양서 「기본값에 넣지 않은 열은 관리자가 골라야 보인다」와 어긋난다.
   - → S19.
7. **(기술) 캠페인 표에 공개 칸을 두면 가짜 충돌이 생긴다.**
   - 공개를 켤 때마다 `version` 이 올라, 편집 폼을 열어 둔 관리자가 「다른 사람이 수정」 충돌을 본다. 변경 이력 세 곳도 맞춰야 한다.
   - → 별도 표로 둔다(조각 1).
8. **(권한) 브랜드를 바꾸거나 병합하면 공개 결과가 즉시 새 브랜드로 간다.**
   - 편집 폼의 브랜드 변경 확인 창은 이 사실을 말하지 않는다.
   - → 조각 10 이 확인 창 문구에 한 줄을 더한다.
9. **(법률) 외부 줄(다른 서비스 회원)을 브랜드에 보이는 근거가 미정이다**(16-5 15번). 개발은 진행하되 출시 날 ①(4·14 — 브랜드가 외부 줄을 보기 시작)의 운영 반영은 막힌다(S1 — 확인은 ⓪).
10. **(기술) 공유 화면의 표 칸·엑셀 코드가 브랜드 쪽에 한 벌 더 생긴다.**
    - `report.html` 의 `chanCell`·`rowHtml`·`downloadExcel` 은 `report-rows.js` 밖에 있다.
    - 열·줄·끈 열 판정은 원본 하나를 쓰지만, 그리는 코드는 출시 날 `report.html` 이 닫힐 때까지 두 벌이다.
11. **(성능) 서명 주소는 요청마다 달라 브라우저 보관이 안 먹는다.**
    - 수백 줄 목록은 서명 요청이 몰린다. 운영 데이터베이스는 가장 작은 사양이다.
    - → 관리자 목록(조각 6 — 화면이 직접 서명)은 그릴 때 보이는 줄만 묶어서 서명하고 화면 메모리에 보관한다. 브랜드 화면은 🔄 「열기」 때 그 영수증 하나만 서명받는다(S26·조각 5b — `view` 는 서명하지 않으므로 표를 그릴 때 서버 쪽 서명도 0번) · 엑셀은 캠페인 단위로 한 번(조각 5 `excel`).

**현재 구현과 충돌하는 지점**
- 공유 판정이 리포트 토큰 기준이다. 🔴 `DROP` 금지라, 본체를 꺼내고 `CREATE OR REPLACE` 로 감싼다.
- 외부 파일 표가 `report_id NOT NULL` 이다.
- 인증샷이 영수증 폴더에 섞여 있다.
- `saveBrandDetail` 이 폼을 통째로 저장한다.
- 행사 「비공개」 배지와 낱말이 겹친다.

**의도가 모호한 점:** 리뷰 인증샷도 비공개 대상인가(S12 → D1 영수증만) · 「건」의 단위(S10) · 「업데이트 시각」의 뜻(S9) · 결과물 영역이 종료 캠페인 전용인가(S15).

**권고**
- 서버 판정 본체를 한 번 꺼내 공유 화면과 브랜드 화면이 같이 쓰게 한다(조각 2).
- 영수증 이전은 이 순서로만 진행한다: 읽는 쪽 이중 지원 → 출시 날 공유 닫기 → 업로드 전환 → 복사·변환 → 공개 사본 삭제.
- 기록용 캠페인(⑥)은 영향 자리가 넓어 별도 작업표로 뗀다(S17).

## ⚠️ 사양서 stale 점검

1. **피그마 bw05-01 설명에 옛 문구가 남아 있다.** 「여러 리포트 중 공유 켜진 최근 것」은 2026-10-15 결정으로 없어졌다. 지금은 **캠페인마다 「브랜드 공개」 하나**다. 화면의 「결과물 숫자는 리포트가 공유되면 보입니다」도 같다(기획 몫).
2. **「상태」 열 넷 중 「검수 불필요」는 브랜드 표에 나올 수 없다.** 이 낱말은 신청 반려·취소 때만 나오는데, 그 줄은 서버가 응답에서 뺀다. 실제로는 셋만 보인다.
3. **「미제출」의 뜻이 사양서와 코드가 다르다.**
   - 사양서는 「채널별 결과물 칸 중 아직 안 낸 항목이 있다」로 정의한다.
   - 코드(`_excelCertStatusKo` 등)는 「아무것도 안 냈다」이고, 일부만 낸 사람은 「인증샷 제출중」이다.
   - 판정은 바꾸지 않고 사양서 문장을 코드에 맞출 것을 권한다(기획 확인).
4. **「영수증 사진 비공개 이전」 ④(함께 바뀌는 자리)에 빠진 곳**
   - 관리자 일일 메일 링크
   - 「영수증에서 읽기」
   - 캠페인 보관 삭제·감사용 청소의 경로 변환
   - 탈퇴 파기 정규식(364)·통 상수(`purge-withdrawal-media`)
   - 진행현황 결과물 탭 표
   - 관리자 엑셀 이미지 끼워 넣기
5. **사양서는 「영수증 사진」만 말하지만, 회원 리뷰 인증샷이 같은 `receipts/` 폴더에 있다**(S12).
6. **사양서 화면 표의 「01a 종료 캠페인 결과물」이 §4 ④(공개 스위치만)와 다르게 읽힌다**(S15).
7. **「구매」 식이 지금 두 화면에서 다르다.** 「같은 판정」이라는 전제가 이미 깨져 있다(S6).
8. **16-5 15번 ① 「권한은 지금 리포트 첨부와 같은 등급」의 열쇠말이 `menu.reports` 쓰기다.** 브랜드 공개의 `report.share` 와 다른 열쇠말이다(S20).
9. **권한 카탈로그 이름 「리포트 공유 링크」**는 출시 뒤 공유 링크가 없어져도 그 열쇠말이 브랜드 공개를 지킨다. 이름을 바꿀지 정해야 한다(낱말 전파 — 권한 관리 화면).
10. **사양서 ③의 「경로로 바꾸는 자료 변환」이 썸네일 사본(`thumb/`) 복사를 말하지 않는다.** 빠뜨리면 목록 썸네일이 전부 원본으로 떨어진다.

## 조각별 상세

### 조각 1. 브랜드 공개 설정·기본 열 서버 (새 마이그레이션 A)
- **하는 일:** 표 셋과 관리자 함수를 만든다 — 캠페인마다 공개 켜짐·꺼짐과 열 목록, 전체 기본값, 브랜드 기본값. 적용만으로 바뀌는 기존 동작은 없다.
- **산출 계약**
  - **표**
    - `campaign_brand_publish(campaign_id uuid PK → campaigns ON DELETE CASCADE, enabled boolean NOT NULL DEFAULT false, columns jsonb NULL, version int NOT NULL DEFAULT 1, updated_at, updated_by, first_enabled_at)`. 🔴 **캠페인 표에 칸을 두지 않는다**(의심 7). 캠페인 복제는 이 줄을 복사하지 않는다(처음 꺼짐).
    - `brand_publish_default_global(id=1, spec jsonb)` · `brand_publish_default_by_brand(brand_id PK → brands ON DELETE CASCADE, spec jsonb)`. 브랜드 줄이 없으면 전체를 따른다. 🔴 `merge_brands`(528)는 손대지 않는다.
  - **기본 열 명세 `spec`:** 늘 있는 열의 열쇠(계정 ID 제외) + 종류 열쇠 `kind:acct`·`kind:url`·`kind:at`(캠페인에 따라 생기는 채널 + 「기타」).
  - **함수**(모두 정의자 권한, `search_path=''`. 읽기는 `is_admin()`, 쓰기는 `has_permission('report.share','write')`)
    - `admin_get_campaign_brand_publish(p_campaign_id)` → `{enabled, columns, version, default_spec, default_source:'brand'|'global'}`. 🔴 어느 기본값(브랜드·전체)을 쓸지는 서버가 정한다 — 그 명세를 그 캠페인 열의 체크로 펼치는 일은 화면이 한다(조각 9·13 `reportDefaultCheckedKeys`).
    - `admin_set_campaign_brand_publish(p_campaign_id, p_enabled, p_columns, p_expected_version)` — 낙관적 잠금, 충돌이면 `-1`.
    - `admin_get_brand_publish_states(p_campaign_ids uuid[])` → `{campaign_id: enabled}`
    - `admin_get_brand_publish_defaults(p_brand_id)` → `{global_spec, brand_spec}`(따로 정하지 않은 브랜드면 `brand_spec` 은 `null`) — 기준 데이터 탭·브랜드 칸(조각 11)용
    - `admin_get_publish_default_for_campaigns(p_campaign_ids uuid[])` → `{spec, source:'brand'|'global'}` — 🔴 서버가 고른다: 담긴 캠페인이 모두 한 브랜드이고 그 브랜드가 따로 정했으면 그 값, 아니면(여러 브랜드·브랜드 없는 캠페인 포함) 전체 기본값. 리포트 엑셀(조각 17)용
    - `admin_set_brand_publish_default_global(p_spec)`
    - `admin_set_brand_publish_default_brand(p_brand_id, p_spec)` — `NULL` 이면 「전체 기본값 따르기」(줄 삭제).
  - **실행 권한:** `authenticated`·`service_role` 만(PUBLIC·`anon` 회수 둘 다).
- **선행:** 없음
- **완료 정의:** 실제 로그인한 브라우저 콘솔에서 확인한다.
  - 함수마다 1회 호출이 성공한다.
  - 매니저 계정의 쓰기는 `42501`, 캠페인 관리자의 쓰기는 성공이다.
  - `default_source` 가 브랜드 줄 유무에 따라 갈린다.
  - 공개를 켜도 `campaigns.version` 이 그대로다.
- **필요 검문소:** `reverb-supabase-expert`(권한 회수 두 방향) · `reverb-reviewer`
- **주의·롤백:**
  - 표·함수를 `DROP` 하면 된다. 화면 조각 9~11 을 먼저 되돌린다.
  - 공개 설정 변경 이력은 `updated_by`·`first_enabled_at` 만 남긴다(개발 기본값).

### 조각 2. 결과물 판정 본체 꺼내기 + §17 두 가지 (새 마이그레이션 B)
- **하는 일**
  - 491 본문을 내부 함수로 옮긴다. 이 함수는 캠페인 배열·열 목록·감사용 포함 여부를 받는다.
  - `get_report_share_data` 는 「토큰 → 리포트 → 캠페인 배열」만 하고 내부 함수를 부른다(539 `_orient_*_core` 선례).
  - §17 두 가지를 고친다: ①회원 응답에서 `is_audit` 칸을 뺀다. ②「또는」 캠페인에서 회원별 채널 집합을 **그 회원이 실제로 게시한 채널**로만 잡는다.
- **산출 계약**
  - `_results_payload_core(p_campaign_ids uuid[], p_cols jsonb, p_include_audit boolean) RETURNS jsonb` → `{campaign_rows, deliverables, users}`. 끈 열 비우기는 기존 두 함수를 그대로 부른다(새 사본 금지).
  - `_results_ext_rows(p_source_ids uuid[], p_cols jsonb, p_for_brand boolean)` — `p_for_brand` 면 `member_no` 를 싣지 않는다.
  - `get_report_share_data(uuid, text)` — 🔴 `CREATE OR REPLACE`, 인자·반환은 그대로.
  - 내부 둘은 PUBLIC·`anon`·`authenticated` 셋 다 회수한다(회수 방향 둘 — 조각 1 과 같다).
- **선행:** 1(같은 세션 순서일 뿐, 실제 의존은 없다)
- **완료 정의**
  - 공유 화면이 §17 두 항목(아래) 외에는 전과 같은 표를 그린다.
  - 응답 `users` 에 `is_audit` 이 없다.
  - 「또는」 캠페인에서 인스타만 낸 회원의 틱톡 계정이 `null` 이다.

### 조각 8. 기존 파일 복사·경로 변환 도구

### D1 반영 — 「영수증만」이 바꾸는 것 (S12 개발 기본값 「포함」을 대신한다)

- **조각별로 바뀌는 것**
  - **조각 5:** 서명은 영수증 칸에만 한다. 리뷰 이미지 주소는 공개 주소 그대로 통과한다.

  - **조각 7:** 비공개 통으로 올리는 것은 영수증 업로드(회원 2578 · 관리자 대리 2843)뿐이다. 인증샷 업로드(회원 2626 · 관리자 2877)는 지금처럼 공개 통이다.
  - **조각 8:** 복사·변환 대상은 `kind='receipt'` 줄의 파일 목록이다. 🔴 같은 파일을 다른 줄(리뷰 이미지)이 가리키는지 확인한 뒤 옮긴다.
  - **조각 20:** 지우는 대상도 그 목록뿐이다. 폴더째 지우면 인증샷이 사라진다.
