## 0. 한 줄 정의

회원 앱에서 **이미 가장 많이 쓰이는 부품을 기준으로 공용 부품 다섯 가지**(단추 · 상태 안내 셋 · 팝업 둘 · 글자 크기 5단계 · 화면 머리)를 **회원 앱 전용 스타일 파일** 한 곳에 정의하고, 화면을 **하나씩 통째로** 그 부품으로 옮긴다.

## 2. 의심·경우의 수 (규칙 B)

1. **(기술) 관리자 화면이 같이 바뀐다** — §1-1. 전용 파일을 두지 않고 공유 파일을 고치면 관리자 표·단추가 한꺼번에 커진다. → §3-0 구조가 이 사양서의 전제다.
2. **(UX) 본문 14 → 15 로 카드·목록 글이 잘린다** — 캠페인 카드 제목처럼 줄 수를 제한한 자리는 글자가 커지면 말줄임표가 더 빨리 붙는다. → 화면 조각마다 「줄 수 제한 자리」를 캡처로 확인하는 것을 완료 정의에 넣는다.
3. **(UX) 화면을 하나씩 옮기는 동안 화면끼리 다르게 보이는 기간**이 생긴다. 지금보다 나쁘지는 않지만 회원이 「바뀌었다」고 느낀다. → 화면 통째 단위로만 내보내고, 자주 쓰는 화면부터(§4).
4. **(기술) 인라인 스타일이 전용 파일보다 이긴다** — 캠페인 상세는 스타일이 거의 전부 인라인(`application.js` 201개)이라 전용 파일에서 `#page-detail .btn{min-height:44px}` 를 줘도 인라인 `padding` 이 섞인 단추는 모양이 어긋난다. → 화면 조각은 **인라인 스타일을 걷어내고 부품 클래스로 바꾸는 일**이 본체다(전용 파일만 추가하고 끝내면 효과가 절반).
5. **(데이터·동작) 부품만 바꿨는데 저장이 흔들린다** — 마이페이지 폼은 입력칸 `id` 로 값을 읽는다. 감싸는 틀을 바꾸다 `id` 를 잃으면 저장이 조용히 빈 값이 된다. → 폼 화면 조각은 「저장 → 다시 열어 값 확인」을 완료 정의에 넣는다.
6. **(UX) 44px 단추가 목록 행에서 너무 크다** — 응모이력·활동관리 행 안 보조 단추. → 결정대로 **보이는 크기는 작게, 누르는 영역만 44**(§3-1).
7. **(접근성) 팝업 닫기를 아이콘 하나로 통일하면** 「✕」 글자만 쓰던 곳의 화면 읽기 이름이 빠질 수 있다. → 닫기 단추에 `aria-label` 필수.

**현재 구현 충돌점:** §1-3 다섯 가지. 그 밖 충돌 없음.

**의도 모호점**
- 「스타일 통일」에 **글꼴 변경(Noto Sans → 시스템 글꼴)** 은 넣지 않는다 — 일본어·한국어 글자 모양이 기기마다 달라지는 큰 변화라 이번 결정 네 가지에 없다. 필요하면 별도 결정.
- 「색 통일」은 **같은 뜻에 서로 다른 값**(빨강 7종 등)을 변수로 모으는 것까지다. 색 자체를 새로 정하지 않는다(2026-07-16 무채색 리디자인 기준 유지).

## 3. 설계

### 3-0. 회원 앱 전용 스타일 파일

- 새 파일 **`dev/css/member-ui.css`** 를 `CLIENT_CSS_FILES` **맨 끝**에 추가한다(`dev/build.sh` 26행 한 줄 — 관리자 목록에는 넣지 않는다). 뒤에 이어 붙으므로 같은 선택자면 이 파일이 이긴다.
- 이 파일에만 둔다: ①글자 크기·누름 영역·팝업 모서리 변수 ②공유 부품(`.btn`·본문 글자)의 **회원 앱용 덮어쓰기** ③새 공용 부품(상태 안내 셋·팝업 둘·`.tap-44`·`.back-link`).
- 🔴 **덮어쓰기는 전역으로 걸지 않고 화면별로 건다** — `#page-detail .btn{…}`·`#page-detail{font-size:var(--fs-body)}` 처럼 **그 화면 조각이 자기 화면 선택자를 목록에 더한다.** 전역(`.btn`·`body`)으로 걸면 아직 인라인을 안 걷어낸 화면에 「덮어쓴 단추 + 인라인 단추」가 섞여 상위 규칙(화면 통째 — 섞이면 통일 전보다 나쁘다)을 깬다. 마지막 조각(6)이 끝나면 화면별 선택자를 전역 한 줄로 합친다.
- ⚠️ `base.css`·`components.css`·`ui.js` 의 **기존 값은 고치지 않는다**(관리자 영향). 새 헬퍼 함수를 `ui.js` 에 더하는 것은 괜찮다(관리자가 안 부르면 영향 없음).

### 3-1. 단추 — 44픽셀

```
/* 화면 조각이 자기 선택자를 앞에 붙인다 — 예: #page-detail .btn{…} (§3-0) */
.btn{min-height:44px}                         /* 기본·btn-sm — 보이는 높이 44 */
.btn-xs{min-height:32px;position:relative}    /* 목록 안 보조 — 보이는 높이 32 */
.btn-xs::after{content:'';position:absolute;inset:-6px 0}   /* 누르는 영역을 위아래 6씩 넓혀 44 */
```
- 인라인으로 46·48·50 을 준 자리는 인라인을 걷어낸다.
- 아이콘만 있는 작은 단추(닫기·넘김 화살표·뒤로)도 같은 방식으로 누르는 영역 44(`.tap-44` 도우미 클래스 — 이름 제안).

### 3-2. 상태 안내 — 세 가지를 다른 모양으로

| 부품 | 모양 | 헬퍼(제안, `ui.js`) |
|---|---|---|
| `.state-empty` | 기존 `.empty-state` 모양을 이름만 공용으로 — 제목은 16 → **17 로 바꾼다**(5단계), 아이콘 48·부제 13, 위아래 64 → 40 | `stateEmptyHtml(icon, title, sub)` |
| `.state-loading` | 돌아가는 표시 + 13px 문구(「読み込み中…」 — "불러오는 중") | `stateLoadingHtml(text)` |
| `.state-error` | 경고 아이콘(`--red`) + 15px 문구 + 「もう一度読み込む」("다시 불러오기") 단추 | `stateErrorHtml(text, retryFnName)` |

- 🔴 **조회 실패(`null`)는 반드시 `.state-error`**, 0건(`[]`)은 `.state-empty` — 저장소 원칙(마이그레이션 276)을 화면 모양으로도 가른다. 지금 `msg-empty`·`notif-empty` 가 셋을 한 모양으로 그리는 것이 이 사양서가 고치는 핵심 결함이다.
- 말줄임표는 「…」 하나로(지금 「…」·「...」 혼재 — 번역 파일 `ja.js` 97·229·319·394·920).
- 헬퍼는 공유 `ui.js` 에 두지만 **클래스는 회원 전용 파일에만** 있다 — 관리자 화면에서 부르면 스타일 없이 그려지므로 관리자 코드는 쓰지 않는다.
- 헬퍼는 **글자를 `esc()` 로 이스케이프**한다(`retryFnName` 은 코드가 넣는 고정 이름만 — 사용자 입력 금지).

### 3-3. 팝업 — 두 종류

| 종류 | 쓰는 곳 | 모양 |
|---|---|---|
| **아래에서 올라오는 창** `.sheet` | 내용이 긴 것 — 응모·약관·정책 통지·알림 | 위 모서리 20, 머리 = 17px 제목 + 오른쪽 위 닫기 |
| **가운데 창** `.dialog` | 짧은 확인·경고 — 동작 선택·주의사항 비교·취소 상세·알림창·프로필 부족·나이 확인 | 모서리 20, 머리 = 17px 제목. **확인창은 닫기 대신 「キャンセル」("취소") 단추** |

- 닫기 = **`close` 아이콘 단추 하나**(아이콘 24, 누르는 영역 44, `aria-label` 필수). 「✕」·「×」 글자, `div` 닫기는 없앤다.
- 기존 `.modal-overlay`(배경·z-index 500)는 그대로 쓰고 안쪽 상자만 두 클래스로. z-index 를 새로 정하지 않는다(ESC 닫기 등 기존 처리에 기댄다).

### 3-4. 글자 크기 — 5단계

```
--fs-caption:11px  --fs-desc:13px  --fs-body:15px  --fs-subtitle:17px  --fs-title:20px
#page-detail{font-size:var(--fs-body)}   /* 화면 조각마다 자기 화면에만(§3-0). 마지막 조각 뒤 body 한 줄로 합친다 */
```
- 5단계는 **입력칸을 뺀 글자**에 적용한다. 입력칸(`input`·`select`·`textarea`)은 **16px 고정**(모바일 확대 규칙 — 5단계 밖의 별도 값). 응모이력 선택칸 12·13px 4곳은 16 으로.
- 옮기는 방향(입력칸 제외): 9·10 → 11 / 12 → **뜻으로** 고른다 — 보조·꼬리표 11, 설명 13 / 14 → 15 / 16 → 15(본문) 또는 17(소제목) — 뜻으로 / 18 → 17.

### 3-5. 화면 머리 · 색 · 모서리

- (색·모서리·되돌아가기 링크는 **각 화면 조각이 자기 화면에서** 적용한다 — 이 항목들 중 조각 0 은 `.back-link` 부품만 정의. 단 결함 1(`var(--text)` 13곳)은 깨진 색을 고치는 것이라 조각 0 — §3-6)
- **화면 머리**: 햄버거에서 들어가는 화면 = `mypage-sub-header`. 목록에서 들어가는 **깊은 화면**(캠페인 상세·활동관리·응모 취소)은 지금처럼 「← 되돌아가기」 링크를 두되 **한 부품**으로 — `.back-link`(`<button>`, 누르는 영역 44, 화살표 24, 글자 13)로 4곳을 통일(응모 취소 `index.html:601` · 캠페인 상세 658 · 활동관리 668 · 문의하기 응모 고르기 `messaging.js:357` — 입장 티켓 648 은 결함 2 로 `mypage-sub-header` 가 된다). 대화 화면(메시지)은 `msg-modal-header` 그대로.
- **색**: `var(--text)` 13곳은 결함 1 로 조각 0 에서 처리(§3-6). 같은 뜻 다른 값은 `--red`·`--gold`·`--green`·`--blue`(+`-l`)·`--muted` 로. 예비값 흔적(`var(--pink,#e84a7f)` 등)은 예비값을 지운다.
- **카드 모서리**: 12(`--r12`) 하나. 로그인 카드 24·이메일 설정 8 등은 12 로.

### 3-6. 결함 5건 (결정 불필요 — 1·3·4·5 는 조각 0, 2 는 조각 6)

1. `var(--text)` 미정의 13곳(`mypage.css` 12·`index.html:862`) → `var(--ink)`
2. **입장 티켓 화면 머리**(`index.html:648`)가 햄버거 화면인데 `detail-back` — `mypage-sub-header` 로(일반 문의 작업표 조각 5-C 와 같은 처리). ⚠️ 이것은 모양 변경이라 **조각 0 이 아니라 조각 6**(입장 티켓 화면 통째)에서 한다
