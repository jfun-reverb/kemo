# 오리엔시트 견적 — 구간 이름·옵션 문구를 관리자가 고친다

**작성일:** 2026-09-21 · **작성:** 기획 세션
**계기:** 사용자 결정(2026-09-21, 개발 세션 선택형 질문)
1. 구간 **이름**은 **리뷰어·시딩 따로**(구간 인원과 같은 구조)
2. 브랜드 폼 **맨 끝 단추도 이름으로 통일** — 지금은 이름 자리에 인원(「500건」)이 들어가 있다. 다른 단추처럼 **이름 + 인원** 모양으로
3. **구간마다 「옵션」 문구**를 넣을 수 있게 — 지금 맨 끝 단추의 「(+실검작업)」 같은 설명 자리를 다섯 구간 모두에

**처음 넣어 둘 값:** 사용자 결정(2026-09-21, 이 기획 세션) — 맨 끝 구간 이름 **「프리미엄+」**, 옵션 **「+실검작업」**. 나머지 넷은 지금 이름(소량·라이트·스탠다드·프리미엄), 옵션은 비움.

> 상위: `docs/specs/2026-09-21-orient-tier-slots-per-form.md`(구간 인원 형식별, 460·461) · `docs/specs/2026-09-21-orient-tier-direct-input.md`(구간 다섯, 458·459)
> 🔴 **이 사양서는 상위 사양서의 「구간 이름은 공통」을 뒤집는다**(2026-09-21 사용자 결정 1). 열쇠(`tmin`·`t50`·`t100`·`t300`·`t500plus`)와 구간 **개수**는 그대로 공통이다.

---

## 0. 한 줄 요약

구간 이름·옵션 문구를 담을 **새 표 하나**(형식 2 × 구간 5 = 10행)를 만들고, 관리자 「견적 기준값」 구간표에 **이름·옵션 칸**을 더한다. 서버는 그 값을 **폼용 단가 조회 응답**과 **견적 줄 이름**에 싣는다. 글자로 박힌 이름 사본 넷(서버 계산식·작성 폼·관리자 상세·기준값 화면)은 **그 표를 읽는 쪽으로** 바꾼다. ⚠️ **기본 이름**은 세 곳에 남는다 — 서버 계산식(그 행이 없을 때) · 작성 폼(응답에 이름이 없을 때 — 주로 옛 서버, 키 빠짐은 방어 · 응답을 아예 못 받았을 때는 확인 화면만, §3-5) · 관리자 상세(조회 실패나 행 없음, §3-7 3단계). §3-1 시드와 **글자 그대로 같게** 유지한다. 옵션 기본값(맨 끝 「+실검작업」)은 작성 폼 **한 곳**에만 남는다.

⚠️ **지금 이미 넷이 서로 다른 말을 한다** — 맨 끝 구간이 서버 견적 줄 「500건」 / 폼 단추 「500건 (+실검작업)」 / 관리자 상세 「실검작업 구간」 / 기준값 화면 「실검작업」. 이 사양서가 넷을 한 표로 모으면 이 어긋남도 함께 사라진다(단 이 변경 전에 제출된 견적은 예외 — §3-6·§3-7).

⚠️ 「옵션」에 해당하는 것은 지금 **맨 끝 단추의 `sub` 하나**뿐이다. 나머지 넷의 `sub` 자리에는 **인원(「150건」)** 이 들어간다 — 즉 지금 `sub` 는 「인원」과 「설명」 두 뜻을 겸한다.

### 1-2. 이름·옵션을 담을 자리가 없다

- `quote_settings.amount` 는 `numeric` 이라 글자를 못 담는다(426). 이력 표 `quote_settings_history` 도 `prev_amount`/`next_amount` 숫자 칸뿐이다.
- 저장 함수 `update_quote_setting(text, numeric)`(현재 원본 461)도 숫자 전용이다.

### 1-3. 폼이 받는 응답

`get_orient_tier_fees`(현재 원본 **461**)가 `{ fees, slots, min_slots, override_krw, form_type, channel }` 를 준다. 폼은 이 응답을 받은 뒤에만 단추 줄을 보인다(`tierSlotsReady`, orient.html:966 — 상위 사양서 §3-6).

### 1-4. 「실검작업」 견적 줄은 이름과 별개의 계산 규칙이다

`_orient_compute_quote` 는 구간이 `t500plus` 이면 **형식과 무관하게** 「실검작업 — 담당자 협의」 줄(값 없음·합계 제외)을 붙인다(461:353-358). 이것은 **이름·옵션 문구와 무관한 계산 규칙**이다.

### 1-5. 이 기능 전체(442~461)는 운영 미배포

받은 브랜드 0. 개발 DB 의 제출된 견적 스냅샷(`data.quote.lines[].label`)에는 옛 이름이 글자로 남아 있다(§3-6).

### 1-6. 충돌 가능 동작

- 없음 — 5개 영역 확인(메일·엑셀·Edge Function 에 구간 이름 0건 / 옛 구조 시트는 구간 개념 없음(상위 사양서 §1-3) / 캠페인 발행 자동 채움은 `slots_tier` 를 안 옮긴다).
- 참고: orient.html:911 주석은 「실검작업은 **리뷰어** 견적의 줄 이름」이라 적혀 있으나 서버는 형식과 무관하게 붙인다(443·461:353). **주석 쪽이 틀렸다** — 이번에 함께 고친다(§3-5).

## 2. 의심·경우의 수 (규칙 B)

### 2-1. 깨질 수 있는 경우

1. **(보안) 관리자 입력 글자가 비로그인 브랜드 화면에 그대로 뜬다** — 지금 단추 마크업은 `${t.name}`·`${t.sub}` 를 **이스케이프 없이** 넣는다(orient.html:1883). 지금은 코드 상수라 안전했지만, 관리자가 입력하는 값이 되는 순간 **저장형 교차 사이트 스크립팅(XSS)** 통로가 된다. → 이 값이 그려지는 **세 화면**(작성 폼·기준값 화면·오리엔시트 상세) 모두 **글자로만** 넣는다(§3-5·§3-7). 작성 폼 안에서 새로 막아야 하는 자리는 **단추 하나**다 — 확인 화면(`tierDisplay` → `pvRow`, orient.html:2935)과 견적서 줄 이름(orient.html:3257 · 관리자 끼워 넣기 admin-orient.js:1152)은 **이미 이스케이프해서** 그린다(2026-09-21 확인). 직접입력 옆 줄은 `textContent` 다. 서버도 태그 문자를 거부한다(§3-2).
2. **(UX) 이름을 비우거나 길게 쓰면 단추가 깨진다** — 단추 넷이 모바일 한 줄(480픽셀)에 나란하고 이름은 줄바꿈이 없다(`.tier-name { white-space: nowrap }`, orient.html:411). → 이름 **1~8자 필수**, 옵션 **0~16자**(비움 허용), 옵션은 줄바꿈 허용(§3-2·§3-5).
3. **(UX) 옵션을 지워도 「실검작업」 줄은 계속 붙는다** — 관리자가 맨 끝 옵션 「+실검작업」을 지우면 브랜드는 안내를 못 보는데 견적서에는 그 줄이 나온다. 반대로 다른 구간 옵션에 「+실검작업」을 적어도 그 구간 견적에는 줄이 안 붙는다. → **옵션은 표시용 문구일 뿐 계산을 바꾸지 않는다**는 사실을 기준값 화면에 적어 둔다(§3-7). 계산 규칙은 이번에 안 바꾼다.
4. **(데이터) 제출 뒤 이름을 바꾸면** — 견적서 줄은 제출 때 이름(스냅샷), 관리자 상세 「모집 구간」은 지금 이름이 되어 **한 시트 안에서 두 이름**이 보인다. → 견적 스냅샷에 구간 이름을 함께 남기고, 관리자 상세는 **스냅샷이 있으면 그 이름**을 쓴다(§3-3·§3-6). 단 이 변경 전에 제출된 견적은 스냅샷에 이름이 없어 어긋날 수 있다 — 개발 DB 시험 시트뿐이라 감수(§3-7).
5. **(동시성) 두 관리자가 같은 칸을 동시에 고치면** — 마지막 저장이 이긴다. 숫자 기준값(`update_quote_setting`)도 같은 규칙이고 이력이 남으므로 맞춘다.
6. **(권한) 캠페인 매니저** — 숫자 기준값과 같게 **수정은 캠페인 관리자 이상**(`is_campaign_admin()`), 읽기는 관리자 전원. 브랜드(비로그인)는 폼용 조회 함수로만 받는다.

### 2-2. 현재 구현과 어긋나는 지점

- N1~N4 넷 모두 바뀐다. 서버 두 함수(`_orient_compute_quote`·`get_orient_tier_fees`)의 **베이스는 461**.
- `TIER_OPTIONS` 의 `sub` 가 두 뜻(인원·설명)을 겸하는 구조를 **나눈다** — 인원과 옵션을 서로 다른 자리에 둔다(§3-5).
- **「맨 끝만 이름 자리가 인원」 구조가 걸린 여섯 곳을 모두 지운다**(결정 2) — 예외 분기 넷(`applyTierSlots`·`refreshTierButtons`·첫 그리기 1883·`tierDisplay`) + 「이름 자리를 제 이름으로 되돌린다」 줄 둘(`onSlotsDirect`·`onTierPick`). 앞 넷 중 한 곳이라도 남으면 **맨 끝 단추·확인 화면에 이름 대신 인원**이 보인다. 되돌리기 줄 둘은 남아도 동작은 같다(서버 이름으로 덮인 `TIER_OPTIONS` 를 다시 쓸 뿐) — 할 일이 없어진 줄이라 정리로 지운다(§3-5).

### 2-3. 의도 모호점

- **「옵션」의 뜻** — 사용자 표현은 「(+실검작업) 같은 부가 설명 자리」. **계산에 영향 없는 표시 문구**로 해석한다(2-1 ③). 옵션을 고르면 금액이 붙는 기능(리뷰어 추가 옵션 LIPS·@cosme 같은)과는 **다르다** — 이름이 같아 헷갈리므로 관리자 화면 칸 이름을 **「옵션 문구」**로 한다.
- **옵션을 어디에 보이나** — 브랜드 폼 **단추**와 **직접입력 옆 줄**(단추가 없는 「소량」은 여기서만 보인다). **견적서·확인 화면 요약에는 안 싣는다** — 견적서는 금액 문서라 설명 문구가 섞이면 청구 항목처럼 읽힌다.
- **소량 이름·옵션** — 단추가 없어도 직접입력 옆 줄·견적 줄에 이름이 나오므로 똑같이 고칠 수 있게 한다.

## 3. 설계

### 3-1. 새 표 `quote_tier_labels`

| 칸 | 형 | 규칙 |
|---|---|---|
| `form_type` | `text` | `CHECK (form_type IN ('reviewer','seeding'))` |
| `tier` | `text` | `CHECK (tier IN ('tmin','t50','t100','t300','t500plus'))` |
| `name` | `text NOT NULL` | 1~8자(앞뒤 공백 제거 뒤) |
| `option_text` | `text NOT NULL DEFAULT ''` | 0~16자. 비움 = 옵션 없음 |
| `updated_at` · `updated_by` | | `quote_settings` 와 같은 꼴 |

- 기본 키 `(form_type, tier)`. **정확히 10행**을 시드한다:

| 구간 | 이름(두 형식 공통 시드) | 옵션 |
|---|---|---|
| `tmin` | 소량 | (비움) |
| `t50` | 라이트 | (비움) |
| `t100` | 스탠다드 | (비움) |
| `t300` | 프리미엄 | (비움) |
| `t500plus` | **프리미엄+** | **+실검작업** |

- 접근: 조회 `is_admin()`, **쓰기 정책 없음**(함수만). 비로그인은 표를 직접 못 읽는다.
- 이력 표 `quote_tier_labels_history` — `(form_type, tier, field['name'|'option_text'], prev_value, next_value, actor, actor_name, at)`, 추가만. 조회 `is_admin()`.
- 🔴 `quote_settings` 에 글자 칸을 더하는 방법은 **쓰지 않는다** — 45행 중 10행만 쓰는 칸이 생기고, 조회 함수 `get_quote_settings` 의 반환 모양을 바꾸려면 `DROP` 이 필요해 권한 회수를 다시 걸어야 하며, 숫자 이력 표와 글자 이력이 한 표에 섞인다.

### 3-2. 함수

**새 함수 둘**(①)
- `get_quote_tier_labels()` — 관리자 전원(`is_admin()`), 10행 반환. 실행 권한 `authenticated` 만.
- `update_quote_tier_label(p_form_type text, p_tier text, p_name text, p_option_text text)` — `is_campaign_admin()`. 거부 코드: `forbidden` · `unknown_tier`(없는 형식·구간) · `name_required`(공백 제거 뒤 빈 값) · `name_too_long`(8자 초과) · `option_too_long`(16자 초과) · `invalid_text`(`<`·`>` 포함). 두 값을 앞뒤 공백 제거해 저장하고, **바뀐 칸마다** 이력 1행. 실행 권한 `authenticated` 만(PUBLIC·anon 회수 — 369·370).
  - 🔴 글자 수는 **문자 수**(`char_length`)로 센다 — 바이트로 세면 한글이 3배로 잡힌다.

**재정의 둘**(②, 베이스 **461**)
- `_orient_compute_quote` — `v_tier_label` 을 CASE 대신 **표에서** 읽는다(`form_type`=`issued.form_type`, `tier`=판정된 구간). 행이 없으면 **§3-1 시드와 같은 기본 이름**(소량·라이트·스탠다드·프리미엄·프리미엄+)으로 — 이름은 금액이 아니라 표시라 `fee_missing` 으로 막지 않는다. 견적 스냅샷에 **`tier_name`**(쓴 이름)을 더한다.
  - 🔴 461 의 맨 끝 「`<시작 인원>건`」 조립은 **지운다**(결정 2).
  - 「실검작업 — 담당자 협의」 줄 규칙(461:353-358)은 **한 글자도 안 바꾼다**.
- `get_orient_tier_fees` — 응답에 **`names: {tmin,t50,t100,t300,t500plus}`** · **`options: {…}`** 를 더한다(그 시트 형식의 값, 두 반환 경로 — 모집비 직접 지정·일반 — 모두). 행이 없는 구간은 키가 빠진다. 🔴 **기존 칸의 모양은 그대로** 둔다.

### 3-3. 견적 스냅샷

- 새 판부터 `quote.tier_name` 이 생긴다. 옛 판(이 변경 전 제출)에는 없다.
- 줄 이름(`lines[].label`)은 지금처럼 제출 시점 글자다. **다시 계산하지 않는다**(§3-6).

### 3-4. 마이그레이션 2개 — 순서 고정

> 번호는 개발 세션이 만들 때 정한다.

- **① 표·이력 표·시드 10행·접근 정책·새 함수 둘** — 계산·폼 응답은 아직 이 표를 안 읽으므로 **견적·폼 표시가 한 가지도 안 바뀐다**.
- **② `_orient_compute_quote`·`get_orient_tier_fees` 재정의**(베이스 461) — 첫머리 가드: 표가 없거나 10행이 아니면 `RAISE EXCEPTION`(① 없이 ② 단독 적용 차단).
- 금액이 바뀌는 변경이 없어 459·461 같은 「중간 상태에서 금액이 조용히 바뀌는」 함정은 없다. 둘로 나누는 이유는 **되돌리기를 따로** 하기 위해서다(②만 되돌리면 461 계산식으로 돌아가고 표는 남는다).
- 되돌리기: ②는 461 두 함수 본문 복구, ①은 표 둘·함수 둘 삭제. 파일 하단에 둔다.

### 3-5. 작성 폼 (`dev/sales/orient.html`)

- `TIER_OPTIONS` 에 **`option` 칸을 새로** 두고, `sub` 는 **인원 전용**으로 한다. 기본값: `name` = §3-1 시드와 같은 다섯, `option` = 맨 끝만 「+실검작업」, `sub`·`slots` = 빈 값.
  - 기본값이 쓰이는 때는 **주로 옛 서버 응답**(`names` 가 없음)이다. 새 서버는 ②를 ① 뒤에만 적용할 수 있고(§3-4 가드), 표에 행을 지우는 경로가 없으므로(§3-1 쓰기 정책 없음 · §3-2 삭제 함수 없음) 구간 키가 빠지는 경우는 **방어용**일 뿐이다. 응답을 못 받았을 때 — **단추**는 줄째 안 보이고(`tierSlotsReady`), **직접입력 옆 줄**은 구간 판정(`tierOfSlots`)이 응답의 인원을 써야 해서 아무것도 안 그린다. **확인 화면**만 예외다 — 이미 저장된 시트는 `slots_tier` 를 갖고 있어 기본 이름으로 「N건 (이름)」을 그릴 수 있다. 표시 전용이고 견적서 이름은 서버가 정하므로 감수한다.
- `loadTierFees` 가 `res.names`·`res.options` 로 `TIER_OPTIONS` 를 덮는다. 🔴 **판정이 둘로 갈린다** — 이름은 「키가 있고 빈 값이 아닐 때만」 덮고, 옵션은 「**키가 있으면 빈 문자열이어도** 덮는다」(기본값은 키가 없을 때만). 옵션을 이름처럼 다루면 관리자가 비운 옵션 자리에 폼 기본값 「+실검작업」이 되살아난다(V7). **인원과 같은 자리에서** 덮어 단추가 한 번에 그려지게 한다.
- `applyTierSlots` — **다섯 구간 모두 `sub` 에 「N건」**. 맨 끝 예외(`t.name = v + '건'`) 삭제.
- 단추 마크업: **이름 / 인원 / 옵션(있을 때만) / 단가**. 🔴 이름·옵션은 **`escAttr`** 로 넣는다(지금은 날것 — §2-1 ①). 옵션 칸은 비면 안 그린다(`:empty` 숨김, 기존 `.tier-note` 와 같은 방식). 옵션 칸은 `.tier-name` 과 달리 **줄바꿈을 허용**한다(`nowrap` 을 걸지 않는다 — 16자가 한 줄에 안 들어가도 단추 폭이 늘지 않게).
- `refreshTierButtons`·첫 그리기의 **「맨 끝이고 저장된 인원이 시작 인원과 다르면 이름 자리에 저장된 인원」 예외를 지운다**. 단추의 인원 자리는 **언제나 그 구간 시작 인원**이다. 옛 방식으로 700 같은 인원이 저장된 시트는 **직접입력 칸**에 700 이 그대로 보이므로(상위 사양서 — 값은 하나, 두 칸이 같은 숫자) 어긋남은 거기서 드러난다.
- 그래서 `onSlotsDirect`·`onTierPick` 의 「이름 자리를 제 이름으로 되돌린다」 줄은 **되돌릴 것이 없어져 지운다**(이름도 인원 자리도 바뀌는 일이 없다).
- `tierDirectInfo` — 「`<이름>` 구간 — 단가」 뒤에 옵션이 있으면 ` · <옵션>`. (「소량」 옵션은 여기서만 보인다.) `textContent` 로 넣으므로 이스케이프 불필요.
- `tierDisplay`(확인 화면) — 다섯 모두 **「N건 (이름)」** 한 모양. 맨 끝 예외 삭제. 옵션은 싣지 않는다(§2-3).
- 주석 정리 — 911 「실검작업은 리뷰어 견적의 줄 이름」 → 「형식과 무관하게 `t500plus` 견적에 붙는 줄」, 945·970 의 「(+실검작업)은 sub」 서술.

### 3-6. 이미 제출된 견적 — 소급하지 않는다

- 스냅샷 줄 이름은 제출 시점 문서다. 이름을 바꿔도 **다시 계산하지 않는다**(452 「상시가→판매가」 때와 같은 원칙).
- 운영 미배포라 운영 영향 0. 개발 DB 의 옛 견적은 「500건」 등 옛 이름 그대로 보인다 — 정상이다.

### 3-7. 관리자 화면

**「견적 기준값」(`admin-lookups.js`)** — 리뷰어·시딩 카드의 구간표에 칸 둘을 더한다:

| 구간(머리) | **이름** | **옵션 문구** | 시작 인원 | 인원 범위 | 단가… |
|---|---|---|---|---|---|

- 구간 머리 글자는 `QUOTE_TIER_NAME` 대신 **순번**으로 고정한다 — `tmin` 은 「최소」, `t50`~`t500plus` 는 「1구간」~「4구간」 — 이름이 편집 칸이 되므로 머리에 이름을 또 쓰면 같은 값이 두 번 보이고, 고치는 동안 서로 다른 말을 한다.
- 편집 방식은 **숫자 칸과 똑같이**(눌러야 입력 상태 → 「저장」·「취소」, Enter 저장·Escape 취소 — #1643~#1645). 저장 함수만 `update_quote_tier_label` 로. 이름·옵션 **두 칸은 각자 저장**(한 칸만 고쳐도 함수는 두 값을 다 보낸다 — 안 고친 칸은 원래 값).
- 권한: 숫자 칸과 같은 기준(`isCampaignAdminOrAbove()`) — 아니면 이름·옵션을 **글자로만** 그리고 편집 칸·버튼을 만들지 않는다(서버도 `forbidden`).
- 칸 글자는 **`esc`** 로 그린다. 입력 상한(8·16자)을 `maxlength` 로 걸고, 서버 거부 코드 여섯 모두 한국어 문구로(하나도 「저장 실패」로 뭉개지 않는다).
- 카드 아래 안내 한 줄: 「옵션 문구는 브랜드 폼 단추에 보이는 설명일 뿐 **견적 금액을 바꾸지 않습니다**. 「실검작업 — 담당자 협의」 줄은 맨 끝 구간이면 옵션 문구와 상관없이 붙습니다.」
- 오름차순 거부 문구(380)는 이름을 박지 않는다 → 「구간 시작 인원은 위에서 아래로 커져야 합니다(「최소」 줄의 시작 인원은 1구간 시작 인원과 같아도 됩니다)」.
- 이름·옵션 조회가 실패(`null`)했거나 **10행이 아니면**(원래 생길 수 없는 이상 상태) 이름·옵션 칸만 「불러오지 못했습니다」로 그리고, 숫자 칸은 그대로 편집 가능하게 둔다. 저장소 함수 반환 규칙(실패 `null` / 0건 `[]`)은 §6 조각 3 그대로.

**오리엔시트 상세(`admin-orient.js`)** — `OS_TIER_LABEL` 상수를 지우고:
- 이름을 고르는 순서(이 한 곳에서만 정한다):
  1. 견적 스냅샷에 `quote.tier_name` 이 있으면 **그 이름**
  2. 없으면(견적 없음·이 변경 전 옛 견적) `get_quote_tier_labels()` 로 받은 **그 시트 형식의 지금 이름**. 표는 페인 진입 때 한 번 받아 둔다
  3. 그것도 없으면(조회 실패, 또는 조회는 됐는데 그 형식·구간 행이 없음) 기본 이름(§3-1 시드와 같은 값). 이름은 금액이 아니라 표시라 빈칸보다 낫다
- 고른 이름은 **`esc`** 로 그린다(표·스냅샷에서 온 관리자 입력값이다 — 옛 `OS_TIER_LABEL` 은 상수라 필요 없었다).
- ⚠️ 옛 견적은 2단계로 가므로 견적서 줄(예: 「500건」)과 상세 이름이 **다를 수 있다** — 개발 DB 의 시험 시트뿐이고 운영은 0건이라 감수한다(§3-6).

### 3-8. 문서

`CLAUDE.md` 「구간 요금」 항목 — 구간 이름·옵션의 정의처가 `quote_tier_labels` 라는 것, **기본 이름이 세 곳**(서버 계산식 = 행이 없을 때 · 작성 폼 = 응답에 이름이 없을 때, 또는 응답을 못 받았을 때 확인 화면만 · 관리자 상세 = 조회 실패나 행 없음 — §0 과 같은 조건)과 **옵션 기본값이 한 곳**(작성 폼)에 남아 §3-1 시드와 같게 유지해야 한다는 것, 옵션은 계산과 무관하다는 것.

| V4 | 빈 이름 `name_required` · `<b>` `invalid_text` · 9자 `name_too_long` · 옵션 17자 `option_too_long` · 없는 형식 `unknown_tier` |
| 폼 조회 | `get_orient_tier_fees` 에 `names`·`options` 다섯 키(옵션은 빈 문자열까지 포함) |

시험으로 바꾼 이름은 「스탠다드」로 되돌렸다. V5~V9·V11 은 화면 배포 뒤 브라우저로 본다.
