# 인수인계 — 문의하기 「서비스 문의」 탭에 새 답장 표시

**작성일:** 2026-10-06 · **작성:** 기획 세션
**상태:** 📄 인수인계 — 개발 세션 착수 대기 (2026-10-06)
**종류:** 버그·미세 조정(데이터베이스 변경 없음, 파일 `dev/js/messaging.js` + 번역 2개 + 스타일 1곳)

## 증상 (2026-10-06 사용자 제보 — 운영)

햄버거 「お問い合わせ」(문의하기)에 배지가 떠서 들어가도, **어디에 새 메시지가 있는지 알 수 없다.**

## 원인 (운영판 `origin/main` `dev/js/messaging.js` 확인)

| 자리 | 지금 동작 |
|---|---|
| 햄버거 배지 `refreshNavInquiryBadge` → `_navInquiryUnread` | **서비스 문의(일반 문의)의 안 읽은 답장 수만** 센다(`fetchMyGeneralInquiryUnread`) |
| `openInquiryPage` | `from !== 'back'` 이면 **항상 「캠페인 문의」 탭**으로 연다 |
| `renderInquiryBranch` 서비스 탭(`_inqTab === 'other'`) | 안내문 + 「문의 시작」 버튼뿐. **탭에도 버튼에도 새 답장 표시가 없다** |

서비스 문의는 회원당 대화 하나라 목록이 없고(사양서 `2026-05-21-general-inquiry-desk.md` §2 「스레드 단위」), 버튼을 눌러야 대화가 열린다. 그래서 배지가 가리키는 곳이 화면 안에 하나도 없다. 사양서가 탭 단위 표시를 정하지 않은 설계 공백이다.

## 고칠 것 (사용자 결정 2026-10-06 — 「탭 배지 + 자동 선택」)

1. **「サービスのお問い合わせ」(서비스 문의) 탭 라벨에 숫자 배지** — 값은 햄버거와 **같은 `_navInquiryUnread`**(따로 세지 않는다 — 두 숫자가 어긋나면 더 헷갈린다). 0이면 숨김, 10 이상은 `9+`(햄버거 `applyNavInquiryBadge` 와 같은 규칙)
2. **새 답장이 있을 때만 서비스 탭을 먼저 연다** — `openInquiryPage` 에서 `from !== 'back'` 일 때 `_navInquiryUnread > 0` 이면 `_inqTab = 'other'`, 아니면 지금처럼 `'app'`
3. **서비스 탭 안 버튼 위에 한 줄** — `新しい返信があります`(새 답장이 있습니다). 버튼에도 같은 숫자 배지
4. **들어가기 직전에 숫자를 새로 받는다** — `openInquiryPage` 가 그리기 전에 `await refreshNavInquiryBadge()`. 안 하면 대화를 읽고 돌아왔을 때 옛 숫자로 탭이 열린다

## 지킬 것

- 🔴 **조회 실패(`null`)면 지난 값을 유지**하는 기존 규칙 그대로 — 실패를 0으로 바꿔 배지를 끄지 않는다
- 탭 모양은 `.lang-toggle` 을 **복사한 `.inq-tab`** 이다. 배지를 붙일 때도 `.lang-btn` 클래스를 쓰지 않는다(`updateLangToggleUI` 가 전역으로 잡아 탭 선택이 지워진다 — 기존 주석)
- 아이콘은 Material Icons + `translate="no"`, 번역 키는 `dev/lib/i18n/{ja,ko}.js` 둘 다(한국어 `새 답장이 있습니다`)
- 캠페인 문의 탭의 안 읽음 표시는 **이번 범위 밖** — 햄버거 배지가 그쪽을 세지 않기 때문이다(응모건 안 읽음은 응모이력 쪽에서 보인다)
- 「응모 0건」 회원은 지금도 탭 화면 없이 바로 대화로 가므로 영향 없음
- 숫자 새로 받기(4번)는 응모·대화 목록 조회와 **`Promise.all` 로 함께** 받는다 — 지금도 두 조회를 차례로 기다리므로 하나 더 줄 세우면 체감이 느려진다
- ⚠️ **읽음 → 뒤로 순서의 경합** — `_msgMarkRead` 가 `refreshNavInquiryBadge()` 를 기다리지 않고 부른다. 뒤로 나와 4번이 받는 값과 겹치면 **늦게 온 응답이 이긴다.** 읽음 저장이 끝난 뒤의 숫자로 탭이 그려지는지 눈으로 확인한다
- 탭 배지는 `renderInquiryBranch` 가 그릴 때의 값이다 — 화면을 연 채로 주기 갱신(`notifications.js`)이 숫자를 바꿔도 다음 그리기까지 옛 값이다(허용). 햄버거용 `data-role="nav-inquiry-badge"` 를 탭 배지에 **재사용하지 않는다**(햄버거 위치 스타일이 딸려 온다) — 탭 전용 클래스로 그린다
- 「서비스 탭 먼저」는 `from !== 'back'` 인 모든 진입에 걸린다 — 햄버거·탈퇴 화면 지름길(응모가 있는 회원)·새로고침 주소 복원(`openInquiryPage('nav', false)`). 셋 다 의도한 동작이다. 알림은 대화로 바로 가므로 이 화면을 안 거친다

## 확인할 것

- 운영팀이 서비스 문의에 답장 → 회원이 햄버거 「お問い合わせ」 → **서비스 탭이 먼저 열리고 배지·안내 줄이 보인다** → 대화를 열면 읽음 → 뒤로 → **배지·안내 줄이 사라지고** 다음 진입은 캠페인 탭
- 새 답장이 없을 때는 지금과 똑같이 캠페인 탭으로 열린다
- 뒤로가기(`from === 'back'`)로 돌아왔을 때 사용자가 고른 탭이 유지된다

## 관련

- 이 문서와 별개로, 서비스 문의를 **여러 대화로 나누는 구조 변경**을 기획 세션이 설계 중이다(사용자 요청 2026-10-06). 이번 수정은 그 전까지의 응급 처치이며, 구조가 바뀌면 이 화면도 다시 그린다.
