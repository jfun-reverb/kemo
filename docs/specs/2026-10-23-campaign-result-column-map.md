# 캠페인 결과물 열 지도 — REVERB 열 ↔ 포인테일 외부 파일 열  **작성일:** 2026-10-23

> 캠페인 결과물 표의 열마다 REVERB 값과 외부 결과 파일(스토어링크·포인테일) 값이 어디서 오는지, 관리자와 브랜드에게 각각 어떻게 보이는지를 정리한 지도다. 결과물 표 = 관리자 리포트 화면 · 리포트 엑셀 · 진행현황 결과물 엑셀 · 브랜드 결과물 화면. 진행현황 「결과물」 탭 화면은 따로 만든 8칸 표(외부 줄은 이름·채널 칸 없음)라 이 지도의 대상이 아니다.
> 그림: Figma Admin 페이지 「[참고] a05-0 캠페인 열 관리」(화면 `참고 a05-00`). **그림과 이 문서가 다르면 이 문서가 이긴다.**
> **기준 시점**: 「기본 출력」 칸과 「→」 뒤의 값은 브랜드 포털의 결정이고, 나머지 칸은 작성일의 개발서버 코드(`origin/dev`) 동작이다. 이 문서는 새로 정하는 것이 없다. 결정은 브랜드 포털 사양서 `docs/specs/2026-07-15-brand-portal.md`(아래 「브랜드 포털」)에 있고, 여기서는 그 자리를 가리킨다.

## 현재 상태 (작성일 기준)

### 관련 코드·DB·화면
- 열 목록(「열 대장」) — `dev/js/report-rows.js`
  - 항상 있는 열: `REPORT_COLS`
  - 채널 목록: `REPORT_CHANNELS`
  - 결과물이 있는 채널 열을 붙이는 곳: `reportColumnsFor`
  - 외부 줄을 표준 줄로 바꾸는 곳: `_reportExtToRow`
- 외부 파일 읽기 — `dev/js/report-parsers.js` `parsePointailWorkbook`. 탭마다 「회원번호」 머리글 행을 찾고, 「구매하기」 탭을 바탕으로 리뷰 탭을 회원번호로 얹는다.
- 외부 줄 저장 — 표 `campaign_report_ext_rows`
- 외부 줄 응답 — `_results_ext_rows`(545). 브랜드용 응답에는 회원번호를 싣지 않는다.
- 외부 파일이 붙은 캠페인의 열 잠금 — 서버 `_brand_publish_ext_locked_key`(587)와 화면 `reportIsExtEmptyKey`. 같은 규칙이 두 곳에 있다(브랜드 포털 16-5 15번 ④ ⓓ).
- 「구분」 칸 — 관리자 쪽(`admin-reports.js`·`admin-excel.js`)에만 있다. 브랜드 결과물 화면(`brand-campaign-results.js`)은 외부 줄인지 알 수 없게 이 칸을 그리지 않는다.
- 관리자 화면에는 열 잠금이 없다. 모든 열을 보이고, 외부 줄은 값이 없으면 빈칸이다(예외: 「계정 ID」 — 표 11번 줄). 리포트 엑셀은 내려받을 때 열을 고르는 창이 따로 있다.

### 이 문서와 충돌 가능성 있는 기존 동작
충돌 없음 — 열 대장·외부 파일 읽기·잠금 판정·「구분」 칸, 네 영역을 확인했다. 단, 외부 파일을 **리포트에** 붙이는 경로는 출시 때 없어지고 붙이는 자리가 캠페인 진행현황으로 옮겨진다(브랜드 포털 §4 「리포트 공유 링크」 ③). 아래 표 2·3번 줄 괄호(리포트에 붙인 외부 줄)는 그때까지만이다.

## 열 지도

- **순서**: 실제 출력 순서다. 「항상」 열 다음에 결과물이 있는 채널 열이 LIPS → 인스타그램 → 틱톡 → X → 유튜브 → 기타 순으로 붙는다. 한 채널 안에서는 계정 → 결과물 → 업로드 날짜 순이다.
- **기본 출력**: 브랜드 공개 기본 열의 **전체 기본값 처음 값**이다(브랜드 포털 16-5 17번 — 운영 반영 때 저장할 값). 캠페인에서 처음 켤 때 실제로 체크되는 열은 이것과 다를 수 있다 — 브랜드 포털 §4 「리포트 공유 링크」 ③ ⓐ~ⓒ와 「출시 때 한 번」.
- **관리자 화면**: 관리자 리포트 화면·리포트 엑셀·진행현황 결과물 엑셀에서 보이는지다.
- **브랜드 화면**: 외부 파일이 붙은 캠페인에서 그 열을 브랜드에게 보일 수 있는지다(16-5 15번 ④ ⓓ). 외부 파일이 없는 캠페인은 공개 설정에서 고른 대로 보인다.

## 의심·경우의 수

1. **같은 열에 성격이 다른 값이 들어간다** — 큐텐·엣코스메 결과물 열에 REVERB 줄은 게시물 링크(또는 인증샷)가 들어가고, 외부 줄은 리뷰 캡처 사진이 들어간다. 브랜드는 같은 열에서 링크와 사진을 섞어 본다(③).
2. **텍스트·포토 리뷰를 둘 다 낸 외부 회원** — 포토 쪽만 남고 텍스트 리뷰 증빙은 버려진다(④).
3. **「상태」는 이름만 같다** — REVERB 는 결과물로 계산한 값이고, 외부는 포인테일 미션 상태를 바꾼 값이다. 외부 「완료」는 구매하기 탭 기준이라 리뷰까지 끝났다는 뜻이 아닐 수 있다. 브랜드 포털 16-5 17번이 이 차이를 경고로 적고 기본 출력에 넣기로 했다(받아들인 위험).
4. **시딩·인스타 파일을 받으면 잠금 규칙과 부딪힌다** — 지금 규칙은 「큐텐·엣코스메가 아닌 채널 열은 외부 파일이 붙으면 잠김」이다. 그런데 이 파일에는 인스타그램 값이 있다(①·②).
5. **LIPS 열이 생기는 조건** — LIPS 는 결과물이 있을 때만 생기는 열이다. 외부 줄에만 LIPS 값이 있을 때도 열이 생기는지는 코드로 확인해야 한다. 지금 판정은 REVERB 줄의 요구 채널이나 값을 본다(⑥ — 아래 「결정됐고 남은 일」).
6. **(UX) 브랜드 화면에서 외부 줄이 드러나는 길** — 잠금은 열 단위다. 같은 열 안에서 값의 모양이 다르면(링크 vs 사진, 1번) 외부 줄이 드러날 수 있다. 브랜드 화면은 영수증 단추 모양을 두 갈래 똑같이 맞췄지만, 결과물 칸은 확인하지 않았다(③).
7. **(UX) 「계정 ID」 한 열에 두 뜻** — REVERB 줄은 로그인 이메일이고, 외부 줄은 SNS 계정(포인테일 「채널 계정 ID(닉네임)」)이다. 브랜드 포털 §4 ③ ⓐ는 「계정 ID」를 로그인 이메일로 정의하고 SNS 계정인 「계정」과 구분한다. 브랜드에게는 항상 꺼져 있고 리포트 엑셀도 이 열을 싣지 않아, 섞여 보이는 곳은 관리자 리포트 화면이다(⑦).

## 사용자 확인 필요

① **시딩·인스타 외부 파일을 받을지** — 받는다면 탭을 어느 열에 넣을지 정한다.
  - 인스타그램 포스팅 → 인스타그램 계정·결과물·업로드 날짜
  - 배송완료 인증 사진 → 어느 열인지 미정(시딩형엔 영수증이 없다)
  - 배송지 입력 → 증빙이 없다

② **①을 받으면 잠금 규칙을 바꿀지** — 예: 「그 캠페인의 외부 파일에 값이 있는 열은 풀림」. 판정은 화면과 서버 두 곳에 있다.

③ **같은 열의 링크/사진 차이를 브랜드에게 그대로 둘지** — 의심 1·6.

④ **텍스트·포토 리뷰를 둘 다 낸 외부 회원의 텍스트 증빙을 버려도 되는지**

⑤ **「구매 옵션」을 결과물 표에 보여 줄지**

⑦ **관리자 리포트 화면 「계정 ID」 열의 외부 값** — 외부 SNS 계정을 그대로 둘지, 비울지(의심 7).

## 결정됐고 남은 일 (개발 몫)

⑥ **LIPS** — 엣코스메와 똑같이 다루기로 했다(브랜드 포털 16-5 17번 — 2026-10-23 결정). LIPS 외부 파일이 온 뒤에 할 일:
  - 실제 탭 이름을 확인한다
  - 외부 파일 읽기에 LIPS 탭을 더한다
  - 잠금 판정 두 곳(화면·서버)을 함께 고친다
  - 기본 출력에 LIPS 결과물·업로드 날짜를 넣는다(운영 기준 데이터에 저장하는 일은 17번) — 🔴 지금 LIPS 는 「캠페인에 따라 생기는 채널」이라 열 목록에는 종류 열쇠로만 적히고, 그 단위는 기본 열에 못 넣는다(브랜드 포털 §4 ③ ⓐ · 15번 ④ ⓓ-1). LIPS 를 큐텐·엣코스메처럼 채널별 열로 적을 수 있게 바꾸는 일이 함께 필요하다
  - 의심 5(외부 줄에만 값이 있을 때도 열이 생기는지)를 코드로 확인한다
